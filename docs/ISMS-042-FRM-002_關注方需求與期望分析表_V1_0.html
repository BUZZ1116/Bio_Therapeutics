1. 文件目的

本表單用於針對已識別之關注方，進一步分析其需求與期望、要求來源、合規義務、重要性、影響範圍、未滿足後果、ISMS範圍影響、風險與機會、控制措施對應、符合性狀態、溝通要求、管理回應與後續行動，以確保相關要求被納入ISMS建立、實施、維持與持續改善過程。

本表單是ISO/IEC 27001:2022 Clause 4.2「理解關注方需求與期望」及Annex A.5.31「法律、法規、監管與合約要求」之核心證據，並支援PIMS、AI治理、GHG/CO2資料治理、雲端與ICT供應鏈合規管理。

14. 溝通需求與頻率表 設定需求相關溝通對象、內容、方式、頻率、責任角色與輸出紀錄。 溝通要求與溝通證據。
15. 管理回應與行動追蹤表 將需求缺口、文件修訂、控制補強、合約審查、供應商追蹤、訓練、CAPA及管理審查轉為可追蹤行動。 行動追蹤、CAPA與改善證據。
16. 管理審查輸入彙整 彙整重大需求、合規義務、供應鏈/雲端、PIMS/AI/GHG、缺口與資源需求作為管理審查輸入。 管理審查輸入資料。

3. 名詞與定義

名詞 定義
關注方 可能影響、受影響或自認受ISMS影響之個人或組織，包括客戶、主管機關、員工、供應商、合作夥伴、股東、驗證機構、資料主體、AI使用者、GHG查證機構及社會大眾。
需求 關注方明確提出或可合理推定之要求，例如法規、合約、客戶安全條款、服務等級、通報義務、證據提供、資料保護與控制措施要求。
期望 關注方未必明確形成法律或合約義務，但對組織可信任營運、資訊安全、隱私、AI負責任使用、永續揭露與服務品質具有影響之期待。
合規義務 組織必須遵循或選擇承諾遵循之法律、法規、監管、合約、標準、政策、客戶要求、供應商條款與驗證要求。
要求Owner 對特定需求或期望之識別、評估、落實、監督、證據維護與改善追蹤負有責任之角色。
符合性狀態 組織對特定需求或期望之落實狀態，可為符合、部分符合、不符合、不適用或待確認。
管理回應 針對需求與期望所採取之政策、程序、控制措施、合約條款、風險評估、溝通、訓練、CAPA或管理審查措施。
