1. 作業目的

本作業指導書規範組織資訊刪除、資料清除、媒體清除、資料銷毀、金鑰銷毀、備份資料過期處理、雲端與SaaS資料刪除、AI資料集退場、Prompt與RAG資料清除、供應商資料刪除證明與刪除驗證要求，確保資訊於保存期限屆滿、合約終止、系統退場、資料主體請求、法規要求、業務需求消失或風險不可接受時，能以可控、可追溯、可驗證且符合法律與合約要求之方式刪除或清除。

本文件旨在防止資料因過度保留、未完全刪除、未清除備份、未處理雲端副本、未撤銷金鑰、未刪除AI訓練資料或供應商保留副本而造成未授權存取、資料外洩、隱私侵害、法規違反、事件證據污染或營運風險。

2. 作業原則

  • 資訊刪除與資料清除應依資料分類、保存期限、法規合約、Legal Hold、資料主體權利、業務需求、風險等級與技術可行性執行。
  • 刪除、清除、覆寫、加密抹除、媒體銷毀、金鑰銷毀與匿名化屬不同控制方法，應依資料敏感度、媒體類型、環境與復原風險選擇。
  • 刪除前應確認無Legal Hold、事件調查保全、合約保存、稽核保存或營運必要保存要求，避免違反證據保存與法規要求。
  • 資料清除作業應具有申請、核准、執行、驗證、紀錄保存與例外管理，不得僅依口頭通知或未記錄之手動刪除完成。
  • 備份、快照、複寫、暫存、索引、Cache、Log、搜尋引擎、AI向量資料庫與供應商副本應納入刪除或過期處理規劃。
  • 刪除證明、銷毀證明、金鑰銷毀紀錄、供應商刪除證明與驗證紀錄應依文件化資訊要求保存。

3. 名詞與定義

名詞 定義
資訊刪除 將資料自使用者或系統可存取狀態移除之作業，可能仍存在於備份、快照、暫存或底層儲存。
資料清除 採用技術或管理措施使資料無法以合理方式復原、讀取或重建之作業。
媒體清除 對磁碟、SSD、磁帶、USB、手機、紙本或其他儲存媒體進行清除、消磁、覆寫、加密抹除或實體銷毀。
加密抹除 銷毀或撤銷加密金鑰，使加密資料在合理條件下無法再解密之資料清除方法。
Secure Erase 使用設備、作業系統、儲存控制器或標準工具執行之安全抹除程序。
Legal Hold 因訴訟、調查、法規、合約或稽核要求，暫停資料刪除或變更之保全狀態。
資料保存期限 依法律、合約、業務與風險要求，資料應保存之期間。
資料退場 資料因系統退役、服務終止、合約結束、目的消失或風險處理而移除、封存、匿名化或銷毀之過程。
供應商刪除證明 供應商確認已依要求刪除或清除資料、副本、備份、快照、Cache、Log或模型資料之文件化證據。
AI資料刪除 針對AI訓練資料、微調資料、Prompt、RAG來源、Embedding、向量資料、模型輸入輸出及模型產物之移除、清除或停用處理。
資料銷毀證明 證明資料或媒體已依核准方法完成銷毀、清除或不可復原處理之紀錄或證明。

4. 角色與責任

CISO / 資訊安全負責人 核准高敏感資料清除、高風險例外、金鑰銷毀、重大資料退場與風險接受。 核准紀錄、風險接受、管理審查。
DPO / Privacy Owner 審查個人資料刪除、資料主體權利、跨境副本、供應商刪除與隱私風險。 DPIA、刪除審查紀錄。
Legal / Compliance Owner 確認Legal Hold、法規保存、合約保存、稽核與訴訟保全要求。 Legal Hold確認、法務審查。
Data Owner 定義資料保存期限、刪除條件、業務影響、驗證標準與刪除核准。 資料刪除核准、驗收紀錄。
Data Lifecycle Owner 維護資料生命週期、保存期限、刪除計畫、清冊、KPI/KRI與改善追蹤。 資料生命週期清冊。
System / Application Owner 執行應用資料刪除、API刪除、帳號資料退場與功能驗證。 應用刪除紀錄。
Database / Data Platform Owner 執行資料庫、資料倉儲、資料湖、索引、ETL暫存與資料平台刪除。 資料庫刪除紀錄。
Backup / Storage Owner 處理備份、快照、複寫、媒體、儲存池與過期刪除。 備份與儲存刪除紀錄。
Cloud Security / SaaS Owner 管理雲端儲存、SaaS資料、Bucket、Object、Snapshot、Versioning與雲端副本刪除。 雲端刪除證據。
Endpoint / Media Owner 執行端點、行動裝置、外接媒體、紙本及退役設備資料清除。 媒體清除與銷毀證明。
AI Governance / MLOps Owner 管理AI資料集、Prompt、RAG、Embedding、向量庫、模型資料與外部AI供應商刪除。 AI資料刪除紀錄。
SOC / Incident Response 監控未授權刪除、異常大量刪除、資料外洩後刪除、事件證據保全與刪除例外。 SIEM/DLP告警、事件紀錄。
Supplier Management 確保供應商依合約完成資料刪除、清除與證明交付。 供應商刪除證明。
Internal Auditor 抽查刪除申請、核准、執行、驗證、例外、供應商證明與保存期限遵循。 稽核底稿、稽核發現。

5. 刪除與清除方法選擇矩陣

方法 適用情境 最低要求 限制 / 注意事項
一般刪除 低敏感、短期暫存、可由系統回收之資料。 需有刪除紀錄或系統日誌。 不代表底層不可復原，不適用高敏感資料最終清除。
邏輯刪除 / 停用 需保留歷史或可復原之帳號、資料或交易狀態。 需標示狀態、限制存取與保存期限。 不得誤認為資料已清除。
安全覆寫 磁性硬碟或可覆寫媒體之資料清除。 使用核准工具與驗證紀錄。 SSD、雲端儲存與快照環境可能不適用。
加密抹除 資料已加密且可安全銷毀金鑰之情境。 金鑰銷毀需授權、記錄、不可復原確認。 需確保無其他金鑰副本或明文副本。
Secure Erase / Sanitize 支援標準清除指令之SSD、磁碟或設備。 需使用核准程序並保存結果。 需確認設備與工具可靠。
實體銷毀 高敏感媒體、故障媒體、不可安全清除媒體或退役媒體。 需雙人見證、供應商證明或銷毀紀錄。 需符合環保與資產處分要求。
匿名化 資料仍需分析或統計但不需識別個體。 需評估重識別風險與DPO核准。 若仍可重識別，不應視為刪除。
Token/映射刪除 刪除Token Vault或對照表，使資料無法還原。 需確保所有映射副本已刪除或封存。 需評估業務依賴。
備份到期淘汰 依備份保存策略自然覆蓋或到期刪除。 需記錄備份保存與不可提前刪除限制。 資料主體刪除請求需明確說明備份例外與復原時處理。
雲端物件刪除 刪除Cloud Object、Version、Snapshot、Replica與Lifecycle副本。 需檢查版本控制、跨區複寫與保留鎖定。 需保存雲端刪除日誌。

6. 資訊刪除與資料清除作業流程

階段 作業要求 責任角色 輸出證據
1. 刪除需求識別 依保存期限屆滿、資料主體請求、合約終止、系統退場、風險處理或專案結束提出刪除需求。 Data Owner / Requester 資料刪除申請單。
2. 資料範圍盤點 識別資料位置、系統、欄位、備份、快照、日誌、雲端副本、SaaS、AI資料與供應商副本。 Data Lifecycle Owner / System Owner 資料範圍清冊。
3. Legal Hold與保存檢查 確認是否有訴訟、調查、稽核、法規、合約或事件證據保存要求。 Legal / Compliance / DPO 保存與保全確認。
4. 風險與方法選擇 依資料分類、媒體類型、可復原風險、技術可行性選擇刪除、清除、銷毀或加密抹除方法。 CISO / Data Owner / Technical Owner 清除方案。
5. 核准 依風險取得Data Owner、DPO、Legal、CISO、System Owner或管理階層核准。 核准角色 核准紀錄。
6. 執行 於核准時間窗口執行刪除、清除、金鑰銷毀、媒體銷毀、雲端刪除或供應商刪除。 Technical Owner / Supplier 執行紀錄。
7. 驗證 驗證資料不可存取、不可復原、權限已撤銷、索引已更新、備份策略已標記或證明已取得。 Data Owner / Security / QA 驗證報告。
8. 紀錄保存 保存申請、核准、執行、驗證、例外、供應商證明與風險接受紀錄。 ISMS代表 / Data Lifecycle Owner 文件化資訊。
9. 監控與事件處理 監控未授權刪除、大量刪除、刪除失敗或資料殘留事件。 SOC / Incident Response 告警與事件紀錄。
10. 定期審查 定期審查刪除需求完成率、逾期資料、供應商證明與保存策略有效性。 ISMS代表 / DPO 管理審查輸入。

7. 資料類型與清除要求

資料類型 清除要求 特別注意事項
一般內部資料 依保存期限刪除，保留系統日誌或工單紀錄。 確認無業務依賴與Legal Hold。
機密 / 高機密資料 需Data Owner與Security核准，執行後需驗證不可存取或不可復原。 備份、快照、暫存、索引與副本需納入。
PII / 個人資料 需DPO審查，依資料主體權利、法規保存與目的限制處理。 需處理供應商、副本、SaaS與備份例外說明。
客戶資料 需依合約、客戶要求、DPA與刪除證明程序處理。 必要時提供客戶刪除證明。
員工資料 需HR、Legal與DPO審查保存期限與勞動法要求。 不可因離職立即刪除依法需保存資料。
Secrets / 金鑰 / Token 需撤銷、輪替、銷毀並驗證無殘留於Repo、Log、CI/CD、雲端或備份中。 外洩時依Secrets事件流程處理。
日誌資料 依日誌保存期限、事件保全與法規要求刪除或封存。 不得刪除正在調查之事件證據。
備份與快照 依備份保存策略到期刪除；若需特殊刪除需評估備份完整性與技術限制。 需記錄無法即時刪除之補償控制。
測試與開發資料 專案結束、測試完成或期限屆滿應刪除或重新遮罩。 測試環境不得長期保留正式資料。
AI訓練 / 評估資料 需刪除資料集、版本、Prompt、Embedding、向量資料與外部AI平台副本。 需評估模型是否已記憶資料與是否需模型退場。

9. 備份、快照與不可變保存資料處理

控制項目 作業要求 注意事項
備份保存策略 備份資料依核准保存期限到期刪除或覆蓋。 需與法規、合約、RTO/RPO、勒索防護平衡。
資料主體刪除請求 如備份無法即時刪除，需記錄技術限制、補償控制與復原後刪除程序。 需DPO審查並可說明。
不可變備份 不可變備份不得任意提前刪除，除非有核准例外與技術可行性。 防止惡意刪除與勒索攻擊。
快照與複寫 刪除主要資料時需確認Snapshot、Replica、DR、Archive與Object Version。 避免舊版本殘留。
復原後處理 若由舊備份復原，需重新執行應刪除資料清單或Deletion Replay。 需保存復原後刪除紀錄。
備份退場 系統退場時需定義備份保留、封存、加密、金鑰保存與最終刪除。 需Data Owner與Legal確認。
備份金鑰銷毀 如採加密抹除，需確保備份與複本無可用金鑰。 需KMS與Secrets Owner驗證。

15. 例外管理

例外情境 最低要求 核准層級 期限與重評
無法即時刪除備份資料 需說明技術限制、保存期限、復原後刪除程序與存取限制。 DPO / CISO / Backup Owner 每季或備份到期時重評。
Legal Hold暫停刪除 需Legal指示、保全範圍、保全期限與解除條件。 Legal / Compliance 依案件狀態重評。
供應商無法提供完整刪除證明 需取得替代證據、風險接受、合約改善或服務退場計畫。 Supplier Owner / Legal / CISO 續約前重評。
AI模型已使用待刪資料訓練 需評估模型記憶、刪除資料集、模型退場、重新訓練或限制使用。 AI Governance / DPO / CISO 依風險設定。
資料仍需保留作統計分析 需匿名化或彙總，並完成重識別風險評估。 Data Owner / DPO 至少每年重評。
媒體無法安全清除且需維修 需加密抹除或實體銷毀；若外送維修需Data Owner與CISO核准。 CISO / IT Owner 單次核准。
刪除可能造成服務中斷 需變更計畫、回復方案、業務核准與替代控制。 System Owner / CISO 依變更期限。
