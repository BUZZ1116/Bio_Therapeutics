1. 目的

本程序旨在建立完整、可執行、可稽核、可衡量且可持續改進之資訊安全事件管理制度，使組織能及時識別、通報、記錄、評估、分類、升級、決策、遏止、根除、復原、溝通、蒐證、檢討及改善資訊安全事件，降低事件對資訊資產、客戶、個人資料、雲端服務、AI系統、供應鏈、營運持續、合規義務、碳/GHG資料可信度及組織聲譽之影響。

本程序同時作為ISO/IEC 27001:2022 Annex A.5.24至A.5.28與A.6.8之控制落地文件，確保事件管理規劃與準備、事件評估與決策、事件回應、事件學習、證據蒐集及人員事件通報均具備明確流程、角色責任、紀錄格式、升級門檻、保存要求與驗證證據。

2. 管理原則

  • 所有可疑事件均應通報，未能確認是否為事件時，應先依資安事件疑似情境進行登錄與初步評估。
  • 事件處理應兼顧機密性、完整性、可用性、可追溯性、合法合規性、營運持續、證據保存與利害關係人溝通。
  • 事件應依衝擊、範圍、資料敏感性、系統重要性、可擴散性、法規與合約通報義務及媒體/聲譽風險進行分級。
  • 重大事件應啟動CSIRT/IRT，並由CISO、Incident Commander或授權主管進行決策與資源協調。
  • 事件證據不得任意刪除、覆寫、重啟、格式化或改變；必要時應依數位證據保存作業指導書建立證據鏈。
  • 涉及PII、客戶資料、雲端服務、AI系統、供應商、跨境、法規、營運中斷或GHG/ESG外部揭露資料者，應立即納入對應Owner及法遵角色。
  • 事件結案前應完成根本原因分析、控制有效性評估、風險登錄更新、矯正措施與經驗回饋。

3. 名詞與定義

名詞 定義
資訊安全事件（Information Security Incident） 一個或多個不期望或未授權之資訊安全事件，可能或已經對資訊安全、營運、法遵、客戶、個人資料、系統、服務或組織聲譽造成損害。
資訊安全事件徵兆 / 事件通報（Information Security Event） 系統、服務、網路、使用者、供應商或監控工具偵測到可能與資訊安全相關之狀況、告警、異常或違規跡象，需評估是否構成事件。
資安弱點 可能被威脅利用而導致資訊安全事件之技術、流程、人員、實體、供應商或組態缺陷。
CSIRT / IRT Computer Security Incident Response Team / Incident Response Team，負責協調、調查、遏止、復原、通報及檢討資訊安全事件之跨職能團隊。
Incident Commander 重大事件處理期間負責統一指揮、決策協調、資源調度、進度追蹤與對管理階層報告之角色。
遏止（Containment） 限制事件擴散、阻斷攻擊路徑、隔離受影響系統、停用帳號或封鎖通道之活動。
根除（Eradication） 移除惡意程式、攻擊工具、後門、錯誤設定、惡意帳號、弱點利用條件或造成事件之根本技術原因。
復原（Recovery） 將受影響服務、系統、資料或流程恢復至可接受之安全營運狀態，並驗證其完整性與可用性。
證據鏈（Chain of Custody） 記錄證據從取得、封存、移交、分析、保存至處置全過程之人員、時間、地點、方法、完整性驗證與授權紀錄。
重大資安事件 可能造成重大營運中斷、重大資料外洩、法規通報、客戶重大影響、媒體曝光、高額財務損失或高階管理階層決策需求之事件。
PII事件 涉及個人可識別資訊未授權存取、揭露、遺失、破壞、竄改、跨境違規或無法於必要期間提供服務之事件。
AI安全事件 涉及AI系統、模型、資料集、Prompt、RAG、代理工具、AI SaaS、模型輸出、訓練資料或推論服務之資安、隱私、完整性、濫用或治理事件。
雲端安全事件 涉及SaaS、PaaS、IaaS、Cloud IAM、雲端儲存、容器、Kubernetes、Serverless、雲端網路、雲端日誌或雲端供應商服務之安全事件。

4. 角色與責任

角色 主要責任 主要輸出/證據
最高管理階層 核准重大事件策略、法規與客戶溝通策略、重大資源、業務中斷決策、重大剩餘風險接受與對外聲明。 重大事件決策紀錄、管理審查輸入、資源核准。
CISO / 資訊安全負責人 維護事件管理制度，核准事件分級、升級、遏止策略、外部支援與結案，向最高管理階層報告重大事件。 事件指揮紀錄、分級決策、結案核准。
Incident Commander 於重大事件期間統一指揮跨部門回應，建立事件作戰節奏、任務分派、時程追蹤、決策記錄與狀態報告。 事件處理日誌、任務看板、狀態報告。
SOC / Security Monitoring Team 監控SIEM、EDR、NDR、DLP、CASB、雲端日誌、IAM告警及威脅情資，執行初步分析、通報與升級。 告警紀錄、初判紀錄、SIEM查詢、事件工單。
CSIRT / IRT 執行技術調查、遏止、根除、復原、惡意程式分析、日誌分析、證據保存、技術建議及事後檢討。 調查報告、遏止紀錄、復原驗證、證據鏈。
IT營運 / System Owner 提供系統資訊、帳號權限、變更紀錄、備份復原、補丁修復及服務恢復支援。 系統日誌、變更紀錄、復原紀錄、修復證據。
Cloud Security Owner 處理雲端帳號、權限、金鑰、組態、日誌、儲存桶、雲端網路、雲端原生安全控制與供應商協調。 CloudTrail/Activity Log、雲端組態、IAM修復紀錄。
Network Security Owner 支援封鎖惡意IP/網域、隔離網段、調整防火牆、VPN、Proxy、WAF、NDR與流量分析。 防火牆紀錄、封鎖清單、流量分析報告。
DPO / PIMS負責人 判斷PII事件、隱私衝擊、資料主體影響、跨境、主管機關或資料主體通報義務。 PII事件評估、DPIA更新、通報紀錄。
法務 / 法遵 評估法規、合約、客戶、監理、訴訟、證據保全、外部通報及法律特權要求。 法遵判斷、合約通報清單、法律意見。
HR / 人資 支援涉及員工違規、內部濫用、紀律處分、教育訓練與人員溝通。 訪談紀錄、紀律程序、訓練紀錄。
供應商管理 協調供應商、雲端服務商、MSSP、第三方與第四方事件通報、證據、SLA與補救措施。 供應商通報、SLA證據、第三方RCA。
AI Governance Owner 判斷AI安全事件、資料輸入輸出風險、模型濫用、Prompt洩漏、RAG資料外洩與AI供應商處理責任。 AI事件評估、模型/資料處理紀錄、人工覆核紀錄。
BCMS / DRP負責人 判斷事件是否啟動BCP/DRP，協調RTO/RPO、替代流程、中斷期間控制與復原測試。 BCP啟動紀錄、DR復原紀錄、演練結果。
全體人員 立即通報可疑事件，不得自行刪除、隱匿或擴散證據，並配合調查與補救。 事件通報紀錄、訪談紀錄、教育訓練紀錄。

5. 事件管理流程總覽

階段 流程活動 責任角色 主要輸出
1. 規劃與準備 建立事件管理政策、流程、分級、通報管道、工具、通訊錄、演練、教育訓練與證據保存能力。 CISO / ISMS管理代表 / SOC / CSIRT 事件管理程序、演練紀錄、通訊錄、值班表。
2. 偵測與通報 由人員、監控工具、供應商、客戶或主管機關通報告警、弱點、可疑活動或事件。 全體人員 / SOC / 供應商 資訊安全事件通報紀錄表。
3. 登錄與初判 建立事件編號，確認事件來源、時間、範圍、受影響資產、資料分類、初步影響與是否需立即遏止。 SOC / Incident Manager 事件工單、初判紀錄、初步分級。
4. 評估與決策 依衝擊、可能性、擴散性、資料敏感性、法遵、供應商、AI/PII/GHG/雲端因素決定事件等級、處理策略與升級。 CISO / Incident Commander / DPO / 法務 事件分級決策、升級紀錄、管理階層通報。
5. 遏止 限制事件擴散，包括隔離主機、停用帳號、封鎖流量、撤銷金鑰、關閉分享、暫停服務或切換備援。 CSIRT / IT / Cloud / Network 遏止紀錄、變更紀錄、封鎖/隔離證據。
6. 調查與蒐證 保存日誌、磁碟映像、記憶體、封包、雲端日誌、帳號活動、DLP、AI輸入輸出與供應商證據。 CSIRT / Forensic Lead / 法務 證據鏈、Hash、蒐證紀錄、調查報告。
7. 根除與修復 移除惡意程式、後門、濫用帳號、錯誤組態、弱點、過度權限與造成事件之流程缺陷。 IT / Cloud / DevSecOps / CSIRT 修復紀錄、補丁紀錄、組態修正證據。
8. 復原與監控 安全恢復服務，驗證資料完整性、系統可用性、權限正確性與攻擊未復發，並進行加強監控。 IT / System Owner / SOC / BCMS 復原驗證、監控紀錄、RTO/RPO結果。
9. 溝通與通報 依事件等級與義務進行內部、客戶、主管機關、資料主體、供應商、查證機構或媒體溝通。 CISO / 法務 / DPO / PR / 管理階層 通報紀錄、對外聲明、客戶通知。
10. 結案與學習 完成根因分析、控制有效性檢討、風險更新、CAPA、教育訓練、文件修訂與管理審查輸入。 Incident Manager / ISMS管理代表 事件檢討報告、CAPA、KPI/KRI、管理審查輸入。

6. 事件類型分類

事件類型 範例情境 必要參與角色 特別要求
惡意程式 / 勒索軟體 EDR告警、檔案加密、惡意連線、橫向移動、疑似C2。 SOC、CSIRT、IT、BCMS、法務 立即隔離、保存記憶體/磁碟/EDR證據、啟動備份完整性檢查。
未授權存取 帳號被盜、異常登入、特權濫用、MFA疲勞攻擊、密碼噴灑。 SOC、IAM Owner、System Owner 停用帳號、撤銷Session/Token、檢查權限與日誌。
資料外洩 / 誤傳 郵件誤寄、DLP告警、公開分享連結、資料庫外洩、未授權下載。 Data Owner、DPO、法務、CISO 確認資料範圍、分類、收件方、可回收性、法規/客戶通報義務。
雲端安全事件 儲存桶公開、IAM過度權限、Access Key洩漏、CloudTrail停用、雲端資源被濫用。 Cloud Security Owner、SOC、供應商管理 保留雲端控制平面日誌、撤銷金鑰、檢查責任共擔與供應商SLA。
AI安全事件 Prompt注入、RAG資料洩漏、模型輸出不當、AI SaaS資料外洩、模型濫用、代理工具越權。 AI Governance Owner、Data Owner、DPO、CISO 保存輸入輸出、模型/資料集版本、供應商條款與人工覆核紀錄。
供應鏈事件 供應商遭入侵、第三方服務中斷、惡意更新、子處理者外洩。 供應商管理、法務、CISO、Service Owner 取得供應商RCA、影響範圍、補救時程、合約通報與SLA證據。
弱點遭利用 Web漏洞、API漏洞、未修補CVE、弱密碼、錯誤組態遭利用。 DevSecOps、System Owner、CSIRT 確認攻擊路徑、補丁/緩解、掃描驗證與風險登錄更新。
實體安全事件 設備遺失、未授權進入、機房異常、紙本資料遺失。 Facility、IT、CISO、DPO 檢查門禁、CCTV、資產、加密狀態與資料範圍。
營運中斷期間資安事件 災害、停電、網路中斷、資料中心故障、DR切換時控制失效。 BCMS、IT、CISO、Service Owner 啟動BCP/DRP，確保中斷期間權限、日誌、變更與資料保護持續。
GHG/ESG資料完整性事件 排放係數遭竄改、盤查底稿遺失、查證證據未授權修改、碳揭露資料版本錯誤。 GHG Data Owner、ISMS、法務、查證窗口 保留資料版本、來源、計算邏輯、審核軌跡與查證溝通證據。

7. 事件分級與升級標準

等級 定義 判定條件 處理時限 核准/升級
SEV-1 緊急/重大 已造成或高度可能造成重大營運中斷、重大資料外洩、法規通報、客戶重大影響或媒體/聲譽重大風險。 核心服務中斷；高機密/大量PII外洩；勒索軟體擴散；雲端主帳號入侵；重大供應鏈攻擊；主管機關通報義務；AI系統造成重大錯誤決策或資料外洩。 15分鐘內通報CISO；30分鐘內啟動CSIRT；1小時內管理階層簡報；依義務執行外部通報。 CISO、Incident Commander、最高管理階層、法務、DPO。
SEV-2 高 已確認事件且影響重要系統、機密資料、受監管資料、供應商服務或可能擴散。 重要系統受影響；機密資料可能外洩；多使用者帳號異常；雲端重大錯誤設定；高風險漏洞遭利用；外部客戶可能受影響。 30分鐘內通報CISO/SOC Manager；4小時內完成初步遏止策略；24小時內提交初步報告。 CISO或授權主管。
SEV-3 中 局部事件或可疑活動，影響有限，尚無重大資料外洩或營運衝擊跡象。 單一端點惡意程式已阻擋；少量誤傳可回收；單一帳號異常已停用；中風險弱點被掃描但未確認利用。 4小時內登錄；1個工作日內完成初判與處置計畫；5個工作日內結案或升級。 SOC Manager / Incident Manager。
SEV-4 低 資訊安全事件徵兆、政策違反或弱點回報，未造成明顯影響。 可疑郵件、誤報告警、低風險弱點、可教育改善之違規、未成功攻擊嘗試。 1個工作日內登錄；10個工作日內完成處置或納入改善追蹤。 SOC / ISMS管理代表。

20. KPI / KRI 與監督量測

指標 定義 建議門檻 資料來源 管理用途
MTTD Mean Time to Detect，從事件發生或可偵測點至被發現之平均時間。 依事件類型設定，SEV-1/2應逐季降低。 SIEM、EDR、事件工單。 評估偵測能力。
MTTA Mean Time to Acknowledge，告警或通報至有人接手之平均時間。 SEV-1小於15分鐘；SEV-2小於30分鐘。 服務台、SOC工單。 評估值班與升級效率。
MTTC Mean Time to Contain，從確認事件至完成主要遏止之平均時間。 依事件類型與系統重要性設定。 事件處理日誌、變更紀錄。 評估遏止能力。
MTTR Mean Time to Recover/Resolve，從事件確認至復原或結案之平均時間。 不得超過RTO或管理階層核准之例外。 事件紀錄、BCP/DR紀錄。 評估復原與解決能力。
重大事件數 SEV-1/SEV-2事件數量與趨勢。 逐季監控；異常上升需管理審查。 事件登錄表。 管理風險趨勢。
事件重複發生率 同類根因或同一控制失效於期間內重複發生之比例。 應持續降低；重複重大事件需高階審查。 RCA、CAPA、事件檢討報告。 評估CAPA有效性。
通報延誤率 超過本程序通報時限之事件比例。 應接近0；重大事件不得延誤。 事件通報時間、發現時間。 評估通報文化與訓練。
CAPA逾期率 事件衍生矯正措施逾期未完成比例。 不得超過管理階層核准門檻。 CAPA追蹤表。 評估改善執行力。
