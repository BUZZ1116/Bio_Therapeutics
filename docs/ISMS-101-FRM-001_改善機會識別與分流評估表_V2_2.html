1. 表單目的

本表用於記錄改善機會之來源、客觀證據、10.1改善類型、影響分析、路徑判定、優先順序、Owner、期限、資源與有效性確認方式。它是改善機會進入ISMS流程前的分流評估表。

2. 使用時機

使用情境 觸發事件 最低輸出
提出改善機會 關注方回饋、KPI/KRI、稽核、管理審查、風險、供應商、資訊、資產、系統與服務資料、員工建議或外部要求顯示可改善事項。 完成來源、證據、改善類型與初步影響說明。
分流前評估 需要判斷改善走快速改善、CAPA、風險、變更、資源、管理審查或持續改善。 完成路徑判定、優先順序、Owner與期限。
管理審查或治理升級 改善需重大資源、跨部門協調、策略決策或最高管理階層核准。 形成管理審查輸入與建議輸出。

4. 10.1改善類型檢核

改善類型 判定問題 應填寫的證據
10.1 a 產品與服務改善 此機會是否改善資訊、資產、系統與服務，以滿足既有要求、未來需求或關注方期望？ 關注方、法規及合約要求、合約、需求趨勢、設計輸入、放行/服務資料或關注方回饋。
10.1 b 修正、預防或降低不期望影響 此機會是否與不符合事項發現、資訊安全事件、申訴或通報、重複問題、風險、KPI異常或不符合輸出有關？ 問題描述、發生資料、趨勢、影響、是否需CAPA或風險處理。
10.1 c 改善ISMS績效與有效性 此機會是否改善流程、資源、能力、供應商、稽核、管理審查、量測或跨系統整合？ KPI/KRI、流程績效、稽核結果、管理審查決策或改善效益。
