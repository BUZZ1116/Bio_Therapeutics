程序定位：本程序用於落實ISO/IEC 27001:2022 Clause 4.4「ISMS及其過程」與Clause 6.3「變更規劃」，並將ISMS流程、條款、Owner、風險、SoA、文件化資訊、稽核、管理審查、CAPA、PIMS、AI治理、GHG/CO2資料治理及供應鏈治理連接成可操作、可稽核、可驗證的企業流程管理架構。

1. 文件目的

本程序用於定義組織如何建立、實施、維持與持續改善ISMS及其必要流程，並明確描述各ISMS流程之活動、輸入、輸出、責任Owner、執行頻率、文件化資訊、驗證證據、績效監督、規劃變更與改善機制。

本程序強化Clause 6.3規劃變更、Clause 7.1資源、Clause 7.2能力、Clause 7.3認知、Clause 8.2風險評估、Clause 8.3風險處理及Clause 9.1績效評估之流程整合，確保組織在資訊安全、隱私、AI、GHG/CO2資料、雲端與ICT供應鏈場景中均能形成一致、完整且可追溯的管理證據鏈。

3. 名詞與定義

名詞 定義
ISMS流程 為達成資訊安全管理系統預期成果而建立之一組相互關聯或相互作用之活動。
流程整合 將ISMS各流程之輸入、輸出、責任、證據、控制、風險、KPI/KRI、稽核與改善活動連接成一致運作機制。
規劃變更 於ISMS或其流程、範圍、資源、責任、控制、文件化資訊或外部介面變更前，評估變更目的、可能後果、管理系統完整性、資源、責任與風險影響。
Process Owner 對特定ISMS流程之目的、範圍、輸入、輸出、活動、資源、績效、風險、文件化資訊與改善負責之角色。
Control Owner 對特定控制措施之設計、實施、監督、測試、證據保存與有效性負責之角色。
Clause Owner 對ISO/IEC 27001特定條款之符合性、證據完整性與持續改善負責之角色。
驗證證據 可證明流程活動及條款要求已被執行之文件、紀錄、報告、日誌、截圖、會議紀錄、合約、測試結果或審查紀錄。
證據鏈 由流程輸入、活動、輸出、控制證據、KPI/KRI、稽核發現、管理審查與CAPA串接形成的可追溯證據關係。

4. ISMS流程管理原則

原則 要求說明 最低證據
流程明確性 每一項ISMS流程均應定義流程目的、流程Owner、活動步驟、輸入、輸出、證據、執行頻率、績效指標與改善機制。 流程活動矩陣、流程與條款對應矩陣。
流程一致性 流程應與ISMS範圍、組織情境、關注方需求、風險管理、SoA、RACI及文件清冊一致。 ISMS範圍聲明、組織全景、RACI、SoA。
變更前規劃 任何影響ISMS目的、流程、範圍、控制、資源、角色、文件化資訊或驗證證據之重大變更，應於變更前完成影響評估。 ISMS變更影響評估表、文件制修訂申請。
資源、能力與認知分離管理 資源、能力與認知應分別管理，並分別保存資源核准、能力評估與認知宣導證據。 資源計畫、能力評估、訓練與認知紀錄。
風險與控制連動 流程活動之風險、控制措施、SoA與控制證據應可互相追溯。 風險登錄、風險處理計畫、SoA、控制措施矩陣。
持續改善閉環 流程活動若產生不符合、KRI超標、稽核缺失、事件教訓或管理審查決議，應回饋至CAPA及持續改善流程。 CAPA紀錄、改善追蹤、管理審查輸入。
