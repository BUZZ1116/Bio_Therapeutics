1. 作業目的

本作業指導書規範組織於軟體、API、雲端原生服務、資料平台、AI系統、MLOps、Prompt應用與RAG應用之需求、設計、開發、測試、部署、維運、變更與退場階段，導入安全與隱私保護要求，確保系統於整個生命週期中維持機密性、完整性、可用性、可追溯性、合法合規性與韌性。

本文件目的在於將安全開發從單點測試提升為生命週期管理，透過安全需求、威脅建模、安全架構審查、安全程式撰寫、程式碼掃描、開源與供應鏈管理、API安全、雲端與容器安全、AI安全、測試與上線閘門、變更管理與持續監控，建立可驗證、可稽核、可持續改善的企業級安全開發機制。

2. 作業原則

  • 所有開發活動應採取Secure by Design、Privacy by Design、Secure by Default與Defense in Depth原則。
  • 安全需求應在需求階段納入，不得僅於上線前以弱點掃描取代安全設計。
  • 高風險系統、對外服務、處理PII/客戶資料/高機密資料、支援關鍵業務流程或使用AI決策之系統，應完成威脅建模與安全架構審查。
  • 所有原始碼、套件、容器映像、IaC、CI/CD、API、Secrets、模型服務與Prompt應用均應納入安全檢查與版本追蹤。
  • 不符合安全閘門之版本不得上線，除非完成例外核准、補償控制、剩餘風險接受與期限追蹤。
  • 安全開發證據應完整保存，支援ISMS稽核、內部稽核、客戶審查、供應鏈安全、事件調查與管理審查。

3. 名詞與定義

名詞 定義
安全開發生命週期（SSDLC） 於軟體與系統生命週期各階段納入安全需求、風險分析、設計審查、程式碼安全、測試、部署、監控與改善之管理方法。
安全需求 基於法規、合約、風險、資料分類、威脅情境、架構與控制要求所定義之安全功能、非功能需求與限制條件。
威脅建模 識別系統資產、信任邊界、資料流、攻擊者、威脅、濫用案例、控制措施與剩餘風險之方法。
安全架構審查 對系統架構、資料流、信任邊界、身分驗證、授權、加密、日誌、網路、雲端、第三方與營運韌性之審查。
SAST Static Application Security Testing，靜態應用程式安全測試，用於分析原始碼或編譯前程式碼安全缺陷。
DAST Dynamic Application Security Testing，動態應用程式安全測試，用於分析執行中應用程式之外部可利用弱點。
SCA Software Composition Analysis，軟體組成分析，用於識別開源套件、第三方元件、授權與已知弱點。
IaC掃描 Infrastructure as Code安全掃描，用於檢查Terraform、CloudFormation、Kubernetes YAML、Helm、Ansible等基礎架構設定風險。
SBOM Software Bill of Materials，軟體組成清單，用於記錄軟體元件、版本、供應商、授權與弱點曝險。
安全閘門（Security Gate） 於合併、建置、測試、部署、上線或版本發布前設定之安全檢查條件，未符合者應阻擋或進入例外流程。
Prompt應用 使用Prompt模板、系統指令、工具調用、RAG、Agent或AI API完成業務功能之AI應用。

8. 安全編碼要求

控制領域 作業要求 禁止事項 / 注意事項
輸入驗證 所有外部輸入、檔案、Header、Cookie、API參數、Prompt、Webhook與批次資料應進行白名單、型別、長度、格式與語意檢查。 不得信任前端檢查或第三方傳入資料。
輸出編碼 依HTML、JavaScript、SQL、LDAP、Shell、URL、JSON、XML等情境採適當編碼或安全函式。 不得直接拼接未處理資料至輸出或命令。
身份驗證 使用組織核准身份服務與標準協定，避免自製脆弱驗證。 不得自行儲存明文密碼或弱雜湊。
授權檢查 每個敏感功能、API、資料物件與管理操作應於伺服器端驗證權限。 不得僅依前端隱藏按鈕或路由控制權限。
Secrets管理 Secrets、API Key、Token、憑證與私鑰應使用Secret Manager、Vault、KMS或受控環境變數。 不得提交至原始碼、映像、Issue、聊天或文件。
錯誤處理 錯誤訊息應提供必要資訊，不揭露堆疊、SQL、路徑、Token、內部IP或敏感資料。 不得將詳細錯誤直接回傳外部使用者。
加密使用 使用核准加密演算法、TLS、KMS、憑證管理與金鑰輪替，不得自製加密演算法。 不得硬編碼金鑰或使用已淘汰演算法。
檔案處理 檔案上傳應限制類型、大小、內容掃描、儲存位置、執行權限與下載授權。 不得允許上傳檔案於可執行路徑直接執行。
AI Prompt安全 Prompt模板應避免暴露系統指令、Secrets、內部規則與高機密上下文，並對工具調用與RAG檢索做權限控制。 不得將PII或高機密資料送入未核准AI服務。

12. API與微服務安全設計

控制項目 要求 證據
API資產盤點 所有API應納入API清冊，包含Owner、資料分類、認證方式、外部/內部、版本與風險等級。 API清冊、架構文件。
認證與授權 使用OAuth2/OIDC、mTLS、JWT驗證、Scope、Role或等效機制，避免匿名敏感API。 API Gateway設定、測試紀錄。
物件層級授權 每次存取資料物件均需檢查使用者是否有權存取該物件。 授權測試案例。
輸入限制與Schema驗證 API應驗證Schema、大小、型別、格式、速率、重放與簽章。 API測試報告。
速率限制與濫用防護 外部API與高風險API應具Rate Limit、Quota、Bot防護、異常行為告警。 API Gateway政策。
版本與退場 API版本變更應評估相容性與安全影響，舊版API應設定退場期限。 版本策略、退場紀錄。
日誌與追蹤 API應記錄Request ID、使用者、端點、狀態碼、資料量、失敗原因與安全事件。 API Log、SIEM接入。

13. 資料、隱私與加密安全設計

控制領域 作業要求 適用情境
資料分類 需求與設計階段應識別資料分類、PII、客戶資料、高機密、模型資料與法規限制。 所有涉及資料處理之系統。
資料最小化 僅蒐集、處理、儲存與傳輸業務必要資料，避免測試環境使用未遮罩正式資料。 PII、測試資料、AI訓練資料。
加密傳輸 外部與內部敏感資料傳輸應使用TLS 1.2以上或組織核准安全通道。 Web、API、DB、MFT、AI API。
加密儲存 敏感資料、備份、物件儲存、資料庫、Secrets與模型權重應依風險加密保存。 PII、高機密、客戶資料、模型權重。
金鑰管理 金鑰應由KMS/HSM/Vault等受控機制管理，具Owner、用途、輪替、撤銷與存取紀錄。 所有加密應用。
資料主體權利 涉及PII者應支援查詢、更正、刪除、限制處理、可攜出與紀錄保存要求。 隱私相關系統。
保留與刪除 系統應設計資料保存期限、刪除、封存、匿名化與退場處理機制。 資料平台、SaaS、AI資料集。

14. 雲端原生、容器與IaC安全要求

領域 安全要求 證據
IaC管制 所有正式雲端基礎架構應盡量以IaC管理，提交前執行安全掃描與審查。 IaC Repository、掃描報告。
雲端身份權限 使用最小權限、角色分離、短期憑證、工作負載身份與權限審查。 IAM政策、權限審查。
網路隔離 依信任邊界設計VPC/VNet、Subnet、Security Group、Network Policy與Private Endpoint。 網路架構圖、規則清單。
容器映像 使用可信Base Image、最小化映像、非Root執行、映像掃描與簽章。 映像掃描、Registry政策。
Kubernetes安全 啟用RBAC、Admission Control、Pod Security、Secrets管理、Network Policy與稽核日誌。 K8s設定、稽核日誌。
CSPM / CNAPP 正式雲端環境應納入CSPM/CNAPP或等效監控，追蹤設定偏差與風險。 CSPM報告、修復紀錄。

15. AI系統、Prompt應用與MLOps安全開發要求

領域 作業要求 證據
AI資產登錄 AI模型、Prompt模板、RAG資料源、Agent工具、模型API與MLOps平台應納入清冊並指定Owner。 AI模型與Prompt資產清冊。
資料治理 訓練、微調、評估、RAG與推論資料應確認來源、授權、PII、分類、保留與使用限制。 資料追蹤清冊、DPIA。
Prompt安全 系統Prompt與工具指令應受版本控管，避免暴露Secrets、內部政策與高機密資訊。 Prompt版本紀錄、審查紀錄。
RAG權限 RAG檢索應依使用者權限與資料分類控管，不得因索引而繞過原始資料權限。 RAG權限測試、檢索日誌。
模型輸出控制 高風險輸出應具安全過濾、內容政策、敏感資料偵測、人工覆核與標示機制。 輸出覆核紀錄、DLP告警。
模型供應鏈 外部模型、開源模型、模型權重、插件、工具與SDK應審查來源、授權、弱點與資料使用條款。 供應商審查、授權紀錄。
AI安全測試 上線前測試Prompt Injection、越權檢索、資料外洩、濫用、偏差與模型服務拒絕服務風險。 AI安全測試報告。
人類監督 涉及重大決策、客戶影響、法規或高風險場景者，應明確設計Human Review與責任歸屬。 作業流程、審核紀錄。

16. 外包開發與第三方元件管理

管理項目 作業要求 證據
外包安全要求 合約應規範安全開發、保密、智慧財產權、開源使用、弱點修復、事件通報與稽核權。 合約、NDA、SOW。
供應商能力 重要開發供應商應評估安全能力、開發流程、測試方法、資安人員能力與交付證據。 供應商評估表。

19. 安全開發KPI/KRI

指標 定義 目標 / 門檻 用途
安全閘門通過率 符合CI/CD安全閘門之建置或部署比例。 持續提升；重大系統需達成內部目標。 DevSecOps成熟度。
Critical/High缺陷逾期率 超過修復期限仍未關閉之Critical/High安全缺陷比例。 Critical目標0。 風險升級與資源分配。
SCA高風險元件數 尚未修補或未核准例外之高風險第三方元件數。 持續下降。 供應鏈安全管理。
Secrets洩漏事件數 Repository、CI/CD、日誌或文件中偵測到Secrets之事件數。 目標0；發現需立即撤換。 開發安全文化與管制。
威脅建模覆蓋率 符合條件之高風險專案完成威脅建模比例。 高風險專案目標100%。 設計階段安全成熟度。
安全測試修復率 安全測試發現缺陷於期限內修復比例。 依風險等級設定。 修復效率。
AI安全測試覆蓋率 AI應用完成Prompt、RAG、模型服務與資料安全測試比例。 高風險AI應用目標100%。 AI治理與安全控制有效性。
