1. 作業目的

本作業指導書規範測試資料之需求提出、分類分級、產生、抽樣、遮罩、去識別、使用、傳輸、保存、監控、刪除、例外核准與稽核要求，確保測試活動能取得足夠且具代表性之資料，同時避免正式資料、PII、客戶資料、Secrets、機密資料、AI訓練資料或營運敏感資料在非正式環境中遭未授權存取、外洩、誤用或不當保存。

本文件支援安全開發生命週期、安全測試、環境區隔、隱私保護、AI治理與供應商管理，要求測試資料管理具備可追溯、可核准、可遮罩、可限制、可刪除、可稽核及可驗證之控制能力。

2. 作業原則

  • 測試資料應優先使用合成資料、範例資料或人工建立資料；不得將正式資料作為測試資料之預設選項。
  • 測試資料應依資料分類分級管理，任何可能含PII、客戶資料、機密/高機密資料、交易資料、健康/金融資料、AI資料、Prompt或GHG/ESG底稿之資料，應先完成資料影響評估與核准。
  • 正式資料複製至非正式環境前，應完成資料最小化、遮罩、去識別、抽樣、加密、存取限制、保存期限、刪除方式與監控設計。
  • 測試資料不得包含明文密碼、正式Secrets、正式API Key、正式憑證、私鑰、Token、正式金鑰材料或可直接登入正式系統之資料。
  • 測試資料之使用應與測試目的相符，不得擴大用途、轉移給未核准人員或供應商，亦不得輸入未核准AI工具或外部服務。
  • 測試資料於測試目的完成、有效期限屆滿、專案結束或供應商退場時，應刪除、銷毀或依核准方式封存，並保存刪除或封存證據。

3. 名詞與定義

名詞 定義
測試資料 為開發、測試、驗證、UAT、效能測試、安全測試、AI評估、教育訓練或供應商測試所使用之資料。
正式資料 正式環境中真實業務、客戶、PII、交易、機密、AI或營運資料。
合成資料 依統計規則或業務邏輯人工或自動產生，並非直接取自正式個人或客戶資料之測試資料。
遮罩資料 將敏感欄位以替代、亂數、泛化、雜湊、Tokenization或其他方法處理，使其降低識別或敏感程度之資料。
去識別資料 經處理後無法或難以識別特定個人或客戶，且需評估重新識別風險之資料。
匿名化 使資料不可再識別特定個人，且無合理方式重新識別之處理。
假名化 以替代識別碼取代直接識別資料，但仍可能透過額外資訊重新識別之處理。
資料最小化 僅取得測試目的必要之最少資料欄位、筆數、期間與敏感內容。
重新識別風險 遮罩、假名化或去識別資料被透過其他資料集、邏輯或推論重新識別之可能性。
測試資料集 依特定測試目的建立、版本化、核准、保存與刪除之一組測試資料。
RAG測試資料源 供AI檢索增強生成系統測試使用之文件、知識庫、向量索引或資料片段。

5. 測試資料分類與允許使用原則

資料類型 允許使用原則 最低控制 核准角色
合成資料 優先使用，可用於一般開發、測試、教育訓練與安全測試。 需符合測試案例需求，不得意外包含真實個資或Secrets。 System Owner / QA Owner。
範例資料 可用於示範、文件、訓練與低風險測試。 不得包含真實客戶、PII、正式交易或內部機密。 System Owner。
遮罩正式資料 可於必要情境使用，需完成遮罩、最小化、核准、保存期限與刪除。 欄位遮罩、存取限制、加密、日誌、刪除證明。 Data Owner / DPO / CISO依風險。
假名化資料 可用於統計、測試或AI評估，但需控制重新識別Key。 重新識別Key分離保存，限制存取。 Data Owner / DPO。
未遮罩正式資料 原則禁止於非正式環境使用。 僅於無替代方案且具強控制、短期限與高層核准時允許。 CISO / DPO / Data Owner / 管理階層授權代表。
Secrets或憑證資料 不得作為測試資料；測試應使用專用短期測試Secrets。 Secrets掃描、測試Key、到期與撤銷。 Secrets Owner。
AI訓練或評估資料 需依AI治理、資料授權、PII、資料品質與模型用途核准。 版本、來源、授權、去識別、刪除與模型記錄。 AI Governance / Data Owner / DPO。
RAG測試資料 需確認文件來源、資料分類、權限繼承、索引刪除與越權檢索測試。 RAG權限測試、索引清冊、刪除同步。 AI Governance / Data Owner。

6. 測試資料管理流程

階段 作業要求 責任角色 輸出證據
1. 需求提出 說明測試目的、系統、環境、資料欄位、筆數、期間、資料分類、使用者與保存期限。 QA / System Owner 測試資料申請。
2. 替代方案評估 優先評估合成資料、範例資料、Mock資料、Stub或小型抽樣資料。 Test Data Owner / QA 替代方案評估紀錄。
3. 分類與影響評估 確認資料是否含PII、客戶資料、機密、AI資料、跨境、合約限制或重新識別風險。 Data Owner / DPO 資料影響評估。
4. 遮罩與最小化設計 定義欄位遮罩、假名化、匿名化、抽樣、欄位排除、Tokenization與驗證方式。 Data Engineer / DPO 遮罩設計與測試。
5. 安全核准 依資料敏感度取得Data Owner、DPO、CISO、AI Governance或供應商管理核准。 相關Owner 核准紀錄。
6. 產生與載入 依核准方式產生、抽取、遮罩、驗證、加密傳輸並載入指定測試環境。 Data Engineer / DBA / DevSecOps 產生與載入紀錄。
7. 使用與監控 依核准目的使用，監控存取、複製、下載、外傳、AI輸入與供應商存取。 QA / SOC / Data Owner 使用與監控紀錄。
8. 變更與續用 資料範圍、用途、環境、使用者、期限或供應商變更時需重新核准。 System Owner / Data Owner 變更核准。
9. 刪除與關閉 測試完成或期限屆滿後刪除資料、索引、備份、快照、暫存與輸出，保存證據。 System Owner / Data Owner 刪除證明。

7. 測試資料產生方法與適用情境

方法 適用情境 優點 注意事項
合成資料產生 功能測試、壓力測試、教育訓練、初期開發。 不含真實PII，可大量產生且低風險。 需符合業務規則、資料格式與邊界條件。
資料工廠 / Test Data Factory 需要可重複、可版本化之標準測試資料集。 可自動化、可追溯、可重複建置。 需納入版本控管與存取控制。
Mock / Stub資料 API測試、外部服務尚未可用或不可直接連正式服務。 降低外部依賴與正式服務誤呼叫。 需確保與真實行為足夠一致。
抽樣遮罩資料 複雜業務邏輯、UAT、資料遷移驗證。 保留部分真實分布與關聯性。 需嚴格遮罩、最小化與重新識別風險評估。
匿名化資料 統計測試、趨勢分析、低風險模型驗證。 降低個人識別風險。 需確認匿名化不可逆且無合理重新識別方式。
假名化資料 需維持同一個體關聯性之測試。 可保留資料關聯與測試一致性。 需保護對照表與重新識別Key。
邊界條件資料 安全測試、輸入驗證、例外流程測試。 強化測試完整性。 不得包含真實敏感資料。
AI評估資料集 AI輸出品質、安全性、偏誤與RAG測試。 可支援模型評估與安全測試。 需版本化、授權、資料分類與刪除控制。

8. 遮罩、去識別與匿名化要求

技術方法 適用資料 要求 風險注意
替代 / Substitution 姓名、地址、電話、Email、公司名稱。 以可信測試值替代，保留格式。 需避免替代值仍指向真實個人。
亂數化 / Randomization ID、金額、日期、序號。 保留資料型態與範圍，避免破壞測試邏輯。 關聯性需求需另行設計。
泛化 / Generalization 年齡、地區、職稱、時間。 將精細資料轉為區間或較高層級。 可能降低測試精度。
截斷 / Suppression 不必要敏感欄位。 直接移除測試不需要欄位。 需確認應用不依賴該欄位。
雜湊 / Hashing 識別碼、帳號、Email。 需加Salt並評估字典攻擊風險。 不可將低熵資料單純Hash視為匿名。
Tokenization 需保留一致性且降低直接識別之資料。 Token對照表需分離、加密與嚴格限制。 若對照表外洩可重新識別。
日期偏移 出生日期、交易日期、事件日期。 維持相對間距但改變實際日期。 仍可能透過罕見事件重新識別。
資料合成 大量PII、AI訓練、效能測試。 以統計或規則生成非真實資料。 需檢查是否過度接近真實個體。
差分隱私或統計保護 分析、模型評估、報表測試。 依風險使用噪音或限制輸出。 需專業評估效用與風險。

9. 測試資料安全控制要求

控制項目 最低要求 高風險加強要求
存取控制 測試資料僅限核准人員、核准系統與核准環境使用。 高風險資料採PAM/JIT、MFA與定期權限審查。
加密 測試資料傳輸與儲存應依分類加密。 PII、客戶資料、機密以上需KMS或等效金鑰控管。
環境區隔 測試資料應放置於核准測試環境，不得散落於個人端點、聊天工具或未核准雲端。 正式資料副本需獨立網段、DLP與SIEM監控。
日誌與監控 測試資料存取、匯出、下載、刪除與跨環境傳輸需記錄。 高風險資料需建立異常告警。
DLP控制 對含PII、客戶資料或機密資料之測試資料套用DLP、CASB或外傳監控。 外部分享與AI輸入需阻擋或告警。
保存期限 測試資料需設定明確期限，逾期刪除或重新核准。 高風險資料最短化保存並定期檢查。
版本管理 重要測試資料集需版本、來源、遮罩規則、用途與Owner。 AI評估資料集需與模型版本關聯。
備份控制 測試資料備份需符合保存與刪除要求；不得因備份延長未核准保存。 刪除時需處理快照、備份與暫存。

10. 禁止事項

禁止事項 說明 例外條件
禁止未核准複製正式資料 不得將正式資料庫、檔案、日誌、RAG資料源或客戶資料直接複製至非正式環境。 需正式資料使用申請與核准。
禁止未遮罩PII測試 不得以未遮罩PII進行一般開發、測試、教育訓練或供應商測試。 僅重大例外並需DPO、Data Owner、CISO核准。
禁止保存正式Secrets 測試資料不得包含正式密碼、Token、API Key、私鑰、憑證或KMS材料。 無例外；應使用測試Secrets。
禁止輸入未核准AI工具 測試資料不得輸入未核准AI、翻譯、資料分析或外部SaaS工具。 需AI工具與資料使用政策核准。
禁止任意外部分享 不得將測試資料透過Email、聊天、個人雲端、USB或未核准共享連結外傳。 需Data Owner與Security核准。
禁止永久保存測試資料 測試資料不得無期限保存。 需封存理由、保存期限與核准。
禁止資料回流正式 測試環境產生或修改之資料不得直接回寫正式環境。 需變更核准、驗證與資料品質檢查。
禁止供應商自行保留資料 供應商不得於專案結束後保留測試資料、備份、快照或衍生資料。 需合約明定封存或法定保存。

11. AI、MLOps、RAG與資料科學測試資料管理

場景 控制要求 證據
AI模型評估資料 評估資料集需標示來源、資料分類、授權、偏誤風險、PII狀態、版本與保存期限。 AI評估資料清冊。
模型微調資料 正式資料用於微調需AI治理審查、資料授權、DPO審查、去識別與模型風險評估。 AI資料使用核准。
Prompt測試資料 Prompt測試不得包含Secrets、PII或客戶資料，除非核准並受控。 Prompt測試紀錄。
RAG測試資料源 測試RAG資料源需與正式資料源分離，或以遮罩/合成資料建立測試索引。 RAG資料源清冊。
向量資料庫測試索引 測試向量索引需標示資料來源、嵌入模型版本、刪除機制與權限。 向量庫版本紀錄。

16. 測試資料監控與異常處理

異常情境 判定條件 處置要求
未核准正式資料出現於測試環境 DLP、抽查、資料庫掃描或人員通報發現未核准正式資料。 立即限制存取、通報CISO/Data Owner/DPO，評估是否啟動事件。
測試資料含Secrets Secrets掃描命中有效Key、Token、密碼、私鑰或憑證。 立即撤銷輪替、清除資料、調查來源。
測試資料外部分享 發現測試資料被分享至個人雲端、Email、聊天工具、未核准SaaS或供應商。 停止分享、回收連結、調查與通報。
測試資料逾期保存 資料超過核准期限未刪除或未續核。 通知Owner，限制存取並要求刪除或重新核准。
AI工具輸入敏感測試資料 敏感測試資料輸入未核准AI工具或外部模型。 依AI資料使用政策與事件程序處理。
重新識別風險升高 遮罩資料可與其他資料集結合識別個人或客戶。 停止使用，重新遮罩或匿名化，DPO重評。
供應商逾期保留資料 供應商未於期限內刪除測試資料或未提供證明。 依合約要求補救、暫停存取並升級風險。
測試資料回流正式環境 發現測試資料或假資料被寫入正式系統。 立即隔離資料、修正、評估業務影響與事件等級。
