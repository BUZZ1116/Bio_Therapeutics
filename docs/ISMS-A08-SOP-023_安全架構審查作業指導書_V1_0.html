1. 作業目的

本作業指導書規範安全架構審查之觸發條件、分級方式、審查流程、輸入資料、審查面向、威脅模型、風險判定、缺失追蹤、例外核准、上線閘門、稽核證據與持續改善要求，確保新系統、新服務、重大變更、雲端導入、供應商整合、AI/ML應用、資料平台與網路架構於設計階段即納入資訊安全、隱私、AI治理、供應鏈、營運持續與合規要求。

本文件旨在落實Security by Design、Privacy by Design、AI Risk by Design、Cloud Security by Design、Zero Trust、Least Privilege、Data Minimization、Secure Defaults、Auditability及Resilience by Design，降低上線後再補救造成之成本、風險、延誤、合規缺口與資安事件。

2. 作業原則

  • 安全架構審查應於需求、設計、導入、採購、外包、雲端建立、AI模型部署或重大變更之早期階段執行，不得等到上線前才進行形式化補件。
  • 安全架構應遵循安全預設、最小權限、最小暴露、資料最小化、分區分段、加密保護、日誌可追溯、失敗安全、可復原及防禦縱深原則。
  • 涉及PII、客戶資料、機密/高機密資料、特權權限、外部連線、供應商代管、AI模型、RAG、AI Agent、自動化決策、跨境處理或關鍵營運流程者，應執行強化安全架構審查。
  • 審查結論應形成明確決策：通過、有條件通過、需修正後再審、風險接受後通過或不通過；不得以口頭同意取代正式紀錄。
  • 安全架構缺失應連動風險登錄、風險處理計畫、變更管理、上線閘門、供應商要求、合約條款與管理審查。
  • 架構設計應納入可觀測性、可稽核性、可回復性與可退場性，避免形成不可監控、不可轉移、不可復原或責任邊界不明之架構。

3. 名詞與定義

名詞 定義
安全架構 為滿足資訊安全、隱私、合規、營運持續與風險控制需求而設計之技術元件、資料流、信任邊界、控制措施、流程與責任配置。
安全架構審查 針對系統或服務架構進行之結構化審查，確認其安全設計、威脅模型、資料保護、存取控制、網路、日誌、復原、供應商控制及AI治理符合組織要求。
威脅模型 識別系統資產、信任邊界、攻擊面、威脅、濫用情境、控制缺口與緩解措施之分析方法。
信任邊界 不同信任等級、控制責任或資料保護要求之間的邊界，例如外部/內部、使用者/管理、應用/資料庫、組織/供應商、AI模型/資料源。
資料流圖 描述資料在使用者、系統、服務、資料庫、API、雲端、供應商及AI模型間流動與處理方式之圖示或文件。
架構決策紀錄 ADR Architecture Decision Record，記錄重要架構選項、決策理由、替代方案、風險、限制與後續影響之文件。
上線閘門 系統、服務或重大變更上線前必須完成之審查、測試、核准或風險接受條件。
安全控制模式 可重複使用之安全設計樣式，例如SSO/MFA、API Gateway、Private Endpoint、PAM、Secrets Manager、WAF、RAG權限繼承等。
架構例外 因業務、技術、供應商或時間限制，無法符合安全架構要求而需正式核准之偏差。

4. 角色與責任

角色 主要責任 主要輸出 / 證據
CISO / 資訊安全負責人 核准高風險架構、重大例外、剩餘風險接受、不通過決策與管理審查輸入。 核准紀錄、風險接受、管理審查資料。
Security Architecture Owner 制定審查標準、主持安全架構審查、確認控制要求、追蹤缺失、維護安全模式與架構審查清冊。 審查紀錄、架構審查意見、控制要求。
Enterprise Architect 確保安全架構與企業架構、技術藍圖、資料架構、雲端策略、供應商策略與系統生命週期一致。 企業架構審查意見、ADR。
Solution / System Architect 提供系統架構、資料流、信任邊界、技術選型、整合方式、部署方式與設計決策。 架構文件、ADR、資料流圖。
Application / Service Owner 提出業務需求、資料分類、服務重要性、上線時程、系統Owner與風險接受需求。 需求文件、Owner確認。
DevSecOps / AppSec Owner 審查安全開發、CI/CD、SAST/DAST/SCA、Secrets、API、容器、IaC與應用安全控制。 安全測試計畫、Pipeline證據。
Cloud Security Owner 審查雲端帳號、IAM、網路、KMS、日誌、CSPM、備份、區域、雲端標籤與共享責任。 雲端架構審查、CSPM要求。
Network Security Owner 審查網路分段、防火牆、VPN/ZTNA、WAF、API Gateway、DDoS、DNS與連線規則。 網路安全審查意見。
Data Owner 確認資料分類、資料流、保留、刪除、加密、遮罩、備份、共享與資料使用限制。 資料分類與使用核准。
DPO / 隱私負責人 審查PII、跨境、DPIA、資料主體權利、自動化決策與隱私風險。 隱私審查、DPIA。
AI Governance / MLOps Owner 審查AI模型、RAG、Prompt、訓練資料、模型版本、AI輸出、AI Agent與AI供應商風險。 AI風險審查、模型治理紀錄。
Supplier Management / Legal 審查供應商責任、合約條款、SLA、DPA、子處理者、稽核權、資料不訓練與退場。 供應商評估、合約審查。
BCMS / ICT Readiness Owner 審查RTO/RPO、備援、備份、DR、容量、服務可用性與復原演練。 ICT備妥性評估。
Internal Auditor 抽查架構審查程序、證據、缺失追蹤、風險接受與上線閘門。 稽核底稿、稽核發現。

5. 安全架構審查觸發條件

觸發情境 是否必須審查 審查強度 說明
新系統或新服務導入 是 標準或強化 所有正式上線系統、平台、SaaS、雲端服務或對外服務應完成安全架構審查。
重大系統變更 是 依影響判定 涉及身份、權限、資料流、網路、供應商、雲端架構、AI模型、資料分類或控制改變。
雲端服務或雲端架構導入 是 強化 包含IaaS/PaaS/SaaS、跨區、Private Link、KMS、CSPM、雲端日誌與共享責任。
對外服務、API或客戶入口 是 強化 包含Web、Mobile、API、Webhook、B2B、對外資料交換與客戶Portal。
處理PII、客戶資料、機密或高機密資料 是 強化 需資料Owner、DPO與CISO審查。
AI/ML、生成式AI、RAG或AI Agent 是 強化 需AI治理、模型風險、Prompt/RAG、資料不訓練、AI安全測試與人類監督設計。
供應商代管或外包開發/維運 是 標準或強化 需供應商安全、合約、SLA、退場、日誌與存取控制。
重大弱點或事件後架構修正 是 強化 需納入根因、CAPA、防再發控制與復原設計。
法規、客戶或合約新增要求 是 依影響判定 需確認架構是否符合新要求並形成證據。
低風險設定調整或非正式原型 視情況 輕量 不得處理正式資料、PII、客戶資料、Secrets或高風險連線。

6. 安全架構審查流程

階段 作業要求 責任角色 輸出證據
1. 審查申請 申請人提交需求、架構圖、資料流、技術清單、資料分類、供應商、風險與上線時程。 Service Owner / Architect 安全架構審查申請。
2. 初步分級 依資料分類、對外暴露、AI/雲端、供應商、服務重要性與法規要求判定審查強度。 Security Architecture Owner 審查分級結果。
3. 文件完整性檢查 確認架構圖、資料流、信任邊界、控制設計、RTO/RPO、供應商與測試計畫齊備。 Security Reviewer 文件檢核表。
4. 威脅模型與風險分析 識別攻擊面、濫用情境、控制缺口、資料外洩、權限濫用、供應鏈與AI風險。 Security Architecture / AppSec / AI Owner 威脅模型與風險紀錄。
5. 控制審查 審查身份、存取、加密、網路、日誌、備份、弱點、供應商、隱私、AI、營運持續等控制。 審查小組 審查意見與缺失清單。
6. 修正與再審 針對缺失提出修正、補償控制、風險處理或例外申請，必要時重新審查。 Project / System Owner 修正證據、再審紀錄。
7. 結論與核准 形成通過、有條件通過、需再審、風險接受或不通過結論。 CISO / Security Architecture Owner 核准紀錄。
8. 上線閘門與追蹤 將未完成項納入上線條件、風險登錄、變更管理、測試計畫與管理審查。 ISMS管理代表 / Project Owner 追蹤紀錄。
9. 審查回饋與模式更新 將重複缺失、有效控制與架構模式回饋至安全控制模式庫與訓練教材。 Security Architecture Owner 安全模式更新紀錄。

10. 威脅模型與攻擊面審查

上線前High/Critical未關閉數 上線前仍未關閉且未正式接受之High/Critical缺失數。 目標0。 上線風險控制。
架構缺失逾期數 超過期限未修正或未重評之架構缺失數。 Critical/High目標0。 改善追蹤。
風險接受到期未重評數 到期但未重評或未關閉之架構風險接受數。 目標0。 例外治理。
重複性架構缺失數 同類型架構缺失於不同專案重複發生次數。 趨勢應下降。 安全模式與教育改善。
事件後架構改善完成率 事件根因涉及架構缺口之改善完成比例。 目標100%。 防再發能力。
AI架構審查缺失數 AI/RAG/MLOps/Agent相關安全架構缺失數。 重大缺失需管理審查。 AI治理成熟度。
供應商架構缺口數 供應商或SaaS責任邊界、日誌、備份、DPA或退場缺口數。 高風險缺口需改善或接受。 供應鏈風險管理。
