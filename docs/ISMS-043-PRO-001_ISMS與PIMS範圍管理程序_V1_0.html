1. 目的

本程序旨在建立資訊安全管理系統（ISMS）與隱私資訊管理系統（PIMS）範圍之界定、審查、核准、發布、維護、變更與持續改善方法，以確保組織能清楚定義管理系統之邊界、適用性、責任、控制範圍、驗證範圍及文件化資訊要求。

本程序亦用於確保ISMS/PIMS範圍能完整涵蓋組織全景、關注方需求、法規與合約要求、資訊資產、PII處理活動、AI系統與服務、雲端與資料中心、外包與供應鏈、GHG/CO2資料治理及第三方查證證據，避免範圍不足、排除不當或驗證聲明誤導。

2. 適用範圍

本程序適用於下列範圍管理活動：

  • ISMS與PIMS首次建立時之範圍界定。
  • ISMS/PIMS年度範圍審查與管理審查輸入。
  • 組織、流程、產品、服務、場域、資訊資產、系統、雲端或供應商變更時之範圍重新評估。
  • PII處理活動、PII controller / processor角色、第三方處理、跨境傳輸或資料主體權利流程變更時之PIMS範圍調整。
  • AI系統、AI服務、生成式AI、模型API、Prompt、RAG、AI資料集或AI供應商導入時之範圍判定。
  • GHG/CO2資料、產品碳足跡、碳中和聲明、碳資料平台、查證證據或氣候變遷相關議題納入ISMS/PIMS時之範圍調整。
  • 第三方驗證、客戶稽核、監理檢查或合約要求下之範圍聲明維護。
  • 排除事項、適用性聲明書、風險登錄、控制措施、稽核方案及管理審查之連動更新。

4. 名詞與定義

名詞 定義
ISMS Information Security Management System，資訊安全管理系統，指組織用於建立、實施、維護及持續改善資訊安全之管理系統。
PIMS Privacy Information Management System，隱私資訊管理系統，為ISMS之延伸，用於管理PII保護、PII controller / processor責任及隱私風險。
ISMS範圍 組織納入ISMS管理之組織單位、場所、流程、產品、服務、資訊資產、技術環境、外部活動及控制邊界。
PIMS範圍 組織納入PIMS管理之PII處理活動、資料主體、處理目的、PII類別、角色、第三方處理、跨境傳輸及隱私控制邊界。
邊界 管理系統適用範圍之組織、實體、技術、地理、流程、系統、資料、供應商、雲端與法律責任界線。
排除 經風險、法規、合約與控制適用性審查後，組織判定不納入管理系統範圍之活動、場所、系統或控制項目。排除必須有合理理由且不得影響管理系統符合性。
PII Personally Identifiable Information，可識別特定自然人之資訊，包括直接識別與間接識別資料。
PII Controller 決定PII處理目的與方式之組織或單位。
PII Processor 依PII controller指示代表其處理PII之組織或單位。
AI系統 基於模型、演算法、資料、推論、生成或自動化分析之系統，包含內部自建、外部取得、雲端AI、生成式AI、RAG、模型API及自動化決策功能。
GHG/CO2資料 溫室氣體盤查、活動數據、排放係數、產品碳足跡、碳中和聲明、能源使用及相關查證證據之資料。
外部依賴 由供應商、外包服務商、雲端平台、資料中心、AI服務商、顧問、查證機構或第四方提供之服務、資料、系統或支援。
驗證範圍 對外聲明並供第三方驗證或稽核之管理系統範圍，包括適用組織、地點、流程、服務、技術、控制措施及排除事項。

6. 範圍管理原則

  • ISMS/PIMS範圍應以組織全景、關注方需求、資訊安全風險、隱私風險、法規合約與預期結果為基礎。
  • 範圍應清楚說明納入與排除之組織、地點、流程、產品、服務、資訊資產、系統、資料、供應商、AI與PII處理活動。
  • PIMS範圍不得與PII處理事實不一致，且應明確區分PII controller、PII processor及共同責任。
  • AI系統與服務若處理機密資料、PII、客戶資料、模型資料、Prompt、RAG或GHG/CO2資料，應評估納入ISMS/PIMS範圍。
  • GHG/CO2資料若涉及查證、客戶承諾、產品碳足跡、碳中和聲明、PII或資料完整性要求，應視為資訊資產並評估納入ISMS/PIMS範圍。
  • 任何排除均應保存理由、風險評估、合規確認與核准證據。
  • 範圍聲明應可被內部稽核、外部驗證、客戶稽核及管理審查理解與查證。
  • 範圍變更應觸發風險評鑑、SoA、資產清冊、供應商管理、PIMS控制、AI風險評估、稽核方案及文件化資訊之連動更新。
  • 範圍至少每年審查一次，並於重大變更或重大事件後即時審查。

必須納入 法規、合約、客戶或監理明確要求納入；直接處理關鍵資訊資產或PII；對機密性、完整性、可用性有重大影響；支援已納入範圍之核心產品或服務；涉及外部驗證範圍。 法規合約要求清冊、關注方需求、資產清冊、風險登錄、範圍界定表。
通常納入 支援範圍內流程之IT、雲端、資料中心、AI服務、供應商管理、資安事件、存取控制、備份、日誌、風險管理、文件化資訊及稽核活動。 流程矩陣、資產清冊、供應商評估、控制矩陣。
視風險判定納入 間接支援流程、低敏感資料、低影響供應商、非關鍵SaaS、試驗性AI工具、局部使用之GHG/CO2資料或非核心場域。 風險評估、資料分類、供應商風險、範圍補充表。
可排除 與範圍內資訊資產、PII、服務、合約、法規、控制措施或外部驗證無關；排除不會影響管理系統達成預期結果且有充分理由。 排除理由、風險評估、合規確認、管理核准。
不得排除 排除會導致法規或合約不符合、PII責任不明、AI服務風險未受控、重大供應商未納管、SoA不完整、驗證範圍誤導或管理系統無法有效運作。 合規判定、SoA、風險評估與治理委員會決議。

10. 作業程序

程序步驟 作業要求 責任角色 輸出/紀錄
10.1 啟動範圍界定 ISMS管理代表應於首次建立、年度審查、重大變更、驗證申請、併購、組織重整、重大供應商變更、AI服務導入、PII處理變更、GHG/CO2資料治理變更或重大事件後啟動範圍界定。 ISMS管理代表 / CISO 範圍界定啟動紀錄、評估計畫。
10.2 蒐集範圍輸入 蒐集組織全景、關注方需求、法規合約、產品服務、流程、資訊資產、PII處理、AI系統、雲端服務、供應商、GHG/CO2資料及既有風險資料。 範圍管理負責人 / 各資料Owner 範圍輸入資料包。
10.3 識別組織與場所邊界 確認納入之組織單位、地點、資料中心、遠端工作、備援場所、雲端區域及外部服務地點。 ISMS管理代表 / IT / 場所Owner 組織與場所邊界清單。
10.4 識別流程與服務邊界 確認納入範圍之產品、服務、流程、活動、支援流程、委外活動、PII處理活動及AI/碳資料流程。 流程Owner / ISMS管理代表 流程與服務範圍清單。
10.5 識別資訊資產與資料邊界 確認納入之資訊資產、系統、資料庫、資料集、AI模型、Prompt、RAG知識庫、日誌、備份、GHG/CO2資料及文件化資訊。 資產Owner / Data Owner 資訊資產與資料邊界。
10.6 識別外部依賴 確認供應商、雲端、外包、AI服務、資料中心、碳平台、查證機構、顧問與第四方依賴是否納入。 採購 / 供應商管理 供應商與外部依賴清單。
10.7 界定PIMS範圍 依PII處理目的、PII類別、資料主體、PII角色、第三方處理、跨境傳輸、資料主體權利及隱私風險界定PIMS範圍。 DPO / PIMS管理代表 PIMS範圍判定、隱私風險評估輸入。
10.8 界定AI治理與安全範圍 依組織AI角色、AI系統、AI服務、模型、資料集、Prompt/RAG、雲端、供應商及輸出用途界定AI相關ISMS/PIMS範圍。 AI治理負責人 AI範圍判定、AI風險評估輸入。
10.9 判定GHG/CO2資料範圍 依GHG與碳資料治理觀點，確認GHG/CO2資料、查證證據、產品碳足跡或碳中和聲明資料是否納入ISMS/PIMS。 GHG資料治理負責人 GHG/CO2資料範圍判定、碳證據清冊更新。
10.10 分析排除事項 任何排除均須確認其不影響ISMS/PIMS達成預期結果、不違反法規合約、不使驗證範圍誤導，並保存排除理由及核准紀錄。 ISMS管理代表 / 風險管理 / 法務 排除事項紀錄、風險與合規確認。
10.11 形成範圍聲明 將納入範圍、邊界、適用項目、排除項目、外部依賴、PII角色、AI角色、GHG/CO2資料與驗證範圍寫入範圍聲明書。 ISMS管理代表 ISMS範圍聲明書。
10.12 審查與核准 由ISMS/PIMS管理代表、CISO、DPO、AI治理、GHG及相關流程負責人審查，提交資訊安全治理委員會或最高管理階層核准。 最高管理階層 / 治理委員會 核准紀錄、管理決議。
10.13 更新相關文件 依範圍界定結果更新資產清冊、風險登錄、SoA、供應商評估、PII清冊、AI風險評估、外部文件清冊、稽核方案及管理審查輸入。 文件Owner / 流程Owner 文件制修訂申請、連動更新紀錄。
10.14 溝通與發布 將核准範圍傳達至相關人員、流程負責人、稽核員、供應商管理、驗證機構及需要知悉之關注方。 ISMS管理代表 / 文件管制 發布紀錄、溝通紀錄。
10.15 監督與持續改善 至少每年審查一次範圍，並以稽核、事件、管理審查、風險評估、法規變更及業務變更作為持續改善輸入。 ISMS管理代表 / 稽核主管 範圍審查紀錄、改善追蹤。

10.4 PIMS範圍界定要求

PII處理目的 定義每項處理活動之目的、合法性、資料主體、資料類別、保存期限及處理方法。 PII處理活動資料、隱私風險評估。

AI角色 情境 範圍處理要求

10.6 GHG/CO2資料與氣候相關範圍判定要求

範圍項目 處理要求

10.7 排除事項管理

排除事項應說明內容 最低要求
排除項目之名稱、類型、地點、流程、系統或服務。 應可被稽核員理解並可追溯至範圍界定表。
排除原因及其與ISMS/PIMS範圍之關係。 不得以便利性或缺乏資源作為唯一排除理由。
排除後是否仍能符合法規、合約、標準及客戶要求。 需法務或合規審查。
排除後是否會造成重大資訊安全、隱私、AI治理、GHG/CO2資料或供應鏈風險。 需執行風險評估，必要時提交剩餘風險接受。
是否仍需由其他管理系統或控制措施管理。 需明確指定替代控制或管理責任。
審查人員、核准者及核准日期。 重大排除需提交最高管理階層或資訊安全治理委員會。
