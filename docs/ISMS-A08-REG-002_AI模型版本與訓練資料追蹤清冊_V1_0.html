1. 清冊目的

本清冊用於建立組織AI模型版本、訓練資料、驗證資料、測試資料、微調資料、Prompt模板、RAG知識庫、向量資料庫、模型部署狀態、供應商來源、資料權利、資訊安全風險、隱私風險、模型變更與退役證據之完整追蹤機制。

本文件支援組織在AI系統生命週期中維持模型與資料之可識別性、可追溯性、完整性、授權合規性、風險可控性與稽核可驗證性，並作為AI治理、ISMS風險管理、變更管理、事件調查、供應商管理、隱私保護、資料治理、模型監控及管理審查之重要證據來源。

2. 登錄原則

  • 所有正式、試行、POC、內部測試、客戶專案、供應商代管或雲端API形式之AI模型，只要會處理組織資訊、客戶資料、PII、商業機密、程式碼、Prompt、訓練資料或決策支援資料，均應登錄。
  • 每一個模型版本應可追溯至其來源模型、訓練資料集、驗證資料集、測試資料集、資料處理方法、模型參數、評測結果、核准紀錄與部署環境。
  • 訓練資料、微調資料、RAG資料、Prompt資料與Embedding資料應明確記錄資料來源、權利狀態、分類等級、PII狀態、跨境處理、保存期限與刪除要求。
  • 高風險AI模型、涉及自動化決策、處理PII、連接外部服務、支援資安監控、客戶服務、財務、法遵、人資或關鍵營運流程之模型，應提高審查、監控與證據保存要求。
  • 模型版本變更、重新訓練、微調、參數更新、Prompt更新、RAG資料更新、供應商模型升級或API版本替換，均應保留變更前後差異、測試結果、風險評估與核准證據。

3. 名詞與定義

名詞 定義
AI模型 透過機器學習、深度學習、統計方法、規則與資料驅動方法產生輸出、分類、預測、生成內容、建議或決策支援之模型。
模型版本 特定時間點可識別之模型狀態，包括基礎模型、架構、參數、權重、訓練資料、微調資料、Prompt模板、部署設定及評測結果。
基礎模型 由組織自行開發、供應商提供、開源社群發布或雲端平台提供之原始模型或預訓練模型。
訓練資料 用於訓練、調整、微調或強化模型能力之資料集，可能包括結構化資料、非結構化文件、程式碼、影像、語音、標註資料或合成資料。
驗證資料 模型開發期間用於調整參數、比較模型或選擇版本之資料。
測試資料 模型定版或上線前用於確認性能、安全性、偏差、穩定性與控制有效性之資料。
微調資料 用於Fine-tuning、Instruction tuning、RLHF/RLAIF或領域適配之資料。
Prompt資產 可重複使用、具業務價值或控制意義之Prompt模板、System Prompt、工具調用指令、Agent設定、Few-shot範例或防護提示。
RAG資料 供檢索增強生成使用之文件、資料庫、索引、向量資料、知識庫與Embedding資料。
模型漂移 模型因資料分布、使用情境、外部環境、使用者行為或供應商版本變更而導致性能、風險或輸出特性發生變化。
資料血緣 資料自來源、收集、清理、標註、轉換、訓練、驗證、測試、部署、保存至銷毀之可追溯關係。

4. 角色與責任

Data Steward / Data Engineer 維護資料血緣、資料處理、資料清理、標註、去識別、品質檢查與資料集版本。 資料血緣紀錄、ETL紀錄、品質檢查結果。
DevSecOps / MLOps 維護模型儲存庫、CI/CD、部署環境、存取控制、日誌、監控、回滾及版本標籤。 MLOps紀錄、部署日誌、存取紀錄。
DPO / PIMS負責人 審查涉及PII、敏感資料、自動化決策、跨境處理或資料主體權利之AI資料處理。 DPIA、DPA、PII處理紀錄。
法務 / 法遵 審查資料來源權利、授權條款、開源限制、模型供應商條款、監管要求與合約義務。 授權審查、合約條款、法規遵循紀錄。
供應商管理 確認AI供應商、模型供應商、標註供應商、雲端平台及第四方之安全與合約要求。 供應商評估、SLA、DPA、第四方清冊。
內部稽核 查核本清冊之完整性、正確性、更新頻率、證據保存與控制有效性。 稽核工作底稿、不符合報告、改善追蹤。
