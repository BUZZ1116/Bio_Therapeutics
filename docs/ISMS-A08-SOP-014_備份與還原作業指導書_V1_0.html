1. 作業目的

本作業指導書規範備份與還原之策略、範圍、頻率、保留、加密、不可變性、異地保存、存取控制、監控、測試、事件復原、災難復原、資料刪除與稽核要求，確保組織在資料損毀、誤刪、勒索軟體、系統故障、供應商中斷、雲端區域事故、資安事件、自然災害或人為錯誤時，能於核定之RTO/RPO內恢復關鍵服務與資料。

本文件亦確保備份資料本身受到與原資料相當或更高等級之保護，避免備份成為未授權存取、資料外洩、勒索軟體加密、保留期限違反、隱私刪除失敗或查證證據缺失之風險來源。

2. 作業原則

  • 所有重要資訊資產、關鍵系統、關鍵資料、設定、日誌、證據與支援營運持續之資料，應依業務影響分析、資料分類與風險評估結果定義備份與還原要求。
  • 備份策略應符合RTO、RPO、資料保存期限、法規、合約、客戶承諾、隱私、AI治理及GHG/ESG查證要求。
  • 備份資料應啟用加密、存取控制、日誌監控與完整性檢查；高風險與關鍵資料應具不可變備份、離線備份或隔離備份能力。
  • 備份成功不等於復原成功；關鍵系統與資料應定期進行還原測試、災難復原演練與證據保存。
  • 備份與還原權限應採最小權限與職務分離，備份管理員不得任意讀取業務資料；還原作業應有申請、核准、驗證及紀錄。
  • 勒索軟體、資料破壞或惡意刪除情境下，應優先保護備份完整性，避免將受污染資料覆蓋乾淨備份。

3. 名詞與定義

名詞 定義
備份 將資料、系統、設定、映像、資料庫、日誌或其他資訊複製至受控位置，以支援資料復原、服務恢復、證據保存或營運持續。
還原 將備份資料、系統、設定或服務恢復至指定時間點、指定環境或指定狀態之作業。
RTO Recovery Time Objective，復原時間目標，即服務中斷後可接受之最長復原時間。
RPO Recovery Point Objective，復原點目標，即資料可接受之最大損失時間範圍。
不可變備份 在保留期間內不得被修改、刪除或覆寫之備份，通常用於防勒索軟體與證據保護。
離線備份 與生產環境邏輯或實體隔離之備份，避免遭線上攻擊、帳號濫用或勒索軟體同步加密。
異地備份 保存於不同地理位置、資料中心、雲端區域或隔離環境之備份，用於災害復原。
完整備份 備份完整資料集或系統映像。
增量備份 僅備份自上次備份後異動之資料。
差異備份 備份自上次完整備份後異動之資料。
還原測試 定期驗證備份是否可讀取、可還原、完整且可於RTO/RPO內達成預期復原能力。
乾淨還原點 經確認未受惡意軟體、資料破壞或錯誤變更污染之可用備份版本。

7. 備份作業流程

階段 作業要求 責任角色 輸出證據
1. 備份需求定義 依資產清冊、資料分類、BIA、RTO/RPO、法規、合約與風險評估定義備份需求。 System Owner / Data Owner / BCMS Owner 備份需求表、ICT備妥性評估。
2. 備份方案設計 決定備份頻率、類型、保留、加密、異地、不可變、存取、監控與復原方式。 Backup Owner / Security Architect 備份設計與核准紀錄。
3. 備份設定 於備份平台、雲端服務、SaaS或資料庫中設定備份任務與保護策略。 Backup Admin / Cloud / DB Owner 備份任務設定。
4. 初次備份驗證 完成初次備份後確認成功、資料量合理、加密、保存位置與權限。 Backup Owner 初次備份驗證紀錄。
5. 例行監控 每日或依系統重要性監控備份成功率、錯誤、容量、保留、不可變狀態與告警。 Backup Owner / SOC 備份監控報表。
6. 失敗處理 備份失敗、逾期、容量不足或不可變失效時，依優先級修復並升級。 Backup Owner / System Owner 失敗處理工單。
7. 還原測試 依測試計畫定期執行檔案、資料庫、系統、雲端、SaaS或災難復原測試。 Backup Owner / System Owner 還原測試紀錄。
8. 變更與退場 系統變更、資料分類變更、退場或保留期限變更時更新備份策略。 System Owner / Backup Owner 變更紀錄、清冊更新。

8. 備份保存、加密與不可變要求

控制項目 最低要求 高風險加強要求
備份加密 備份資料傳輸與儲存應加密，金鑰受KMS、HSM或Secrets管理保護。 高機密、PII、客戶資料與關鍵備份須使用獨立金鑰與嚴格存取。
不可變備份 關鍵系統、勒索風險高資料與事件證據應啟用不可變或WORM保護。 Tier 0/Tier 1需具不可變、隔離或離線備份。
異地保存 關鍵備份應保存於不同區域、資料中心、雲端帳號或隔離位置。 需符合災難復原與地區風險要求。
離線或隔離副本 勒索軟體高風險系統應具離線、隔離或獨立權限域備份。 備份管理帳號與生產管理帳號分離。
保留期限 依業務、法規、合約、隱私、稽核、GHG查證與事件保存要求設定。 保留期限與刪除權利衝突時須DPO/法務審查。
存取控制 備份管理、還原與讀取權限應分離，採最小權限、MFA與審計。 高風險還原需雙人核准或PAM。
完整性檢查 定期檢查備份可讀性、雜湊、校驗、版本與還原可用性。 事件證據與GHG底稿需保留完整性證明。
防刪除控制 備份刪除需核准、延遲刪除或刪除保護。 管理員不得單人刪除所有備份副本。

7. 後續處理 更新事件、變更、風險或問題紀錄，分析原因並必要時改善備份策略。 Backup Owner / ISMS管理代表 復原報告、CAPA。

14. 備份安全監控與告警

未授權還原 非核准還原、異常下載、跨環境還原或資料大量匯出。 立即調查並限制權限。

17. 例外管理

例外情境 最低要求 核准層級 期限與重評
無法符合RTO/RPO 需業務影響分析、風險評估、補償控制、改善計畫與管理階層確認。 Business Owner / CISO / BCMS Owner 至少每季重評。
無法啟用不可變備份 需說明技術限制，提供隔離、離線或權限分離等替代控制。 CISO / Backup Owner 最長90日，高風險每30日追蹤。
無法加密備份 原則不允許；若因技術限制，需限制資料分類、隔離保存與改善時程。 CISO / Data Owner 最長90日。
無法定期還原測試 需說明限制，採抽樣、替代環境、部分復原或供應商證據。 BCMS Owner / CISO 下一期必須補測或重評。
SaaS無完整還原能力 需評估第三方備份、資料匯出、供應商SLA與退場方案。 SaaS Owner / Supplier Management / CISO 續約前重評。
資料刪除與備份保留衝突 需DPO、Legal與Data Owner審查保留、刪除、封存或不可識別化方案。 DPO / Legal / CISO 依案件重評。
