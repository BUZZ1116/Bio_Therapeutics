1. 管理意圖

管理審查是最高管理階層確認ISMS是否仍然適合、充分、有效並與組織策略方向一致的正式治理活動，不是例行會議紀錄。審查應以完整、可信、可追溯的輸入資料為基礎，作成資源、改善、變更、風險、目標、政策及管理系統整合之決策。

本程序要求管理審查輸入必須能反映ISMS實際運作狀態，輸出必須能被追蹤到行動Owner、期限、資源、文件更新與有效性確認。若管理審查只記錄『無異常』或『持續改善』但沒有資料來源、趨勢、判定與決策，視為證據不足。

重大事項需轉年度或事件型管理審查。
事件型管理審查 重大資訊安全事件、申訴或通報、重大不符合事項發現、重大變更、供應鏈中斷、重大風險、法規/關注方、法規及合約要求、氣候事件或資料可信度重大疑慮。 針對事件形成專項決策、資源、風險接受、CAPA、變更或關注方溝通。
整合管理系統審查 ISMS與ISMS、PIMS、AIMS、BCMS、GHG/CO2資料治理共用議題、風險、稽核、資源或改善時。 確認跨系統政策、風險、文件、稽核、管理審查與改善是否一致。

步驟 輸入資料 活動內容 輸出 / 客觀證據 活動參考文件 負責人員
1. 建立管理審查計畫與議程 年度管理審查計畫、事件型觸發、前次審查紀錄、治理會議議題。
  • 確認年度或事件型管理審查目的、範圍、主席、參與者、議程、提交期限與資料Owner。
  • 事件型觸發包含重大變更、重大風險、重大資訊安全事件、申訴或通報、重大不符合事項發現、供應鏈中斷、氣候相關事件或外部要求。
  • 若輸入資料無法於期限內完成，應先決定補件期限或調整審查日期。
 管理審查計畫、議程、資料提交清單與會議通知。

2. 收集管理審查輸入 9.3.2輸入清單、KPI、關注方需求與資訊安全承諾達成、稽核、CAPA、風險、供應商、資源、變更與改善資料。
  • 依9.3.2逐項收集資料，不得只收單一績效報表。
  • 每一項輸入需由資料Owner確認資料期間、資料來源、限制、趨勢、異常與建議決策。
  • 氣候變遷、AI、資訊安全、隱私、供應鏈與GHG/CO2資料若影響ISMS，應納入對應輸入項目。

3. 確認輸入完整性與資料資訊安全 管理審查輸入彙整表、原始資料、趨勢圖、量測描述子、資料限制與補件資料。
  • 確認每一項輸入是否有資料來源、期間、責任人、趨勢、結論與決策需求。
  • 資料不足、不可比較、方法變更或證據缺漏時，應標示限制並決定是否可用於決策。
  • 若缺漏會影響ISMS有效性判定，應要求補件或將資料資訊安全問題列為管理審查議題。
 資料資訊安全結論、補件要求、限制使用說明與會議前資料包。
  • ISMS-091-FRM-003 ISMS量測描述子設定表（互動式）
  • ISMS-091-FRM-004 KPI/KRI資料收集與有效性查核表（互動式）
  • ISMS-091-FRM-005 量測分析模型與解釋紀錄表（互動式）
  • ISMS-093-FRM-001 管理審查輸入彙整表（互動式）

 管理系統代表 / Reviewer
4. 執行管理審查 完整輸入資料包、前次行動狀態、重大風險、資源需求與改善提案。
  • 最高管理階層審查ISMS是否持續適合、充分、有效，且與組織策略方向一致。
  • 逐項審查關注方、目標、流程、資訊、資產、系統與服務、CAPA、量測、稽核、供應商、資源、風險與改善。
  • 對重大議題應作成明確決策，不應只記錄『持續追蹤』而無責任人、期限或判定準則。
 管理審查討論紀錄、決策摘要、保留/變更/升級判定。
  • ISMS-093-FRM-001 管理審查輸入彙整表（互動式）
  • ISMS-061-REG-001 資訊安全風險登錄表（互動式）
  • ISMS-103-FRM-001 改善提案表（互動式）
  • ISMS-093-REC-001 管理審查會議紀錄（互動式）
 最高管理階層
5. 形成管理審查輸出 審查結論、決策需求、改善機會、ISMS變更、資源需求與風險接受事項。
  • 輸出至少應涵蓋改善機會、ISMS變更需求及資源需求。
  • 必要時同步形成資訊安全目標修訂、風險處理、剩餘風險接受、變更申請、CAPA、供應商再評估或專項稽核決定。
  • 每項輸出需有Owner、期限、資源、預期結果、有效性確認方式與升級條件。
 核准決議、行動事項、資源承諾、變更/CAPA/改善/風險連結。
  • ISMS-093-REC-001 管理審查會議紀錄（互動式）
  • ISMS-061-FRM-004 剩餘風險接受單（互動式）
  • ISMS-063-FRM-001 ISMS變更申請表（互動式）
  • ISMS-103-REC-001 改善追蹤報告（互動式）
 最高管理階層 / 管理系統代表
6. 溝通輸出並更新文件化資訊 管理審查決議、行動事項、受影響流程、文件、風險、目標、供應商、能力與溝通需求。
  • 依資訊分級與溝通矩陣通知相關流程Owner、Risk owner、資料Owner、供應商管理Owner或其他利益相關方。
  • 需要修訂文件、流程矩陣、資訊安全目標、風險登錄、供應商清冊或能力文件時，應依文件化資訊管制程序辦理。
  • 涉及關注方、法規、供應商或外部聲明時，應先確認核准權限與對外溝通內容。
 溝通紀錄、文件修訂申請、更新後風險/目標/流程/供應商文件。
  • ISMS-093-REC-001 管理審查會議紀錄（互動式）
  • ISMS-074-FRM-001 資訊安全溝通矩陣（互動式）
 管理系統代表 / 文件管理者
7. 追蹤行動關閉與有效性 管理審查輸出行動、CAPA、變更、資源取得、改善追蹤、KPI/KRI與完成證據。
  • 依期限追蹤每項輸出行動，不得只在下次會議才第一次確認。
  • 完成後應確認有效性，例如KPI改善、風險降低、CAPA有效、資源到位、文件更新或關注方回饋改善。
  • 逾期、無效、資源不足或重複未決事項需升級最高管理階層或治理機構。
 行動追蹤紀錄、有效性確認、逾期升級紀錄與下次管理審查輸入。
  • ISMS-102-REC-001 CAPA登錄表（互動式）
  • ISMS-103-REC-001 改善追蹤報告（互動式）
  • ISMS-063-REC-003 ISMS變更追蹤紀錄（互動式）
  • ISMS-093-REC-001 管理審查會議紀錄（互動式）

10. 監督、量測與有效性評估

指標 判定方式 管理用途
管理審查輸入完整率 已完成並經資料Owner確認之9.3.2輸入項目數 / 應提交輸入項目數。目標：100%。 確認最高管理階層是否取得足夠決策資訊。
管理審查輸入準時率 管理審查日前依規定期限提交並審查完成之輸入資料比例。 確認流程Owner與資料Owner是否能準時提供治理資料。
管理審查輸出行動準時關閉率 於期限內完成並通過有效性確認之管理審查行動數 / 到期行動數。 確認管理審查不是會議紀錄，而是改善與資源決策閉環。
重複未決事項數 連續兩次管理審查仍未解決、未升級或無有效處置之事項數。目標：0。 用來判斷最高管理階層決策與資源配置是否有效。
事件型管理審查啟動準時率 重大事件發生後於規定期限內完成事件型管理審查或治理決策之比例。 確認重大變更、風險、資訊安全事件、申訴或通報、供應鏈或氣候事件能被及時處理。
