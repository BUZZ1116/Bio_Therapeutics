1. 表單目的

本表用於依據組織全景與內外部議題管理程序，系統化識別、分析、評估與追蹤外部環境中可能影響ISMS、PIMS、AI治理、GHG/CO2資料治理及營運韌性之議題。外部議題包含法規監管、客戶合約、威脅情資、供應鏈、雲端服務、AI技術與監管趨勢、氣候變遷、能源、社會期待、產業標準、驗證查證要求與市場競爭等。

本表應將外部議題轉換為法規合約要求、ISMS/PIMS範圍輸入、風險評鑑、AI/PII/GHG/氣候專項評估、供應商風險評估、SoA與控制措施、KPI/KRI、稽核方案、管理審查與持續改善之實際輸入。

權責、資源與溝通 外部議題若需管理階層決策、責任分派、訓練、資源或外部溝通，應使用權責、資源與溝通文件管理。 RACI、資源需求、溝通計畫、管理承諾證據。

文件保存、監督、稽核、管理審查與改善 本表輸出應依文件化資訊管制保存；重大外部議題應納入KPI/KRI、稽核方案、管理審查、CAPA與持續改善。 受控紀錄、監測指標、稽核輸入、管理審查與改善閉環。

3. 填寫說明與判定規則

欄位/項目 填寫要求 判定原則
議題編號 使用格式 EXT-ISS-YYYY-NNN，例如 EXT-ISS-2026-001。 每一項外部議題應唯一編號，不得重複。
議題來源 可為法規公告、客戶合約、威脅情資、供應商通報、雲端服務公告、AI監管趨勢、氣候事件、GHG查證要求、媒體或產業報告。 需可追溯至來源連結、文件、通知、會議紀錄、合約條款、威脅情資或公告。
議題類別 依PESTLE分類，並可標示資安、PII、AI、GHG/CO2、氣候、雲端、供應鏈、合規、營運持續、聲譽或財務影響。 同一議題可有多個標籤，但應指定主要類別與Owner。
議題描述 以具體外部事實描述議題，包含來源、變化、要求、趨勢、事件、影響區域與生效日期。 不得僅填寫抽象詞；應能支持後續風險與合規判定。
影響面向 應評估對CIA、AI、PII、GHG/CO2、氣候、供應鏈、雲端、法規合約、營運持續、聲譽與資源之影響。 若任一面向為高，應列為重大議題並轉入風險或管理審查。
重大性等級 依高、中、低評估。 高：必須轉風險、法規清冊、管理審查或CAPA；中：追蹤並視需要轉風險；低：保存並定期重評。
處理方式 可選擇監測、更新法規清冊、轉風險、更新範圍、供應商評估、控制補強、稽核抽樣、CAPA或管理審查。 處理方式需與重大性、合規義務與實際影響一致。
議題擁有人 指定負責追蹤之外部議題Owner，例如Compliance Owner、Supplier Owner、AI Governance Owner、DPO、GHG Data Owner、Cloud Owner。 需可對應RACI或管理責任。
