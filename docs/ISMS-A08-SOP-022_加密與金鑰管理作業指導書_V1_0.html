1. 作業目的

本作業指導書規範組織加密與金鑰管理之原則、角色責任、演算法選用、金鑰生命週期、憑證管理、KMS/HSM、雲端與應用程式金鑰、Secrets保護、金鑰備份與復原、輪替、撤銷、銷毀、事件處理、例外管理與稽核證據要求，確保資訊在傳輸、儲存、處理、備份、交換、AI推論、模型訓練、RAG檢索與供應商服務中受到適當保護。

本文件旨在防止因弱加密、錯誤金鑰管理、硬編碼Secrets、憑證逾期、金鑰外洩、權限過寬、供應商代管不透明、加密例外未核准或銷毀不完全而造成資料外洩、未授權存取、不可否認性不足、服務中斷、法規違反及客戶信任損害。

2. 作業原則

  • 加密控制應依資料分類、風險評估、法規合約要求、系統重要性、威脅情境及營運持續需求設計，不得以單一預設機制取代風險判斷。
  • 金鑰、憑證、Token、API Key、私鑰與Secrets不得硬編碼於程式碼、文件、Repo、容器映像、CI/CD設定、Notebook、日誌、Prompt或聊天工具中。
  • 生產、預備、測試、開發、沙箱、AI/MLOps與供應商環境應使用不同金鑰與Secrets，不得跨環境混用。
  • 金鑰生命週期應包含產生、登錄、分發、啟用、使用、保存、備份、輪替、停用、撤銷、封存、銷毀與稽核，並指定Owner與責任。
  • 特權金鑰、高機密資料金鑰、根金鑰、憑證私鑰與HSM/KMS管理權限應依職務分離、最小權限、MFA、PAM/JIT與雙人核准原則管理。
  • 加密不得取代其他安全控制；仍需搭配身份驗證、授權、日誌監控、DLP、備份、網路隔離、弱點管理與事件回應。

3. 名詞與定義

名詞 定義
加密 使用密碼學方法保護資料機密性、完整性、真實性或不可否認性之控制措施。
金鑰 用於加密、解密、簽章、驗章、MAC、Token簽署或建立安全通道之秘密或公開密碼材料。
KMS Key Management Service，金鑰管理服務，提供金鑰建立、保存、授權、輪替、審計與銷毀能力。
HSM Hardware Security Module，硬體安全模組，用於保護高價值金鑰並提供硬體層級密碼運算。
DEK Data Encryption Key，資料加密金鑰，用於加密資料內容。
KEK Key Encryption Key，金鑰加密金鑰，用於加密或包裝其他金鑰。
Secrets 密碼、API Key、Token、私鑰、憑證、Webhook Secret、資料庫密碼、AI API Key或其他可用於取得存取權之秘密資訊。
金鑰輪替 依週期、事件、風險或人員異動更換金鑰或憑證之活動。
金鑰撤銷 因外洩、疑似外洩、誤用、停用或退場而使金鑰不再可信或不可使用之作業。
Bring Your Own Key BYOK，組織自行產生或控制金鑰並提供給雲端或供應商使用之模式。
Hold Your Own Key HYOK，組織保有金鑰並限制供應商或雲端服務直接取得明文金鑰之模式。
Envelope Encryption 信封式加密，以DEK加密資料，再以KEK保護DEK之加密架構。

5. 加密適用場景與最低要求

場景 最低加密要求 補充控制 證據
資料傳輸 使用TLS或等效安全通道，禁止使用明文傳輸敏感資料。 憑證有效性、TLS組態、HSTS、mTLS視風險使用。 TLS掃描、組態截圖。
資料儲存 機密、PII、客戶資料、高機密與重要系統資料應加密儲存。 KMS/HSM、資料庫TDE、欄位加密、存取控管。 KMS設定、DB設定。
備份與快照 備份、快照、匯出檔與離線副本應依資料分類加密。 不可變備份、分離金鑰、復原測試。 備份設定、還原紀錄。
資料庫 依風險啟用TDE、欄位加密、連線加密、金鑰輪替與審計。 高敏感欄位優先欄位級或應用層加密。 DB設定與測試。
API與Webhook Token、簽章、mTLS、Webhook Secret或HMAC視風險採用。 Replay Protection、Timestamp、Nonce、Rate Limit。 API測試紀錄。
CI/CD與Artifact Pipeline Secrets、簽章金鑰、部署Token與Artifact應受控。 Artifact簽章、SBOM、Secrets掃描。 Pipeline紀錄。
容器與Kubernetes Kubernetes Secrets應加密，映像、Registry與部署Secret需受控。 External Secrets、KMS Provider、RBAC。 K8s設定。
Mobile與端點 本機敏感資料應使用平台安全儲存與裝置加密。 Keychain/Keystore、MDM、憑證保護。 Mobile測試報告。
AI與RAG AI API Key、模型、RAG資料源、向量庫與Prompt資產應加密與分權管理。 資料不訓練、權限繼承、輸入輸出控管。 AI治理紀錄。
供應商與SaaS 供應商應提供傳輸、儲存、備份、金鑰管理與事件通報證據。 BYOK/HYOK視風險採用。 供應商評估。

6. 核准加密演算法與禁止事項

類別 核准要求 禁止或限制事項
對稱加密 應使用組織核准之強度與模式，例如AES-256-GCM或等效核准演算法。 禁止使用DES、3DES、RC4、ECB模式或自行設計演算法。
非對稱加密 應使用足夠強度之RSA、ECC或等效演算法，依組織標準選擇金鑰長度。 禁止使用過短金鑰、弱參數或未核准曲線。
Hash 密碼不得使用一般Hash；完整性檢查應使用SHA-256或更強等級。 禁止MD5、SHA-1用於安全完整性或簽章目的。
密碼雜湊 密碼應使用Argon2、bcrypt、scrypt、PBKDF2或組織核准方法，搭配Salt與適當參數。 禁止明文、Base64、快速Hash或可逆加密保存密碼。
TLS 應使用核准TLS版本與Cipher Suite，停用弱協定與弱套件。 禁止SSL、早期TLS或匿名/弱Cipher。
數位簽章 應使用核准簽章演算法，保護私鑰並驗證憑證鏈。 禁止共用簽章私鑰或將私鑰存放於Repo。
隨機數 金鑰、IV、Nonce、Token、Session ID應使用密碼學安全隨機數。 禁止使用一般Random或可預測種子。
AI與Prompt安全 AI API Key與模型存取Token應使用Secrets Manager管理並限制Scope。 禁止將API Key輸入Prompt或保存於Notebook明文。

7. 金鑰生命週期管理流程

階段 作業要求 責任角色 輸出證據
1. 需求提出 定義金鑰用途、資料分類、系統、環境、演算法、保存期限、Owner與風險等級。 System Owner / Data Owner 金鑰申請紀錄。
2. 安全設計 確認KMS/HSM、DEK/KEK、權限、輪替、備份、審計、災難復原與退場設計。 Cryptography Owner / Cloud Security 金鑰設計紀錄。
3. 產生 金鑰應於核准KMS/HSM或安全工具中產生，使用密碼學安全亂數。 Key Management Owner 金鑰建立紀錄。
4. 登錄 登錄金鑰ID、用途、Owner、資料分類、環境、權限、輪替日、到期日與依賴系統。 Key Management Owner 金鑰清冊。
5. 分發與啟用 金鑰分發應透過安全通道與授權流程，避免明文曝露。 IT / DevSecOps / Cloud Owner 啟用紀錄。
6. 使用與監控 金鑰使用需限制權限、記錄操作、監控異常、建立告警。 SOC / System Owner KMS日誌、SIEM告警。
7. 輪替 依週期、風險、事件、供應商變更、人員離職或技術要求輪替。 Key Management Owner 輪替紀錄。
8. 撤銷與停用 外洩、疑似外洩、用途結束或退場時應撤銷、停用或移除授權。 CISO / Key Owner 撤銷紀錄。
9. 銷毀與封存 到期或退場金鑰應依資料保留與法規要求安全銷毀或封存。 Key Management Owner 銷毀證明。
10. 稽核與檢討 定期審查金鑰清冊、權限、輪替、例外、事件與控制有效性。 Internal Audit / ISMS代表 審查與稽核紀錄。

9. 金鑰權限與職務分離要求

控制項目 最低要求 高風險加強要求
Owner指定 每把金鑰應指定業務Owner、技術Owner與安全Owner。 高機密或關鍵系統金鑰需CISO核准Owner變更。
最小權限 僅授予必要角色使用或管理金鑰，避免萬用管理權限。 使用Key Policy、IAM條件、PAM/JIT與定期審查。
職務分離 金鑰管理、應用開發、資料存取與稽核角色應適度分離。 根金鑰、KEK與HSM管理需雙人核准。
管理操作 建立、刪除、撤銷、Key Policy變更、匯入匯出需記錄與核准。 高風險操作需MFA、PAM與Session Recording。
人員異動 Owner、管理員、供應商或高權限人員異動時需審查金鑰權限。 必要時輪替相關金鑰與Secrets。
供應商存取 供應商不得直接取得明文金鑰，必要時使用受控KMS或臨時權限。 正式環境需PAM/JIT與全程記錄。
Break-glass 緊急金鑰操作需具核准、時限、日誌與事後審查。 使用後重新評估與輪替。

11. 應用程式加密與安全編碼要求

項目 安全要求 驗證方式
應用層加密 高敏感欄位應評估應用層或欄位級加密，不僅依賴磁碟或資料庫加密。 架構審查、Code Review。
金鑰取得 應用程式應透過KMS SDK、Secrets Manager或受控身份取得金鑰，不得硬編碼。 Secrets掃描、程式碼審查。
IV / Nonce 加密模式所需IV或Nonce應唯一、不可預測並依演算法要求處理。 SAST、人工審查。
錯誤處理 加密失敗、解密失敗、簽章驗證失敗不得回傳敏感細節。 測試與Code Review。
Token簽章 JWT或其他Token應驗證Issuer、Audience、期限、簽章與撤銷策略。 API安全測試。
資料遮罩 解密後資料顯示、日誌、報表、匯出與AI輸入需依分類遮罩或最小化。 測試案例。
密碼保存 不得自行設計密碼保存方式，需使用核准密碼雜湊與參數。 Code Review、SAST。
AI程式碼 AI/RAG/Agent程式不得將Secrets寫入Prompt、Notebook、向量資料或模型輸出。 AI安全測試、DLP。

12. 雲端KMS、HSM與供應商代管金鑰

控制項目 最低要求 證據
KMS啟用 正式與高風險雲端資源應使用KMS或等效金鑰管理服務。 KMS設定。
Key Policy Key Policy應遵循最小權限，限制管理、使用、解密與刪除權限。 Key Policy審查。
BYOK/HYOK 高機密、法規、客戶或合約要求時應評估BYOK/HYOK。 架構與風險評估。
HSM使用 根金鑰、簽章金鑰、支付或高價值金鑰應評估HSM或受認證硬體保護。 HSM設定或評估紀錄。
供應商KMS SaaS或外部服務若代管金鑰，需取得加密、輪替、隔離、刪除與事件通報證據。 供應商評估。
多租戶隔離 供應商或雲端服務需證明金鑰與資料具租戶隔離。 SOC報告、技術說明。
KMS日誌 KMS管理與使用事件應啟用日誌並接入監控或可供稽核。 KMS Audit Log。
刪除保護 高風險金鑰應啟用刪除保護、延遲刪除、雙人核准或等效控制。 設定證據。

13. AI、RAG、MLOps與資料科學加密要求

場景 加密與金鑰要求 證據
AI API Key AI API Key應分環境管理、限制Scope、用量、Owner、輪替與監控。 AI Key清冊、用量報告。
模型檔與權重 模型權重、微調模型、Embedding模型與模型Artifact應依資料分類加密與控管。 模型Registry設定。

19. 加密例外與風險接受

例外情境 最低要求 核准層級 期限與重評
無法加密特定資料 需說明原因、資料範圍、補償控制、殘餘風險、期限與改善計畫。 CISO / Data Owner / DPO如適用 最長90日，高風險每30日重評。
使用非標準演算法 需密碼學審查、相容性原因、限制用途、退場計畫與風險接受。 CISO / Cryptography Owner 最長180日或專案期限。
