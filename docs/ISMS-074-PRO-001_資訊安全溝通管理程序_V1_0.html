1. 程序目的

本程序用於規範組織如何識別、規劃、執行、核准、監督、保存與改善資訊安全相關內部與外部溝通，確保適當之資訊於適當時間，以適當方式傳達給適當對象，並維持訊息一致性、準確性、保密性、可追溯性與合規性。

本程序為ISO/IEC 27001:2022 Clause 7.4 Communication之核心符合性證據，並支援Clause 4.2關注方需求、5.1領導承諾、6.1風險與機會、8.1運作控制、9.1績效評估、9.3管理審查及Annex A中與主管機關、專業團體、供應商、事件管理、法規合約及隱私保護相關之控制要求。

2. 適用範圍

  • 適用於ISMS範圍內所有內部資訊安全溝通，包括政策、目標、風險、控制、認知、事件、變更、稽核、管理審查及CAPA相關溝通。
  • 適用於外部資訊安全溝通，包括主管機關、客戶、供應商、外包商、雲端服務商、驗證機構、法務顧問、專業團體、資料主體、媒體與其他關注方。
  • 適用於一般溝通、定期溝通、緊急溝通、重大事件/危機溝通、隱私通報、AI事件溝通、復原狀態溝通、法規/合約通報及供應鏈事件溝通。

外部溝通 與客戶、供應商、主管機關、驗證機構、資料主體、合作夥伴、媒體或其他外部關注方之溝通。

訊息分類 依資訊敏感度、影響範圍、法規合約要求及事件等級決定溝通限制、對象與核准層級。
危機溝通 面對重大資訊安全事件、隱私事件、AI事故、服務中斷、供應鏈事件或聲譽風險時之快速且受控溝通。
通報 依法律、監管、合約或內部程序要求，於指定時限內向特定對象傳達事件、變更或合規事項。

4. 溝通管理原則

原則 說明 管理要求
準確性 溝通內容應基於已確認事實，避免未經證實之推測。 重大或外部溝通需經指定角色審查。
及時性 資訊應於風險、事件、合規或營運需求所要求之時限內傳達。 通報時限需依事件等級、法規與合約要求管理。
適當性 溝通對象、內容深度、頻率與管道應符合情境與權限。 避免過度揭露或不足揭露。
保密性 溝通過程需保護機密資訊、PII、客戶資料、事件細節與商業敏感資訊。 依資料分類與Need-to-Know原則控管。
一致性 內外部訊息應一致，避免不同對象收到矛盾內容。 重大事件需建立核准版訊息與FAQ。
可追溯性 重要溝通、核准、通報與回覆需保留紀錄。 保留溝通計畫、通知、會議、郵件與決策紀錄。
合規性 溝通需符合法律、監管、合約、資料處理條款、SLA與客戶承諾。 法務、DPO或合約Owner需參與相關審查。
