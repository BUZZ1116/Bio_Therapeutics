1. 作業目的

本作業指導書規範委外開發與供應商交付之安全要求，涵蓋供應商選擇、風險評估、合約安全條款、開發環境、資料與Secrets保護、安全架構、安全編碼、安全測試、開源與供應鏈安全、AI/ML委外開發、交付驗收、上線前安全閘門、維護變更、事件通報、退場移交與稽核證據要求，確保外部開發活動符合組織ISMS、隱私、AI治理、營運持續與合規要求。

本文件旨在避免委外開發造成未授權存取、原始碼外洩、弱點導入、開源授權違規、惡意程式或後門植入、供應商環境資料外洩、AI資料誤用、模型供應鏈風險、Secrets外洩、交付物不可維護、退場資料殘留及供應鏈中斷等風險。

2. 作業原則

  • 委外開發不得降低組織安全要求；供應商交付物應符合與內部開發相同或更高之安全開發、安全編碼、安全測試、資料保護與交付驗收標準。
  • 委外開發應採風險導向，依資料分類、系統重要性、對外暴露、供應商存取權限、雲端/AI使用、客戶影響與法規要求決定控制深度。
  • 供應商不得未經核准取得正式資料、PII、客戶資料、Secrets、正式憑證、正式環境權限或生產系統管理權限。
  • 所有委外交付物應具備可驗收、可掃描、可追溯、可維護、可移交與可退場能力，包括原始碼、建置腳本、部署文件、測試報告、SBOM、模型版本、Prompt與設定。
  • 委外開發合約、SOW或採購文件應事前納入安全要求；不得於專案結束後才要求供應商補交安全證據。
  • AI、RAG、MLOps或生成式AI相關委外開發應額外納入AI資料、模型、Prompt、輸出、工具調用、資料不訓練、模型供應鏈與碳/資源資料安全要求。

3. 名詞與定義

名詞 定義
委外開發 由外部供應商、承包商、顧問或合作夥伴為組織設計、開發、測試、維護、建置、部署或客製化系統、程式、AI模型或技術服務之活動。
交付物 供應商交付之原始碼、二進位檔、腳本、設定檔、文件、測試報告、SBOM、模型、Prompt、資料集、部署包或其他成果。
SOW Statement of Work，工作說明書，描述委外範圍、責任、交付物、時程、驗收、安全要求與限制。
SBOM Software Bill of Materials，軟體物料清單，列示元件、版本、授權、來源與供應鏈資訊。
Secure SDLC 安全軟體開發生命週期，將安全需求、設計、編碼、測試、部署、維護與退場整合至開發流程。
委外開發環境 供應商或組織提供予供應商之開發、測試、建置、CI/CD或交付環境。
供應商存取 供應商人員對組織系統、資料、Repo、雲端、SaaS、CI/CD、測試環境或正式環境之存取。
第三方元件 由外部提供之開源套件、商業函式庫、SDK、模型、API、容器映像、插件或工具。
AI委外開發 供應商參與AI模型、AI應用、RAG、Prompt、Agent、MLOps、模型評估或AI資料處理之開發活動。
交付驗收 組織依合約、SOW、品質、安全、功能、文件、測試、授權與移交要求確認交付物可接受之活動。

Cloud Security Owner 審查供應商雲端帳號、IAM、網路、KMS、CSPM、日誌與共享責任。 雲端安全審查。
AI Governance / MLOps Owner 審查AI模型、Prompt、RAG、訓練資料、模型版本、AI安全測試與AI供應商風險。 AI風險審查。

5. 委外開發風險分級

風險等級 判定條件 最低控制要求 核准層級
低 不接觸正式資料、無PII、無正式系統存取、非對外服務、低重要性內部工具或文件型交付。 NDA、基本安全要求、交付驗收、開源授權檢查。 System Owner / Procurement。
中 接觸內部資料、需存取開發/測試環境、一般API或內部應用開發。 供應商安全評估、SOW安全條款、安全編碼、SAST/SCA/Secrets掃描。 System Owner / CISO授權角色。
高 處理機密資料、客戶資料、PII、對外服務、雲端平台、API、支付/金融/營運關鍵流程或特權開發。 強化供應商評估、DPA、稽核權、安全架構審查、DAST/API測試、SBOM、正式驗收。 CISO / Data Owner / DPO如適用。
極高 供應商需正式環境高權限、代管關鍵系統、大量PII、高機密資料、AI高風險系統、自動化重大決策或重大客戶服務。 管理階層核准、獨立安全測試、PAM/Session Recording、強化合約、退場演練、定期稽核。 CISO / 管理階層授權代表 / Legal。
AI高風險 涉及AI模型訓練/微調、RAG正式資料源、AI Agent高風險工具、模型供應鏈、外部AI API或客戶AI功能。 AI風險評估、資料不訓練條款、模型/Prompt版本、AI安全測試、AI供應商評估。 AI Governance / CISO / Data Owner / DPO。

6. 委外開發安全流程

階段 作業要求 責任角色 輸出證據
1. 需求與風險識別 確認委外範圍、資料分類、系統重要性、對外暴露、AI/雲端/供應商依賴與法規要求。 Project Owner / System Owner 委外需求與風險分級。
2. 供應商預審 評估供應商安全能力、開發流程、認證、過往紀錄、子承包商、資料保護與交付能力。 Supplier Management / CISO 供應商安全評估。
3. 合約與SOW安全條款 納入NDA、DPA、保密、智慧財產權、開源、交付、測試、稽核權、事件通報與退場。 Legal / Procurement 合約與SOW。
4. 安全啟動會議 向供應商說明安全要求、資料限制、Repo、CI/CD、測試、交付格式與溝通窗口。 Project Manager / DevSecOps / AppSec 啟動會議紀錄。
5. 安全架構與設計審查 審查架構、資料流、身份、網路、雲端、AI、供應商連線與威脅模型。 Security Architecture / CISO 架構審查紀錄。
6. 開發與安全控制 依安全編碼、Secrets管理、環境區隔、測試資料與CI/CD要求進行開發。 Supplier / DevSecOps 開發紀錄、掃描報告。
7. 安全測試與弱點修復 執行SAST、SCA、Secrets、DAST、API、IaC、容器、AI安全測試及重測。 Supplier / AppSec / QA 安全測試與修復證據。
8. 交付驗收 依功能、品質、安全、授權、文件、SBOM、部署、移交與退場要求驗收。 System Owner / QA / AppSec 驗收紀錄。
9. 上線與營運移交 交付物納入組織Release、監控、備份、組態、權限與事件流程。 Release Manager / IT Operations 上線與移交紀錄。
10. 維護、變更與退場 維護期間持續管理弱點、變更、供應商存取、資料刪除、知識移轉與合約終止。 Supplier Management / System Owner 維護與退場紀錄。

7. 供應商預審與安全能力評估

評估領域 評估要求 證據範例
資安管理能力 供應商是否具備資訊安全政策、角色責任、風險管理、事件通報與內部控制。 ISO 27001證書、SOC報告、政策摘要。
安全開發能力 是否有Secure SDLC、安全編碼、Code Review、安全測試、弱點管理與Release控制。 SDLC流程、工具報告範例。
人員管理 開發人員是否簽署保密、接受安全訓練、具背景查核或適任性管理。 NDA、訓練紀錄、角色清單。
開發環境安全 開發環境是否具MFA、EDR、硬碟加密、Repo權限、Secrets保護與環境區隔。 環境說明、控制證據。
資料保護 是否能保護PII、客戶資料、測試資料、跨境資料與刪除證明。 DPA、資料處理流程。
開源與供應鏈 是否執行SCA、SBOM、授權檢查、惡意套件防護與元件更新。 SBOM範例、SCA報告。
雲端安全 是否具雲端IAM、網路、KMS、CSPM、日誌與備份能力。 雲端控制證據。
AI開發能力 如涉及AI，是否管理模型來源、資料授權、Prompt、RAG、模型安全測試與資料不訓練。 AI治理文件、模型卡。
事件與弱點回應 是否能於約定時間通報事件與弱點並支援修復。 事件通報流程、SLA。
退場能力 是否能交付原始碼、文件、帳號移交、資料刪除、Secrets撤銷與知識移轉。 退場程序、移交清單。

8. 合約與SOW安全條款最低要求

條款領域 最低要求 適用情境
保密與NDA 供應商及其人員應保護組織資料、原始碼、架構、弱點、Secrets與業務資訊。 所有委外開發。
資料保護與DPA 明確資料類型、用途、保存、刪除、跨境、子處理者、資料主體權利與通報義務。 涉及PII、客戶資料或受管制資料。
安全開發要求 要求安全編碼、Code Review、弱點修復、測試、掃描與安全閘門。 所有程式交付。
開源與第三方元件 要求列示元件、授權、版本、來源、SBOM與禁止授權限制。 使用開源或第三方元件。
交付物要求 定義原始碼、建置腳本、部署文件、設定、測試報告、SBOM、模型、Prompt與操作手冊。 所有交付型專案。
稽核權與證據 組織得審查供應商安全證據、測試報告、弱點修復、資料刪除與控制有效性。 中高風險以上。
事件通報 要求資安事件、資料外洩、Secrets外洩、供應鏈事件與重大弱點於約定期限內通報。 所有委外開發。
弱點修復SLA 定義Critical/High/Medium/Low弱點修復期限、重測與延遲修復核准。 所有程式交付。
智慧財產權 明確原始碼、文件、模型、Prompt、資料集、衍生成果與使用授權歸屬。 所有交付型專案。
子承包商管理 供應商使用子承包商需事前核准並承擔同等安全義務。 涉及子處理者或子承包商。
退場與刪除 合約終止或專案結束時需移交成果、刪除資料、撤銷權限、提供刪除證明。 所有委外開發。
AI資料不訓練 若使用外部AI或AI供應商，需明定資料不訓練、Prompt保存、模型輸出與刪除要求。 AI相關專案。

9. 委外開發環境與存取安全要求

控制項目 最低要求 高風險加強要求
Repo存取 供應商Repo存取需具名、MFA、最小權限、分支保護與活動紀錄。 高風險專案使用組織控制之Repo與審查流程。
開發端點 供應商開發端點需防惡意程式、加密、螢幕鎖定、修補與不使用共享帳號。 高風險需EDR、MDM或供應商控制證據。
開發環境隔離 供應商開發/測試環境不得連接正式資料庫或正式服務，除非核准。 需網路隔離、測試資料與測試Secrets。
測試資料 供應商原則僅可使用合成或遮罩資料。 正式資料需DPA、Data Owner、DPO與CISO核准。
Secrets管理 不得以Email/聊天傳送Secrets，不得提交Repo或寫入文件。 使用Vault/Secrets Manager與短期憑證。
遠端存取 供應商遠端存取需MFA、VPN/ZTNA、時間限制、來源限制與日誌。 正式或高權限存取需PAM與Session Recording。
雲端權限 供應商雲端權限需限定Role、環境、資源與期限。 禁止長效高權限Access Key，採JIT或臨時角色。
AI工具使用 供應商不得將組織資料、原始碼、Secrets或客戶資料輸入未核准AI工具。 需AI工具清單、資料不訓練與DLP監控。
存取撤銷 人員異動、專案結束、合約終止或疑似事件時立即撤銷權限與輪替Secrets。 需撤權證據與帳號盤點。

審查領域 最低要求 證據

威脅模型 中高風險系統需識別攻擊面、威脅、濫用情境、控制缺口與緩解措施。 威脅模型文件。
身份與存取 採SSO/MFA、最小權限、RBAC/ABAC、服務帳號管理與權限審查。 IAM設計。
資料保護 依資料分類設計加密、遮罩、DLP、保留、刪除與備份。 資料保護設計。
網路安全 採網路分段、最小連線、WAF/API Gateway、Private Link、VPN/ZTNA與日誌。 網路設計。
日誌與監控 需設計安全日誌、審計日誌、告警、事件追蹤與Log遮罩。 日誌設計。
備份與復原 需符合RTO/RPO、備份、還原、不可變與災難復原需求。 復原設計。

11. 安全編碼與交付開發要求

控制項目 最低要求 證據
安全編碼標準 供應商需遵守組織安全編碼要求與相關OWASP/ASVS/API/LLM安全要求。 安全編碼承諾、Code Review。
Code Review 所有正式交付程式碼需經Code Review，敏感功能需安全審查。 PR與Review紀錄。
Secrets防護 程式碼、設定、測試、CI/CD、容器與文件不得含有效Secrets。 Secrets掃描報告。
輸入與輸出控制 需防注入、XSS、命令注入、Prompt Injection與不安全反序列化。 SAST/DAST報告。
授權邏輯 API、資料、租戶、角色與高風險操作需伺服器端授權驗證。 安全測試與Code Review。
錯誤處理 不得在錯誤訊息或Log洩漏內部架構、Stack Trace、SQL、Secrets或PII。 測試報告。
檔案與內容處理 上傳、下載、解析、轉換與媒體處理需掃描、授權與隔離。 測試案例。
CI/CD安全 Pipeline需具分支保護、安全掃描、Artifact完整性與正式部署核准。 Pipeline設定。
AI產生程式碼 供應商使用AI產生程式碼需揭露並經人工審查、安全測試與授權確認。 AI使用紀錄、Review紀錄。
