1. 作業目的

本作業指導書用於規範組織之日誌管理、資安監控、事件偵測、告警分級、通報升級、監控規則維護、日誌完整性保護、保存期限、隱私與合規要求及監控有效性評估，以確保資訊安全事件能被及時發現、正確分析、有效回應並保留可稽核之證據。

本文件同時支援ISO/IEC 27001:2022 Annex A.8.15「Logging」、A.8.16「Monitoring activities」、A.8.17「Clock synchronization」及事件管理、存取控制、弱點管理、雲端安全、供應鏈安全、AI治理、隱私保護與營運持續之要求。

2. 作業原則

  • 所有關鍵資訊資產、對外服務、特權存取、身分驗證、雲端控制平面、資料存取、AI模型服務及安全設備，應產生日誌並納入監控。
  • 日誌應具備完整性、可用性、可追溯性、時間一致性、存取管制與防竄改能力，並依風險、法規、合約與稽核要求保存。
  • 監控應採風險導向，優先覆蓋高價值資產、外部暴露系統、PII/客戶資料、高機密資料、關鍵流程、雲端與AI服務。
  • 告警應分級、去重、關聯、指派Owner、紀錄處置結果，並與事件通報、事件回應、數位證據保存及事後檢討連動。
  • 監控規則、偵測案例與告警門檻應定期檢討，並結合威脅情資、弱點資訊、攻擊技術、事件經驗與業務變更持續改善。

3. 名詞與定義

名詞 定義
日誌（Log） 系統、應用程式、設備、服務、使用者、管理員、API、資料庫、雲端平台或安全工具於操作、存取、錯誤、異常、事件、稽核或安全控制活動中產生之紀錄。
安全監控 持續或定期收集、分析、關聯與檢視日誌、流量、端點、雲端、身分、資料、應用與AI服務活動，以識別異常、攻擊、違規或控制失效。
SIEM Security Information and Event Management，用於集中蒐集、關聯分析、搜尋、告警與報表之安全資訊與事件管理平台。
SOAR Security Orchestration, Automation and Response，用於告警自動化、工單、應變劇本、證據蒐集與流程協調之平台。
EDR / XDR Endpoint Detection and Response / Extended Detection and Response，用於端點或跨域偵測、調查與回應之安全工具。
偵測案例（Detection Use Case） 針對特定威脅、攻擊技術、風險情境或控制要求所設計之監控邏輯、資料來源、關聯條件、告警門檻與應變動作。
誤報（False Positive） 監控系統產生告警但經分析後確認非資安事件或非控制失效之情形。
漏報（False Negative） 實際發生異常、攻擊或控制失效，但監控規則未能偵測或未產生有效告警之情形。
時間同步 透過可信任時間來源（如NTP）確保所有系統、設備、日誌與監控平台時間一致，以支援事件關聯、鑑識與稽核。

5. 日誌與監控作業流程總覽

流程階段 作業內容 責任角色 輸出紀錄
1. 監控範圍識別 依資產清冊、風險評鑑、資料分類、雲端服務、AI服務、供應商與關鍵流程識別應納入監控之資產。 SOC / ISMS管理代表 / 資產Owner 監控範圍清單、日誌來源清冊。
2. 日誌需求定義 定義日誌類型、欄位、頻率、保存期限、敏感資料遮罩、時間同步、傳輸與存取要求。 SIEM Owner / System Owner 日誌需求矩陣。
3. 日誌接入與解析 將日誌安全傳送至SIEM、資料湖或集中日誌平台，完成解析、標準化、分類與完整性檢查。 SIEM Owner / IT 日誌接入紀錄、解析規則。
4. 偵測規則設計 依威脅情資、MITRE ATT&CK、弱點、事件經驗、法規與控制要求建立偵測案例。 SOC / Threat Detection Engineer 偵測案例清單、關聯規則。
5. 告警分級與處置 依告警嚴重度、資產重要性、資料敏感度、攻擊階段與影響範圍進行初判、指派、升級與通報。 SOC Analyst / Incident Manager 告警工單、事件通報紀錄。
6. 調查與證據保存 保留相關日誌、封存證據、記錄查詢、關聯分析、鑑識線索與處置行動。 SOC / Digital Evidence Custodian 調查紀錄、證據保存紀錄。
7. 效能與品質檢討 分析告警量、誤報、漏報、MTTD、MTTA、MTTR、資料來源缺口、規則有效性與改善行動。 SOC負責人 / CISO KPI/KRI、規則調整、CAPA。

7. 日誌欄位與品質要求

要求類別 最低要求 品質檢核方式
識別資訊 日誌應包含事件ID、事件類型、使用者/服務帳號、來源IP、目的IP、系統名稱、資產ID、應用程式、API端點或資源名稱。 抽樣檢查日誌欄位完整性。

告警等級 判定條件 初步處置時限 升級要求
P1 重大 / Critical 疑似資料外洩、勒索攻擊、已確認入侵、關鍵服務受影響、特權帳號遭接管、雲端控制平面遭濫用、AI服務造成重大資料揭露。 15至30分鐘內初判並通知Incident Manager。 立即通報CISO、IT主管、System Owner；必要時啟動事件管理與危機溝通。
P2 高 / High 高可信度攻擊、外部暴露系統高風險告警、重大弱點遭嘗試利用、異常大量資料存取或高價值資產異常。 1小時內初判並建立工單。 通知SOC負責人、資產Owner與相關技術Owner。
P3 中 / Medium 需進一步確認之異常行為、政策違規、掃描、單一系統異常、可疑登入或控制失效。 1個工作日內處理。 依分析結果升級或關閉。
P4 低 / Low 資訊性告警、低風險異常、已知誤報、一般政策提醒或基準偏差。 依排程檢視。 納入趨勢分析與規則調整。

12. SOC告警處理作業

步驟 作業內容 責任角色 必要紀錄

資料補充 查詢相關日誌、端點狀態、網路流量、雲端活動、IAM事件、弱點與資產重要性。 SOC Analyst / Tier 2 查詢紀錄、證據連結。
分級與指派 依嚴重度、影響範圍與處理手冊分派至事件、工單、問題管理或例行追蹤。 SOC Lead 工單、指派紀錄。
遏止與通報 必要時執行封鎖、隔離、停用帳號、撤銷Token、阻擋IP、調整WAF或通報Owner。 SOC / IT / Incident Manager 處置紀錄、通報紀錄。
關閉與回饋 確認處置完成、記錄根因、誤報原因、規則改善需求與後續追蹤事項。 SOC Analyst / SOC Lead 關閉紀錄、規則調整需求。
