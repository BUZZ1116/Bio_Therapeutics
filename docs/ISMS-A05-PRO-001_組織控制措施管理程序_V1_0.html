1. 程序目的

本程序用於建立、實施、維持與持續改善ISO/IEC 27001:2022 Annex A.5組織控制措施之治理與管理機制，確保組織控制措施可依風險處理結果、SoA適用性、法規合約要求、營運需求、供應鏈與雲端依賴、PIMS/AIMS/BCMS/GHG專項治理需求被有效規劃、執行、監督、驗證與改善。

本程序同時作為Annex A.5.1至A.5.37組織控制措施之共同管理程序，支援控制Owner指派、控制目標設定、控制實施證據保存、控制有效性驗證、KPI/KRI監督、內部稽核、管理審查、SoA更新及CAPA改善。

2. 適用範圍

  • 適用於Annex A.5所有組織控制措施之適用性判定、控制設計、實施、維護、證據保存、監督量測與有效性驗證。
  • 適用於資訊安全政策、角色責任、職責分離、管理責任、主管機關與專業團體聯繫、威脅情資、專案安全、資產管理、資訊分類、存取權限、供應商、雲端、事件管理、營運持續、法規合約、隱私、獨立審查、政策符合性與文件化程序。
  • 適用於與組織控制相關之內部部門、流程Owner、Control Owner、風險Owner、供應商、外包商、雲端服務商、客戶服務團隊、DPO、AI治理負責人、BCMS負責人、GHG資料治理負責人與內部稽核人員。

3. 名詞與定義

名詞 定義
組織控制措施 ISO/IEC 27001:2022 Annex A.5所列之管理、治理、政策、流程、角色、供應商、合規與營運管理類控制措施。
Control Owner 對特定控制措施之設計、實施、證據、有效性、缺口改善與稽核回覆負責之角色。
Control Governance Owner 負責整體控制治理、清冊、SoA連結、監督量測與管理審查輸入之角色。
控制目標 控制措施欲達成之風險降低、合規、營運、治理或證據目標。
控制證據 可證明控制措施已按要求執行之文件化資訊，例如政策、清冊、紀錄、報告、工單、會議紀錄、系統紀錄與核准紀錄。
控制有效性 控制措施是否已設計適當、實施到位、持續運作並達成預期風險降低或合規效果。
SoA 適用性聲明，列明Annex A控制措施之適用性、實施狀態、排除理由與證據。
控制缺口 控制未設計、未實施、未持續運作、未保存證據或無法達成預期效果之情形。
補償控制 原控制不可行或不足時，採用替代措施以降低相同或相近風險之控制。

4. 組織控制措施治理原則

治理原則 說明 管理要求
風險導向 所有Annex A.5控制措施之適用與實施需以風險評鑑、風險處理、合規義務與營運需求為基礎。 控制措施不得僅形式化列示，需能對應風險與實際運作。
責任明確 每項控制措施需指定Control Owner、執行角色、審查角色與核准角色。 責任需納入RACI與SoA。
證據可稽核 控制措施需定義證據型態、保存位置、保存期限與證據Owner。 無證據不得視為控制有效。
SoA一致性 控制措施之適用性、實施狀態與證據需與SoA一致。 控制變更需同步更新SoA。
跨治理整合 控制措施需支援ISMS、PIMS、AIMS、BCMS、GHG/CO2資料治理及供應鏈治理。 專項Owner需參與相關控制審查。
持續監督 控制措施需透過KPI/KRI、控制自評、內部稽核、事件、CAPA與管理審查持續監督。 重大缺口需升級CISO或管理階層。
持續改善 控制失效、稽核發現、事件與風險變化需導致控制改善。 必要時啟動CAPA。
