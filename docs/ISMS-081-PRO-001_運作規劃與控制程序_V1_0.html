1. 程序目的

本程序用於建立、實施、維持與持續改善ISMS運作規劃與控制機制，確保組織在資訊安全管理系統範圍內之所有流程、系統、服務、資料處理、供應鏈、雲端服務、AI系統、PII處理、營運持續及GHG資料資料治理活動，均依已規劃之準則執行，並保留足夠文件化資訊以證明流程已依要求運作。

本程序為ISO/IEC 27001:2022 Clause 8.1 Operational planning and control之核心符合性證據，並支援Clause 8.2資訊安全風險評估、8.3資訊安全風險處理、7.5文件化資訊、9.1監督量測分析評估、9.2內部稽核、9.3管理審查及10.2不符合與矯正措施。

2. 適用範圍

  • 適用於ISMS範圍內所有需被規劃、控制、監督、外包、變更或保存證據之資訊安全運作活動。
  • 適用於資訊資產管理、存取控制、供應商安全、雲端服務、弱點管理、事件應變、變更管理、備份復原、日誌監控、資料保護、PII處理、AI系統使用、營運持續/復原與GHG資料資料治理。
  • 適用於由內部部門執行、由供應商或外包商執行、由雲端平台支援或由跨部門協作完成之運作流程。

3. 名詞與定義

名詞 定義
運作規劃 為達成ISMS要求、資訊安全目標、風險處理計畫與控制要求，預先定義流程、責任、資源、準則、證據與監督方法之活動。
運作控制 依規劃準則執行、監督與維持流程，使風險與控制要求在日常營運中落實之活動。
控制準則 用於判定運作是否符合要求之規則、政策、程序、KPI/KRI、驗收標準、SLA或控制要求。
外包流程 由外部供應商、雲端服務商、承包商或第三方執行，但仍由組織承擔管理責任之流程。
流程Owner 對特定運作流程之規劃、執行、控制、監督、證據與改善負責之角色。
Control Owner 對特定控制措施之設計、執行、證據、有效性與改善負責之角色。
運作證據 可證明流程依規劃執行之紀錄，例如工單、日誌、會議紀錄、審查紀錄、報告、簽核、平台紀錄或監控結果。
偏離控制 運作未按規劃準則執行時之識別、評估、核准、補救與改善活動。

4. 運作規劃與控制原則

原則 說明 管理要求
風險導向 運作控制應依資訊安全風險、合規義務、客戶承諾與營運重要性設計。 高風險流程需有更高頻率監督、證據保存與管理審查。
流程導向 每項關鍵運作需定義輸入、活動、輸出、責任、資源與控制準則。 流程Owner需維護流程文件與運作紀錄。
控制整合 運作控制需與風險處理計畫、SoA、Annex A控制與內部程序一致。 Control Owner需定期確認控制有效性。
證據導向 所有重要運作控制需保留足以證明執行情形之文件化資訊。 證據需可追溯、完整、受控保存。
變更受控 影響ISMS運作之變更需依變更管理程序評估與核准。 重大與緊急變更需保留CAB/ECAB與PIR證據。
外包可控 外包流程不得免除組織責任，需透過合約、SLA、監督與審查控制。 供應商Owner需定期取得與審查證據。
持續改善 運作偏離、事件、稽核發現與KPI/KRI異常需導出改善。 必要時啟動CAPA並追蹤有效性。
