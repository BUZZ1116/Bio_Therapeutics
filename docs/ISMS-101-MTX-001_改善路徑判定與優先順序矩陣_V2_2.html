1. 矩陣目的

本矩陣用於將10.1改善機會快速、清楚且一致地分流到正確的管理系統流程，避免所有改善都被錯誤地當作CAPA，或所有改善都只停留在提案表。

4. 使用規則

規則 要求
一案一主路徑 每一項改善機會應指定一個主要路徑；
必要時可列關聯路徑，例如CAPA同時需要風險更新與變更管理。
不以快速改善取代CAPA 已發生不符合事項發現、重複問題、資訊安全事件、申訴或通報、稽核不符合或系統性失效時，應轉入10.2 CAPA。
重大事項必須升級 影響關注方、法規、重大風險、重大資源或跨部門決策時，應提交管理審查或治理機構。
資料不足應補證 若分流依據不足，應先要求補充資料，並在改善登錄表標示狀態與期限。
完成後要確認效果 不論走哪一條路徑，最終仍需回到改善登錄表確認完成、效果、標準化與是否關閉。
