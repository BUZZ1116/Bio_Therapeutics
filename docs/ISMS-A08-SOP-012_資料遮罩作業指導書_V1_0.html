1. 作業目的

本作業指導書規範組織資料遮罩、去識別化、假名化、匿名化、Tokenization、資料擾動、資料合成與測試資料保護之方法、流程、角色責任、驗證、核准、保存、例外與稽核要求，確保敏感資料於非正式環境、測試、開發、教育訓練、Demo、分析、AI訓練、供應商支援、客戶服務、報表、除錯、日誌及資料分享場景中受到適當保護。

資料遮罩之目的在於降低資料可識別性與外洩衝擊，同時維持必要之業務、測試、分析或模型訓練效用。本文件要求資料遮罩作業必須與資料分類分級、隱私治理、DLP、存取控制、加密、日誌監控、測試資料管理、AI資料治理及供應商管理整合，形成可驗證、可追溯、可重複執行且符合法規與合約要求之資料保護控制。

2. 作業原則

  • 正式敏感資料原則上不得直接使用於開發、測試、教育訓練、Demo、AI實驗、供應商除錯或非正式環境；如確有必要，應優先使用合成資料、去識別資料或經核准之遮罩資料。
  • 資料遮罩方法應依資料敏感度、使用目的、重識別風險、資料效用、法規合約、資料流向及使用者權限決定，不得以單一遮罩方法套用所有情境。
  • 遮罩後資料仍可能因多欄位組合、外部資料比對、統計推論或AI模型反推而具重識別風險，應定期評估並採取補強控制。
  • 遮罩規則、對照表、Token Vault、Salt、金鑰、演算法與映射資料本身屬高敏感資訊，應限制存取、加密、監控並納入Secrets與金鑰管理。
  • 資料遮罩結果需經驗證，確認敏感資料不可被未授權識別、測試需求仍可滿足、資料關聯性符合用途，且未破壞關鍵測試或業務邏輯。
  • 所有遮罩例外、可逆遮罩、保留原始欄位、使用正式資料或資料集外部分享均應經Data Owner、DPO與CISO視風險核准。

3. 名詞與定義

名詞 定義
資料遮罩 對敏感資料進行遮蔽、替換、擾動、雜湊、Tokenization或其他處理，使未授權對象無法直接取得原始資料之控制措施。
靜態資料遮罩 在資料複製、匯出、移轉或產生測試資料集時，將資料轉換為遮罩後版本。
動態資料遮罩 依使用者角色、查詢情境或應用層規則，在資料存取或呈現時動態遮蔽部分資料。
去識別化 移除或轉換可直接或間接識別個人、客戶或資料主體之資料，以降低識別風險。
假名化 以代碼、Token或替代值取代識別資料，但在保留對照表或補充資料時仍可重新識別。
匿名化 資料經處理後，在合理可預見條件下無法再識別資料主體之狀態。
Tokenization 以Token取代敏感資料，原始值由受控Token Vault或等效機制保存。
資料合成 使用人工產生、統計生成或模型生成之資料取代真實資料，以維持測試或分析效用。
重識別風險 遮罩或去識別資料被透過欄位組合、外部資料集、背景知識或模型推論重新識別之可能性。
遮罩規則 定義哪些欄位、資料類型、資料集、環境與使用情境應採何種遮罩方法、保留格式與驗證要求之規則。
映射表 / 對照表 保存原始資料與遮罩值、Token或假名之對應關係，屬高敏感資料。

4. 角色與責任

角色 主要責任 主要輸出 / 證據
CISO / 資訊安全負責人 核准高風險遮罩策略、可逆遮罩、正式資料使用例外、外部分享與風險接受。 核准紀錄、風險接受、管理審查。
DPO / Privacy Owner 審查PII遮罩、去識別化充分性、DPIA、重識別風險、跨境與資料主體權利影響。 DPIA、隱私審查紀錄。
Data Owner 定義資料分類、使用目的、遮罩需求、資料效用、可接受風險與例外核准。 資料分類與遮罩核准。
Data Governance Owner 維護資料目錄、欄位分類、資料血緣、遮罩政策、資料使用與品質治理。 資料目錄、遮罩規則清冊。
Data Protection / Masking Owner 設計遮罩方法、規則、流程、驗證、工具設定與定期審查。 遮罩方案、測試報告。
Database / Data Platform Owner 執行資料庫、資料倉儲、資料湖、ETL/ELT、Token Vault與資料平台遮罩控制。 資料處理紀錄。
Application Owner 確保應用層動態遮罩、API回應遮罩、報表遮罩與使用者權限正確。 應用設定與測試。
QA / Test Data Owner 定義測試資料需求，優先使用合成或遮罩資料，保護測試環境。 測試資料申請與驗證。
DevSecOps / Application Security 審查遮罩流程、CI/CD資料處理、Secrets、測試資料、程式碼與日誌外洩風險。 安全審查紀錄。
AI Governance / MLOps Owner 審查AI訓練、微調、評估、Prompt、RAG與向量資料之遮罩與重識別風險。 AI資料評估與模型紀錄。
SOC / Monitoring Owner 監控未遮罩資料外傳、異常存取、遮罩例外與資料外洩事件。 DLP/SIEM告警。
Supplier Management 確保供應商使用遮罩資料，並於合約規範資料保護、刪除、事件通報與稽核。 供應商合約與證據。
Internal Auditor 抽查遮罩規則、核准、執行、驗證、例外、日誌與重識別風險評估。 稽核底稿、稽核發現。

5. 資料遮罩適用場景與最低要求

場景 最低要求 禁止或限制事項
開發環境 原則使用合成資料或遮罩資料，不得直接複製正式PII或客戶資料。 禁止開發人員任意取得完整正式資料。
測試 / UAT 依測試目的使用遮罩、Tokenization或合成資料，保留必要格式與關聯。 不得以便利性為由使用未遮罩正式資料。
教育訓練 / Demo 使用完全合成或高度遮罩資料。 禁止使用真實客戶、員工、交易或Secrets。
除錯與客戶支援 僅提供最小必要遮罩資料，必要原始資料需Data Owner核准。 禁止截圖或匯出完整敏感資料至非核准工具。
報表與分析 依角色、目的與粒度遮罩或彙總資料。 禁止將可識別資料提供給無必要知悉者。
資料倉儲 / 資料湖 欄位分類、權限、動態遮罩與資料集級遮罩需受控。 禁止未分類資料直接進入共享區。
API回應 應用層應依角色遮罩PII、Token、帳號、交易與敏感欄位。 禁止將完整敏感欄位暴露於前端或第三方API。
日誌與監控 日誌不得保存明文密碼、Token、完整PII或敏感資料，必要時遮罩。 禁止Debug Log長期保存敏感資料。
AI訓練 / 評估 優先使用合成、去識別或遮罩資料，評估模型記憶與重識別風險。 禁止未核准PII、Secrets或客戶資料輸入外部AI。
RAG / 向量資料庫 RAG資料需依來源分類處理，敏感Metadata與文件內容需遮罩或權限繼承。 禁止將未授權資料Embedding至共享向量庫。
供應商 / 委外 原則僅提供遮罩資料；若需原始資料需合約、DPA、NDA與風險核准。 禁止供應商自行保留資料副本。

6. 資料遮罩方法選擇矩陣

遮罩方法 適用情境 優點 限制 / 風險
固定字元遮蔽 顯示資料時僅保留部分字元，例如手機後三碼、Email部分遮蔽。 簡單、易理解、適合顯示層。 不適合測試關聯性或防止高風險重識別。
格式保留替換 以假資料取代原始值並保持格式，例如身分證、電話、信用卡格式。 適合測試、UAT與系統驗證。 需避免生成有效真實資料。
隨機化 / 擾動 對數值、日期、金額等加入擾動或區間化。 保留統計特性。 可能影響精準分析，仍需重識別評估。
雜湊 將資料轉換為不可讀Hash，用於比對或去識別識別碼。 適合比對與去識別。 低熵資料可能被字典攻擊，需Salt或Pepper。
Tokenization 以Token取代原始值，原始值保存於受控Token Vault。 適合可逆需求與支付/客戶識別。 Token Vault成為高敏感目標。
假名化 以假名或代碼取代識別欄位，保留分析關聯。 可支援長期追蹤分析。 保留對照表時仍屬可識別資料。
資料彙總 將細部資料轉為統計、區間、群組或彙總結果。 降低可識別性，適合報表。 不適合需明細測試情境。
欄位刪除 移除不必要敏感欄位。 最小化風險。 可能降低資料效用。
資料合成 產生非真實但具測試或統計特性之資料。 外洩風險最低，適合測試與AI評估。 需驗證效用與避免反映真實個體。
動態遮罩 依角色或查詢即時遮罩顯示結果。 適合正式查詢與報表。 需防止透過查詢推論繞過。

7. 資料遮罩作業流程

階段 作業要求 責任角色 輸出證據
1. 需求提出 申請人說明資料集、用途、環境、使用者、期限、資料欄位、效用需求與是否可使用合成資料。 申請人 / Business Owner 資料遮罩申請單。
2. 資料分類與欄位識別 識別PII、客戶資料、Secrets、敏感欄位、準識別欄位、資料關聯與資料Owner。 Data Owner / Data Steward 欄位分類表。
3. 風險與隱私評估 評估重識別、外洩影響、法規合約、AI推論、供應商與跨境風險。 DPO / CISO / Data Owner DPIA或風險評估。
4. 遮罩方法設計 依欄位與用途選擇遮罩方法、保留格式、關聯性、可逆性與驗證標準。 Masking Owner / Data Engineer 遮罩方案。
5. 核准 依風險取得Data Owner、DPO、CISO、AI Governance或Legal核准。 核准角色 核准紀錄。
6. 實作與執行 於受控環境執行遮罩，保護原始資料、映射表、金鑰與處理日誌。 Data Platform / DBA 執行紀錄。
7. 驗證 驗證遮罩完整性、資料效用、格式、關聯、重識別風險與無敏感殘留。 QA / Data Owner / Security 驗證報告。
8. 交付與使用 交付遮罩資料至核准位置、使用者與期間，限制複製與再分享。 Data Owner / IT 交付紀錄。
9. 監控與保存 監控遮罩資料使用、DLP告警、存取權限、保存期限與刪除。 SOC / Data Owner 監控與刪除紀錄。
10. 定期審查 定期審查遮罩規則、資料效用、例外、供應商使用與AI資料風險。 ISMS代表 / DPO 審查紀錄。

8. 欄位級遮罩規則建議

資料欄位類型 建議遮罩方式 驗證要求 備註
姓名 替換為假名、Tokenization或部分遮蔽。 不得與真實個體可合理連結。 測試需保留語系與長度時使用假名。
身分證 / 證件號 格式保留替換、Tokenization或Hash加Salt。 不得產生真實有效證號。 高度敏感欄位。
生日 區間化、年份保留、日期擾動或替換。 避免與其他欄位組合重識別。 依用途保留年齡區間即可。
電話 格式保留替換或僅保留末三碼。 不得對應真實可撥打號碼。 避免測試簡訊誤發。
Email 替換為測試網域或遮蔽帳號。 不得寄送至真實外部信箱。 建議使用example.com或內部測試網域。
地址 區域化、移除門牌、替換為假地址。 避免精確定位個人。 可保留縣市作統計。
銀行帳號 / 信用卡 Tokenization、格式保留假資料或完全移除。 不得保留完整真實號碼。 需防止測試付款誤觸發。
客戶編號 假名化、Tokenization或Hash加Salt。 保留關聯時需保護對照表。 可支援測試關聯性。
交易金額 區間化、擾動或合成。 不得影響測試邏輯或財務統計誤用。 正式報表需另行控管。
醫療/健康資料 去識別、彙總、移除直接識別碼與準識別碼。 需DPO與Data Owner核准。 高度敏感資料。
Secrets / Token / 密碼 完全移除、替換為測試Secrets、不可逆Hash。 不得保留任何有效Secrets。 需搭配Secrets掃描。
原始碼片段 移除Secrets、客戶資料、內部端點與敏感註解。 需SAST/Secrets掃描。 AI工具使用需特別審查。
Prompt / AI輸入 移除PII、Secrets、客戶資料與高機密內容。 需AI DLP或人工審查。 注意上下文重識別。

9. 測試資料與非正式環境遮罩要求

控制項目 最低要求 證據
正式資料使用限制 開發、測試、UAT不得直接使用未遮罩正式敏感資料。 資料遮罩申請與核准。
環境隔離 遮罩資料環境應與正式環境分離，權限不得高於必要範圍。 環境與權限設定。
資料量最小化 僅提供測試所需最小資料欄位、筆數、期間與關聯。 資料交付紀錄。
批次遮罩 正式資料複製至非正式環境前應先遮罩或於隔離區完成遮罩後再交付。 ETL/遮罩日誌。
測試Email/簡訊 遮罩或替換收件人，避免發送至真實客戶或員工。 測試設定。
付款/交易測試 支付、帳務、訂單與金融欄位需使用測試代碼與模擬資料。 測試資料驗證。
測試資料保存 遮罩資料仍需設定保存期限、存取控管與刪除機制。 保存與刪除紀錄。
供應商測試 供應商測試資料應為遮罩或合成資料，且需NDA/DPA與刪除證明。 供應商證據。

10. AI、RAG與資料科學遮罩要求

場景 遮罩要求 驗證方式
AI訓練資料 優先使用合成、去識別或最小化資料，移除直接識別碼與不必要準識別碼。 資料集風險評估與抽樣檢查。
模型微調 微調資料不得包含未核准PII、Secrets、客戶資料或高機密內容。 AI資料審查與DLP掃描。
模型評估資料 評估集應使用合成或遮罩資料，必要真實案例需DPO/Data Owner核准。 評估資料清冊。
Prompt樣本 Prompt樣本需移除個資、客戶內容、商業秘密、內部端點與Secrets。 Prompt審查紀錄。
RAG資料源 RAG文件進入索引前需依分類檢查，敏感資料需遮罩或權限繼承。 RAG資料源清冊。
向量資料庫 Embedding可能洩露來源語意，需依來源分類保護並限制查詢與匯出。 向量庫權限與測試。
AI輸出檢查 模型輸出不得重現訓練資料中的敏感資料或可識別內容。 模型記憶測試。
外部AI服務 輸入外部AI前需AI DLP、資料不訓練條款與必要遮罩。 供應商合約與AI DLP紀錄。
AI Agent Agent讀取資料、生成Email、上傳檔案或呼叫API前需檢查遮罩與DLP規則。 Agent操作日誌。
