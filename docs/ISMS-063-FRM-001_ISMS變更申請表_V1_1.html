1. 表單目的

本表用於正式提出、分類、評估、審查、核准、實施、驗證、回復、結案與保存ISMS相關變更，確保所有可能影響資訊安全、隱私保護、AI治理、營運韌性、供應鏈安全、GHG/CO2資料治理、氣候韌性、法規合約及管理系統完整性之變更均受到有效控制。

本表應作為變更管理之完整證據鏈，涵蓋變更原因、影響範圍、風險評估、控制措施、測試驗證、溝通通知、核准權限、實施紀錄、變更後審查、文件/清冊更新、CAPA及管理審查輸入。

1.1 管理活動與輸出摘要

表單章節 / 管理主題 如何使用 輸出 / 證據
1. 表單目的 將變更規劃、風險評估、運作控制、監督量測、CAPA及持續改善整合為完整證據鏈。 表單目的、變更控制閉環。
2. 適用範圍 判斷變更是否影響ISMS範圍、資訊資產、AI服務、PII處理、碳資料、雲端及外包流程。 變更適用範圍判定。
4. 變更基本資料 記錄變更申請人、目的、摘要、時程、停機影響、凍結期例外及狀態。 變更申請基本資料。
5. 變更分類與分級判定 依風險準則、影響範圍、CIA、PII、AI、GHG、供應鏈與合規衝擊判定變更等級與核准層級。 變更分類、風險等級、核准路徑。
6. 變更影響範圍識別 逐項確認是否影響範圍、政策程序、資產、系統、雲端、權限、監控、備份、供應商、PII、AI與碳資料。 影響範圍清單與Owner。
7. 變更觸發來源與原因 將變更來源追溯至定期審查、風險評估、弱點、事件、法規、稽核、CAPA、AI技術或監管趨勢。 變更觸發來源與相關證據。
8. 變更影響分析 評估CIA、權限、日誌監控、備份、PII、AI、氣候、GHG、法規、合約及可用性衝擊。 變更影響分析結果。
9. 變更風險評估與處理 將變更前後風險、風險等級、處理方式、剩餘風險與風險接受要求納入審查。 變更風險評估與處理紀錄。
10. 變更前必要控制措施 確認備份、權限、安全測試、監控、加密、文件清冊更新與變更後驗證要求。 變更前控制措施完成證據。
11~13. 實施、測試驗證與回復計畫 規劃實施步驟、成功/失敗條件、測試驗證、回復觸發、資料一致性與還原確認。 實施計畫、測試紀錄、回復計畫。
14. 溝通與通知計畫 規劃對管理階層、受影響部門、客戶、供應商、主管機關、DPO與使用者之溝通通知。 溝通計畫與通知證據。
15. 審查與核准紀錄 明確CISO、風險、DPO、AI、GHG、法務、供應商及管理階層之審查結果與核准條件。 審查核准紀錄、條件式核准、風險接受。
16~17. 實施紀錄、PIR與結案 記錄實施結果、變更後驗證、PIR、是否產生新增風險、是否需CAPA及結案判定。 實施紀錄、PIR、CAPA、結案紀錄。
18. 文件化資訊與保存要求 定義變更申請表、影響分析、風險評估、測試驗證、核准、PIR及CAPA之保存責任與期限。 文件化資訊保存與版本管理。

2. 適用範圍

  • 適用於定期變更或定期更新、重大變更、緊急變更、事後追認變更及CAPA導入變更。
  • 適用於ISMS範圍內所有組織、治理、流程、政策、目標、風險準則、SoA、控制措施、資訊資產、系統、雲端服務、AI系統、PII處理活動、資料中心、供應商、外包流程、備份與還原、備援、GHG/CO2資料及文件化資訊變更。
  • 適用於內部稽核、外部驗證、客戶稽核、管理審查與持續改善之變更證據保存。

3. 名詞與定義

名詞 定義
變更申請表 提出、分類、評估、核准與追蹤ISMS相關變更之正式表單。
Change Owner 提出變更並負責提供需求、影響分析、測試、實施、回復與結案證據之人員或單位。
變更管理負責人 負責受理、分類、排程、協調審查、追蹤實施及結案之角色。
定期變更 / 定期更新 依既定週期或標準作業執行之變更，例如政策審查、弱點修補、權限複核、文件更新。
重大變更 可能對ISMS範圍、風險、控制措施、服務可用性、合規義務、PII、AI、供應鏈、資料中心或管理系統完整性造成重大影響之變更。
緊急變更 因資訊安全、隱私、AI、氣候、供應鏈、營運中斷或重大弱點事故需立即執行之變更。
變更後審查（PIR） Post Implementation Review，用於確認變更結果、風險、回復、文件更新及改善需求。
