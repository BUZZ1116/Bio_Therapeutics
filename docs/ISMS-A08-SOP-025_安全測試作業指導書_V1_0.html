1. 作業目的

本作業指導書規範安全測試之規劃、範圍、方法、工具、執行、證據保存、弱點分級、修復驗證、例外核准、第三方測試管理、AI安全測試與持續改善要求，確保系統、應用、API、雲端、容器、行動應用、AI/RAG/Agent與供應商交付物於上線前及維運期間具備足夠安全驗證。

本文件旨在建立一致且可稽核的安全測試流程，將安全測試結果與弱點管理、風險登錄、上線閘門、事件管理、管理審查與安全開發流程連動，避免未修復高風險弱點進入正式環境或長期存在於營運服務中。

2. 作業原則

  • 安全測試應採風險導向，依系統重要性、資料分類、對外暴露、AI使用、供應商依賴與法規/合約要求決定測試深度與頻率。
  • 安全測試不得僅依賴單一工具，應整合SAST、DAST、SCA、Secrets掃描、IaC掃描、容器掃描、API測試、組態檢查、人工審查及必要之滲透測試。
  • Critical與High弱點應於上線前修復或取得正式風險接受；未經核准不得以業務時程為由繞過安全閘門。
  • 安全測試應避免對正式環境造成不可接受之影響；若需在正式環境測試，應事前核准、限定範圍、控制時間、通知監控團隊並建立回復方式。
  • 測試資料、測試帳號、掃描報告與弱點細節應依機密資訊管制，避免造成二次外洩或攻擊指引。
  • AI、RAG、AI Agent與模型API之安全測試應包含傳統應用安全、資料保護、Prompt Injection、越權檢索、工具濫用、敏感輸出與模型供應鏈風險。

3. 名詞與定義

名詞 定義
安全測試 用於識別、驗證與評估系統、應用、API、雲端、網路、AI或供應商交付物安全缺陷之測試活動。
SAST Static Application Security Testing，靜態應用程式安全測試，檢查原始碼或編譯產物中的安全缺陷。
DAST Dynamic Application Security Testing，動態應用程式安全測試，在執行環境中測試應用程式弱點。
SCA Software Composition Analysis，軟體組成分析，用於識別開源元件、授權、版本與已知弱點。
IAST Interactive Application Security Testing，在應用執行時結合程式插樁或代理以分析弱點。
Secrets掃描 檢查Repo、Commit、CI/CD、Artifact、Container、日誌與文件中是否含密碼、Token、API Key、私鑰或憑證。
IaC掃描 針對基礎設施即程式碼、雲端配置、Kubernetes YAML或部署腳本進行錯誤組態與安全風險檢查。
滲透測試 由授權測試人員以攻擊者思維驗證系統弱點可利用性與實際衝擊之測試活動。
弱點驗證 確認掃描或測試發現是否真實存在、可利用、影響範圍與風險等級之活動。
重新測試 / Retest 弱點修復後確認修正有效且未引入新問題之測試。
安全閘門 在CI/CD或發布流程中阻擋未達安全要求之程式、設定或交付物進入下一階段之控制。
AI安全測試 針對AI應用、模型API、RAG、Prompt、AI Agent與模型供應鏈之專項安全測試。

測試類型 適用情境 最低要求 輸出證據
SAST 新程式碼、重大變更、PR、Release前。 正式系統應納入Pipeline或定期掃描。 SAST報告。
DAST Web、API、對外服務、測試環境或預備環境。 Release前與重大變更後執行。 DAST報告。
SCA 所有使用開源或第三方套件之專案。 識別CVE、授權、棄用元件與SBOM。 SCA/SBOM報告。
Secrets掃描 Repo、PR、CI/CD、Artifact、Container、Log與文件。 有效Secret命中需立即撤銷與輪替。 Secrets掃描報告。
IaC掃描 Terraform、CloudFormation、Kubernetes YAML、Helm、Ansible等。 部署前阻擋高風險錯誤組態。 IaC掃描報告。
容器映像掃描 Container Image、Base Image、Registry與部署前映像。 檢查OS套件、弱點、Root、Secrets與設定。 容器掃描報告。
API安全測試 REST、GraphQL、gRPC、Webhook與模型API。 測試認證、授權、BOLA/BFLA、Rate Limit與Schema。 API測試報告。
Mobile安全測試 行動App、SDK、行動API與本機儲存。 依風險執行靜態、動態與平台安全測試。 Mobile測試報告。
雲端組態測試 雲端帳號、VPC/VNet、IAM、KMS、Storage、DB與日誌。 CSPM/CNAPP持續監控與Release前檢查。 CSPM報告。
滲透測試 對外系統、高風險系統、重大改版、客戶或法規要求。 需授權範圍、測試窗口、報告與修復追蹤。 滲透測試報告。
AI安全測試 AI應用、RAG、AI Agent、模型API與MLOps。 測試Prompt Injection、越權、資料外洩、工具濫用與模型風險。 AI安全測試報告。

6. 安全測試觸發條件

觸發情境 必要測試 說明
新系統首次上線 SAST、SCA、Secrets、DAST/API、組態掃描，必要時滲透測試。 依資料分類與對外暴露決定深度。
重大功能變更 針對變更範圍執行SAST、DAST、API、權限與迴歸測試。 涉及身份、授權、資料、支付、AI或外部API時加強測試。
對外服務或API發布 DAST、API安全測試、WAF/API Gateway檢查、滲透測試或攻擊面掃描。 公開暴露系統需上線前確認。
雲端或IaC變更 IaC掃描、CSPM檢查、網路暴露、IAM、KMS與日誌測試。 部署前納入Pipeline。
開源元件更新 SCA、授權檢查、相容性與安全迴歸測試。 重大CVE需緊急處理。
AI模型或Prompt變更 AI安全測試、Prompt Injection測試、RAG權限測試、模型API濫用測試。 模型版本與Prompt版本需可追溯。
資安事件後 針對根因與受影響範圍執行專項測試與重測。 作為CAPA驗證。
客戶、法規或合約要求 依要求執行滲透測試、弱點掃描、第三方測試或報告提供。 需保護測試報告機密性。
定期安全驗證 依系統風險等級定期執行弱點掃描、滲透測試或控制有效性測試。 納入年度安全測試計畫。

7. 安全測試流程

階段 作業要求 責任角色 輸出證據
1. 測試需求確認 確認系統範圍、資料分類、測試類型、風險等級、測試環境、時程與Owner。 Security Testing Owner / System Owner 測試需求紀錄。
2. 測試授權與計畫 制定測試範圍、測試方式、限制、測試帳號、測試資料、窗口、通報與回復方式。 Security Testing Owner / CISO 測試計畫與授權。
3. 測試環境準備 準備測試環境、測試資料、測試帳號、白名單、監控通知與備份/回復措施。 QA / IT / SOC 環境準備紀錄。
4. 測試執行 依計畫執行自動化掃描、手動測試、專項測試或滲透測試。 AppSec / QA / Third-party Tester 測試紀錄、工具報告。
5. 結果分析與分級 排除誤報、確認可利用性、影響範圍、資料影響與風險等級。 AppSec / System Owner 弱點分析紀錄。
6. 修復與處置 弱點建立工單，指定Owner、期限、修復方式或補償控制。 Development / System Owner 修復工單、PR紀錄。
7. 重測與驗證 修復後執行重新測試，確認缺失關閉且未造成迴歸。 AppSec / QA 重測報告。
8. 風險接受或例外 無法修復或延後修復者需正式風險接受、補償控制與期限。 CISO / Risk Owner 風險接受紀錄。
9. 報告與歸檔 保存測試報告、弱點清單、修復證據、例外與管理審查資料。 Security Testing Owner / ISMS管理代表 測試報告與歸檔紀錄。

9. 測試環境與測試資料管理

管理項目 作業要求 證據
環境隔離 安全測試應優先在測試或預備環境執行，與正式資料與正式Secrets隔離。 環境架構與存取紀錄。
正式環境測試 需事前核准，限定方法、時間、強度、帳號與停止條件。 正式測試授權。
測試資料 不得使用未遮罩PII或客戶資料；必要時需Data Owner與DPO核准。 資料核准與遮罩紀錄。
測試帳號 測試帳號需具名、限定期限、限定權限，測試後停用或刪除。 帳號建立與撤銷紀錄。
測試Secrets 不得使用正式Secrets；測試Secrets需可撤銷、短效且不具正式資料存取權。 Secrets清冊與撤銷紀錄。
測試工具 測試工具需來源可信、版本受控、避免引入惡意工具或不合規授權。 工具清單與授權紀錄。
測試報告保護 測試報告含弱點細節，應加密保存並限制存取。 文件權限與保存紀錄。

10. SAST、SCA與Secrets掃描要求

測試項目 最低要求 阻擋條件 證據
SAST 正式系統Repo需於PR或Release前執行，規則應涵蓋注入、XSS、授權、加密、反序列化等。 Critical/High未修正或未接受。 SAST報告。
SCA 所有使用開源元件之專案需掃描CVE、授權、棄用與惡意套件風險。 Critical可利用弱點、禁止授權或惡意套件。 SCA報告、SBOM。
Secrets掃描 Commit、PR、Pipeline、Repo歷史、Artifact、Container與日誌需掃描Secrets。 任何有效Secret或高可信命中。 掃描報告、輪替證據。
誤報管理 誤報需由AppSec或工具Owner確認，不得由開發人員自行永久忽略高風險命中。 誤報核准紀錄。
規則維護 掃描規則需定期更新，並依內部事件、弱點趨勢與技術棧調整。 規則版本紀錄。
報告追蹤 掃描結果需納入弱點追蹤，避免僅保存工具報告未處理。 弱點工單。

11. DAST、API與滲透測試要求

測試項目 測試重點 最低要求
DAST 認證、Session、輸入驗證、XSS、注入、錯誤訊息、TLS、Header、檔案上傳。 對外Web與重要系統Release前執行。
API安全測試 認證、授權、BOLA、BFLA、Rate Limit、Schema、CORS、Webhook簽章、錯誤回應。 重要API變更需測試。
GraphQL測試 Introspection、Query Depth、Batching、授權、DoS與Schema暴露。 使用GraphQL者必要。
Mobile DAST 本機儲存、傳輸、API、憑證、Root/Jailbreak、逆向與SDK風險。 正式Mobile App必要。
滲透測試 攻擊鏈、弱點利用、權限提升、橫向移動、資料存取與業務邏輯缺陷。 高風險/對外系統至少依年度計畫或重大變更執行。
重測 針對修復項與可能受影響區域重新測試。 High/Critical修復後必要。

12. 雲端、容器、IaC與組態安全測試

測試項目 測試重點 證據
CSPM/CNAPP 公開儲存、過寬IAM、未加密、未開日誌、公開管理介面、資料庫暴露、KMS設定。 CSPM報告。
IaC掃描 Terraform、CloudFormation、Kubernetes YAML、Helm、Ansible之錯誤組態與高風險設定。 IaC掃描報告。
容器掃描 Base Image弱點、Root、Capabilities、Secrets、惡意套件、過大映像與不必要工具。 Container掃描報告。
Kubernetes測試 RBAC、Network Policy、Pod Security、Secrets加密、Admission Control、API Server暴露。 K8s安全檢查報告。
CI/CD安全測試 分支保護、Runner權限、Artifact完整性、Secret Masking、部署權限與手動繞過。 Pipeline安全檢查。
安全組態測試 作業系統、資料庫、中介軟體、端點與網路設備安全基準。 基準掃描與組態報告。

13. AI、RAG、Agent與模型服務安全測試

測試項目 測試內容 通過標準
Prompt Injection 測試使用者輸入、文件內容、RAG資料、網頁內容或工具回應是否可覆蓋系統指令。 系統能隔離指令與資料，阻擋或降低高風險輸出。
敏感資料外洩 測試模型是否洩漏System Prompt、Secrets、PII、客戶資料、內部文件或越權資料。 不得輸出未授權敏感資料。
RAG越權檢索 以不同角色、租戶或資料權限測試是否可檢索未授權文件或片段。 檢索結果需符合來源資料權限。
AI Agent工具濫用 測試Agent是否可未授權呼叫Email、檔案、系統、支付、部署、刪除或外部API。 高風險工具需白名單、人工確認與日誌。
模型API濫用 測試Rate Limit、認證、授權、Token暴增、成本異常、DoS與批量請求。 API Gateway與監控可限制濫用。
輸出安全 測試不當內容、錯誤建議、程式碼弱點、幻覺風險與合規聲明。 需過濾、提示限制、人工覆核或業務規則。
資料不訓練與保存 確認外部AI服務是否符合資料不訓練、Prompt保存、刪除與日誌設定。 設定與合約證據完整。
模型供應鏈 測試模型來源、版本、套件、容器、權重與MLOps Pipeline弱點。 模型版本可追溯且供應鏈風險受控。

14. 弱點分級與修復SLA

弱點等級 判定條件 修復期限 上線限制
Critical 可造成遠端程式執行、特權取得、重大資料外洩、身份繞過、可被公開利用、有效Secrets外洩、重大AI資料外洩或關鍵服務中斷。 立即處理，原則24至72小時內修復、隔離或停用。 不得上線；正式環境需立即升級。
High 可造成越權、敏感資料暴露、重要控制繞過、重大業務邏輯濫用、供應鏈高風險或AI工具濫用。 7至14日內修復，依風險調整。 上線前應修復或正式風險接受。
Medium 需特定條件利用，可能造成局部資料暴露、功能濫用、弱安全控制或中度合規缺口。 30至60日內修復。 可依上線風險決定是否阻擋。
Low 低風險缺陷、資訊揭露有限、最佳實務偏差或需多重條件利用。 90日內或依版本計畫修復。 通常不阻擋，但需追蹤。
Informational 無直接弱點但可改善安全設計、可維護性或防護深度。 依改善計畫處理。 不阻擋。

15. 弱點修復、重測與關閉

階段 作業要求 證據
弱點登錄 所有有效弱點需記錄等級、描述、影響、證據、Owner、期限與來源。 弱點工單或登錄表。
修復分析 開發或Owner應分析根因、修復方案、影響範圍與是否需修補相同模式。 根因分析與修復計畫。
修復實作 修復需經Code Review、測試、必要安全測試與變更管制。 PR、Commit、測試結果。
補償控制 無法立即修復者需WAF規則、權限限制、停用功能、隔離、監控或Rate Limit等控制。 補償控制紀錄。
重測 安全測試人員或授權角色確認弱點已修復，必要時執行回歸測試。 Retest報告。
關閉 只有在修復驗證通過、風險接受核准或判定誤報後方可關閉。 關閉紀錄。
防再發 針對重複缺陷更新安全編碼規範、測試規則、CI/CD閘門或教育訓練。 CAPA與規則更新。

16. 第三方測試與滲透測試管理

控制項目 最低要求 證據
測試授權 第三方測試需具書面授權、範圍、時間、限制、聯絡窗口與停止條件。 授權書、SOW。
保密與資料保護 測試人員需簽署NDA，報告、證據與資料需加密傳輸與保存。 NDA、傳輸紀錄。
測試範圍 明確列出測試URL、IP、API、帳號、環境、排除項與禁止測試項。 測試範圍文件。
測試帳號 提供最小必要測試帳號，測試後停用與密碼輪替。 帳號建立與撤銷紀錄。
SOC通知 測試前通知SOC與相關維運人員，避免誤判並保留監控資料。 通知紀錄。
報告要求 報告需包含弱點、風險等級、重現步驟、影響、證據、修復建議與管理摘要。 第三方測試報告。
修復追蹤 第三方發現需納入內部弱點追蹤並執行重測。 修復與重測紀錄。
工具與攻擊限制 禁止未核准DoS、大量資料下載、破壞性操作、社交工程或越界測試。 測試規則。

17. 安全測試報告最低內容

報告章節 內容要求 備註
管理摘要 測試目的、範圍、整體風險、重大發現、是否建議上線。 供管理階層與Owner閱讀。
測試範圍 測試系統、版本、URL、API、Repo、雲端資源、AI模型或排除項。 不得含不必要Secrets。
測試方法 工具、版本、測試類型、測試期間、帳號角色與限制。 需可追溯。
弱點清單 弱點名稱、等級、影響資產、狀態、Owner、期限。 可與工單連結。
弱點詳情 重現步驟、證據、影響、根因、利用條件與修復建議。 依機密等級控管。
AI測試結果 若適用，需記錄Prompt Injection、RAG越權、Agent工具、敏感輸出與模型API結果。 AI專案必要。
誤報與限制 列出誤報、未測項目、工具限制、時間限制與假設。 避免誤解結果。
修復優先順序 依風險、可利用性、資料影響、對外暴露與合規要求提出優先順序。 作為修復計畫依據。
重測結果 記錄修復後重測、關閉、仍未解決或風險接受項目。 最終歸檔必要。

18. 安全測試例外管理

例外情境 最低要求 核准層級 期限與重評
