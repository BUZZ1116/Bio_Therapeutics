1. 作業目的

本作業指導書規範組織時間同步之架構、來源、設定、監控、容錯、變更、事件處理、供應商管理、日誌證據與稽核要求，確保所有關鍵系統、資訊安全控制、日誌平台、雲端服務、端點、網路設備、AI/MLOps平台及數位證據之時間戳具有一致性、可靠性、可追溯性與法律/稽核可用性。

準確且一致之時間是身份驗證、憑證驗證、事件偵測、日誌關聯、稽核追蹤、交易紀錄、備份復原、取證時間線、AI模型版本追蹤、供應商事件比對及根因分析之基礎。若時間不同步，可能造成事件調查困難、證據可信度不足、交易紀錄錯誤、告警關聯失準、憑證驗證失敗及合規缺失。

2. 作業原則

  • 所有重要系統應同步至組織核准之時間來源，不得任意使用未核准外部NTP來源或本機手動時間。
  • 時間同步架構應具備分層、備援、監控、權限控管與變更管制，避免單點失效或惡意時間竄改。
  • 正式環境、安全設備、日誌平台、SIEM、IAM、PAM、雲端服務、資料庫、備份系統與事件取證設備應列為高優先同步對象。
  • 所有日誌與證據應記錄時區、時間來源或能對應至標準時間，以支援跨系統、跨區域、跨雲端與跨供應商事件分析。
  • 時間偏移、同步失敗、時間來源異常、手動調整、NTP服務變更或跨系統時間不一致，應依風險觸發告警與處置。
  • 時間同步不得取代日誌完整性、存取控制、事件監控與證據保全；應與日誌、監控、備份、事件管理及數位證據保存控制整合。

3. 名詞與定義

名詞 定義
時間同步 使系統、設備、應用、日誌與平台之時間與核准標準時間來源保持一致之控制活動。
NTP Network Time Protocol，常用於網路設備與系統之時間同步協定。
PTP Precision Time Protocol，適用於需更高精度之環境或特殊設備之時間同步協定。
Stratum NTP時間來源層級，表示與參考時鐘之距離。
時間來源 系統用以同步時間之內部或外部參考來源，如內部NTP、雲端時間服務、GPS或受信任公共時間服務。
時間偏移 系統時間與標準時間來源間之差距。
時間漂移 系統時間因時鐘誤差、資源負載、虛擬化、網路延遲或設定異常逐漸偏離標準時間之現象。
日誌關聯 將多個系統、設備與應用日誌依時間戳關聯，以支援事件偵測與調查。
取證時間線 依可靠時間戳建立事件發生順序、操作紀錄與證據脈絡之分析結果。
UTC Coordinated Universal Time，協調世界時，建議作為跨區域系統、雲端及日誌標準時間基準。
Leap Second 閏秒，可能影響時間同步與事件排序之特殊時間調整事件。

Cloud Security Owner 管理雲端時間同步、雲端日誌時間戳、跨區域與多雲時間一致性。 雲端設定與日誌證據。

System / Application Owner 確保所屬系統、應用、資料庫、容器、API與日誌使用核准時間來源。 系統設定與測試紀錄。
DevSecOps / MLOps Owner 確保CI/CD、模型訓練、模型版本、Artifact、Pipeline與AI/RAG平台時間戳一致。 Pipeline與MLOps日誌。
Supplier / SaaS Owner 確認供應商、SaaS與代管平台具備可靠時間同步與日誌時間戳證據。 供應商證據與合約要求。
Internal Auditor 抽查時間同步架構、設定、監控、偏移處理、事件證據與控制有效性。 稽核底稿、稽核發現。

Low 非關鍵實驗環境、隔離沙箱、短期測試環境。 應使用核准來源或與相關測試環境一致。 依測試目的設定。

Supplier/SaaS 供應商代管系統、SaaS、雲端安全平台、第三方日誌來源。 需取得時間同步與時區處理證據。 應能與組織事件時間線合理關聯。

6. 時間同步架構要求

架構項目 最低要求 高風險加強要求
核准時間來源 應定義內部主時間來源、備援來源與外部受信任來源。 關鍵環境採多來源比對與層級化NTP架構。
內部NTP服務 組織應提供受控內部NTP或等效時間同步服務。 正式與關鍵系統不得直接使用任意公共NTP。
備援與可用性 時間來源應具備至少兩個可用來源或備援機制。 跨資料中心、跨雲或跨區域部署備援。
網路限制 NTP/PTP流量應限制來源與目的，禁止未核准時間服務對外或對內提供。 使用ACL、防火牆與監控限制NTP濫用。
身份與管理 時間伺服器管理需MFA、PAM/JIT、最小權限與變更管制。 關鍵時間伺服器管理操作需Session Recording。
組態基準 伺服器、網路設備、端點、雲端與容器平台應依組態基準設定時間同步。 以Configuration as Code或MDM/GPO集中控制。
監控告警 需監控同步狀態、偏移值、來源可用性、服務停止與手動變更。 Critical系統需即時告警與自動升級。
時區標準 跨區域系統與集中日誌建議使用UTC保存時間戳，顯示層可轉換本地時區。 事件證據需保留原始時區與轉換基準。

7. 時間同步作業流程

階段 作業要求 責任角色 輸出證據
1. 範圍識別 識別需時間同步之系統、設備、應用、雲端、SaaS、AI平台與日誌來源。 Time Synchronization Owner / System Owner 同步範圍清冊。
2. 風險分級 依系統重要性、日誌用途、交易影響、事件證據與合規要求分級。 CISO / System Owner 分級紀錄。
3. 架構設計 設計時間來源、NTP/PTP層級、備援、網路限制、監控與例外機制。 Infrastructure / Network Security 時間同步架構。
4. 設定部署 依組態基準設定伺服器、設備、端點、雲端與應用時間來源。 IT Operations / Cloud Owner 設定紀錄。
5. 驗證測試 驗證時間來源、偏移、時區、日誌時間戳與告警功能。 SOC / System Owner 測試紀錄。
6. 上線監控 同步服務上線後持續監控偏移、失敗、變更與來源可用性。 SOC / Infrastructure 監控報告。
7. 異常處理 發現偏移、失敗、手動改時或來源異常時，依等級處理與通報。 SOC / Incident Response 異常處理紀錄。
8. 定期審查 定期審查時間來源、同步覆蓋率、偏移趨勢、例外與稽核證據。 ISMS代表 / Time Owner 審查紀錄。
9. 退場清理 系統或時間來源退場時，移除設定、更新清冊與依賴系統。 System Owner / Infrastructure 退場紀錄。

8. 系統類型時間同步設定要求

系統類型 設定要求 驗證方式
Windows伺服器與Domain Controller 應使用企業AD時間層級或核准NTP來源；Domain Controller需特別管理。 w32tm狀態、事件日誌、GPO設定。
Linux/Unix伺服器 應使用chrony、systemd-timesyncd、ntpd或核准工具同步至內部時間來源。 timedatectl、chronyc、ntpq狀態。
網路設備 Router、Switch、Firewall、VPN、WAF、Proxy、DNS/DHCP設備應設定核准NTP來源。 設備NTP狀態與日誌。
安全設備 SIEM、EDR、NDR、IDS/IPS、PAM、DLP、CASB與SOC工具應同步並監控偏移。 平台健康檢查與告警。
資料庫 資料庫伺服器與交易系統應與應用、日誌、備份平台時間一致。 DB時間查詢與系統時間比對。
虛擬化平台 Hypervisor、VM、管理平台應避免Host/Guest時間衝突並使用核准來源。 Host/Guest時間比對。
容器與Kubernetes Node、Control Plane、容器日誌、Ingress、Service Mesh需與Host時間一致。 Node時間、Pod日誌比對。
雲端服務 IaaS/PaaS/SaaS需使用雲端核准時間來源或服務預設可靠時間。 雲端文件、配置與日誌比對。
端點與行動裝置 受管理端點應透過MDM、AD、OS服務或企業網路同步。 MDM/EDR報告。
AI/MLOps平台 訓練、推論、模型Registry、Pipeline、Notebook、RAG與向量庫需時間一致。 Pipeline與模型版本日誌比對。

9. 時間偏移與告警門檻

系統等級 偏移門檻建議 告警要求 處置時限
Critical 大於5秒需告警；大於30秒需升級處理。 即時告警至SOC與System Owner。 原則4小時內修復或提出暫時措施。
High 大於30秒需告警；大於2分鐘需升級。 告警至維運與SOC。 原則1個工作日內修復。
Medium 大於60秒至5分鐘需告警或列入健康檢查。 定期報告或自動告警。 原則5個工作日內修復。
Low 依測試目的設定，偏移不得影響日誌與測試結論。 定期檢查。 依專案時程處理。

SaaS/供應商 供應商日誌時間若無法與組織時間關聯需列缺口。 通知SaaS Owner與Supplier Owner。 依合約或風險處理。

13. 時間同步變更管理

變更類型 管理要求 核准層級 驗證
新增時間來源 需評估可信度、可用性、網路路由、安全設定與相依系統。 Time Owner / CISO視風險 同步測試與偏移監控。
變更NTP/PTP伺服器 需變更申請、影響評估、測試、回復方案與通知。 Infrastructure Owner / Change Manager 多系統時間比對。

雲端區域或時區變更 需確認日誌解析、SIEM欄位、備份排程與交易時間影響。 Cloud Owner / SOC 日誌解析測試。
供應商日誌格式變更 需確認匯入SIEM、時區、時間戳欄位與事件關聯不受影響。 SaaS Owner / SOC SIEM解析驗證。
緊急修正 時間偏移影響事件或服務時可緊急處理，事後補變更與根因分析。 Incident Manager / CISO 緊急變更紀錄。

14. 時間同步異常處理

異常類型 判定條件 處置要求
時間偏移超過門檻 系統時間與核准來源偏移超過設定門檻。 確認來源、網路、服務、主機負載，修正並記錄偏移期間。
NTP服務不可用 主要或備援時間來源無法連線或服務停止。 切換備援，調查服務健康與網路規則。
時間來源不一致 不同NTP來源回傳時間不一致。 停用可疑來源，檢查外部時間來源與內部層級。
手動改時 發現系統時間被手動修改或不明變更。 調查操作者、原因、影響，必要時啟動事件。
虛擬機時間漂移 VM因Host設定、快照、暫停或負載造成漂移。 檢查Host/Guest同步策略並修復。
日誌時間錯亂 SIEM事件排序異常或跨系統時間線不合理。 確認日誌來源時間、時區、接收延遲與解析規則。
憑證/Token時間錯誤 憑證驗證、Kerberos、JWT、SAML、OAuth因時間錯誤失敗。 優先修復身份系統與相關主機時間。
AI Pipeline時間錯誤 模型版本、資料集、Pipeline或RAG更新時間不一致。 暫停發布或標註偏移，重建可信時間線。
疑似時間竄改攻擊 時間來源被冒充、NTP Spoofing、惡意修改或繞過監控。 啟動事件管理，封鎖來源並保存證據。

18. 例外管理

例外情境 最低要求 核准層級 期限與重評

需手動調整時間 需核准、記錄原因、操作者、調整前後時間、影響範圍與事件註記。 System Owner / CISO視風險 單次核准。
日誌平台時區無法統一 需明確標示時區、建立解析規則、測試事件關聯與保存轉換規則。 SOC Owner / CISO 最長180日。
