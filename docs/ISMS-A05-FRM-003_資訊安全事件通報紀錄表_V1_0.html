0.1 表單填寫與使用說明

本表為資訊安全事件自發現、通報、初步評估、分級、升級、處理、證據保存、溝通、結案與後續改善之完整紀錄。填寫人應以事實為基礎，不得刪改原始證據，不得自行對外揭露事件內容，並應依事件嚴重度、資料分類、法規合約、客戶要求與管理程序完成通報及升級。

使用時點 填寫責任 最低填寫要求 管制重點
事件發現或疑似事件發生時 發現者 / 第一線主管 / Service Desk / SOC 完成事件基本資料、發現時間、通報來源、初步描述、影響系統、初步證據與聯絡方式。 不得延遲通報；不得自行刪除郵件、日誌、檔案或重新安裝系統。
SOC或事件經理受理後 SOC / Incident Manager 補充事件編號、初判類型、嚴重度、影響範圍、升級狀態、處理負責人與初步處置。 所有處理動作需可追溯；重大事件需建立事件戰情室或等效協調機制。
事件調查與處理期間 事件處理小組 / System Owner / Data Owner 持續記錄時間軸、證據、遏止、根除、復原、溝通、外部通報與決策。 保存證據鏈；重大決策需具核准紀錄。
事件結案前 Incident Manager / CISO / Data Owner / DPO / 法務 完成根本原因、處理結果、剩餘風險、矯正措施、經驗學習與結案核准。 不得於證據不完整、風險未評估或法規通報未完成前結案。

3. 初步嚴重度與優先順序判定

嚴重度 判定條件 範例 通報與處理時限
S1 重大 / 危機級 造成或可能造成重大營運中斷、大量敏感資料外洩、重大法規通報義務、重大客戶/媒體/公共影響、核心系統遭入侵、勒索軟體擴散。 核心服務停擺、大量PII外洩、雲端管理帳號遭入侵、備份同步遭破壞。 立即通報CISO與最高管理階層；15分鐘內啟動重大事件機制；依法規/合約期限外部通報。
S2 高 影響重要系統、重要客戶、機密資料或需跨部門處理，存在擴散或合規風險。 特權帳號異常登入、機密資料誤傳外部、重要SaaS服務安全告警。 1小時內通報CISO/Incident Manager；4小時內完成初步評估與遏止方案。
S3 中 影響局部系統、少量資料或單一部門，暫無重大外部影響，但需正式追蹤。 單一端點惡意程式、單一郵件帳號遭釣魚、局部DLP告警。 1個工作日內完成受理與初判；依程序完成處理與結案。
S4 低 低影響資安異常、誤報、教育訓練或流程改善事項。 低風險釣魚測試通報、未造成影響之政策違規。 依一般工單處理，納入趨勢分析與教育訓練。
