1. 作業目的

本作業指導書用於規範專案生命週期中資訊安全、隱私、AI治理、供應鏈、雲端、營運持續與合規控制之導入、審查、驗證與保存方式，確保專案自立案至結案皆能依風險導向原則設計、執行與驗證必要控制。

本作業指導書之目標在於將資訊安全要求前移至專案初期，避免於上線前才發現重大控制缺口，並確保專案輸出可被稽核、可追溯、可移交、可維運、可持續改善。

2. 作業原則

  • 所有專案均應依專案風險分級決定資安審查深度，不得以時程、成本或便利性規避必要資安控制。
  • 涉及機密資訊、PII、客戶資料、AI系統、雲端服務、供應商、關鍵營運、跨境傳輸或GHG/CO2資料之專案，應完成專項審查。
  • 專案各階段應保留可稽核證據，包括需求、風險、設計、開發、測試、弱點修補、變更、驗收、上線與移交紀錄。
  • 高風險缺口或未完成控制不得逕行上線，除非取得正式例外、補償控制、剩餘風險接受與管理階層核准。

3. 名詞與定義

名詞 定義
專案 為達成特定業務、技術、產品、流程、合規、資安或治理目標而建立之一次性或階段性工作。
專案資安管理 於專案生命週期中規劃、執行、驗證及監督資訊安全、隱私、AI、供應鏈與營運持續控制之活動。
Secure SDLC 將安全需求、威脅建模、安全設計、安全開發、安全測試與安全維運整合於軟體生命週期之方法。
安全閘門 專案在進入下一階段前必須完成之資安條件、審查或核准點。
高風險專案 涉及高機密資料、PII、大量資料、雲端、AI、關鍵流程、外部連線、第三方或重大合規要求之專案。
專案Owner 對專案成果、風險、資源、決策與交付品質負最終責任之角色。
System Owner 對系統、平台、服務或技術資產之運作、控制、風險與維護負責之角色。
Data Owner 對資料分類、授權、使用限制、保護要求與保存刪除負責之角色。
Control Owner 對特定控制措施設計、執行、證據與有效性負責之角色。
Go-Live 專案成果正式上線、啟用、對內外部使用者開放或移交營運之活動。

5. 專案資安分級準則

分級 判定條件 最低資安要求 核准層級
Level 1 低風險 不處理機密/PII，不涉及外部連線、雲端、AI、供應商或關鍵流程。 基本資安需求檢核、Owner確認、結案保存。 專案Owner / ISMS代表抽查
Level 2 中風險 涉及內部資料、一般系統變更、少量外部連線或非關鍵SaaS。 資安需求檢核、基本風險評估、權限與日誌設計、上線檢核。 System Owner / ISMS代表
Level 3 高風險 涉及機密資料、PII、客戶資料、雲端、供應商、API、行動應用或重要流程。 完整風險評估、安全設計審查、弱點掃描、DPIA/DPA（如適用）、Go-Live核准。 CISO / 專項Owner
Level 4 極高風險 涉及高機密、大量PII、AI高影響用途、關鍵營運、跨境、重大合規、核心平台或高可用需求。 威脅建模、架構審查、滲透測試、BCP/DR審查、剩餘風險接受、管理階層核准。 CISO / 最高管理階層授權代表

Secrets管理 禁止將密碼、金鑰、Token、憑證硬編碼或提交至Repo。 Secret Scanning報告。
相依元件管理 使用SCA檢查開源元件、授權、弱點與維護狀態。 SCA報告、SBOM。
安全建置管線 CI/CD需具權限控管、簽章、掃描、審批、部署日誌與回復能力。 Pipeline紀錄。
測試資料保護 測試環境不得使用未遮罩之正式PII或高機密資料。 測試資料核准與遮罩紀錄。
容器與IaC安全 容器映像、IaC、Kubernetes、雲端組態需掃描與基準檢查。 容器/IaC掃描報告。

測試類型 適用時機 最低要求 輸出證據
SAST 開發中與Merge前。 高風險弱點不得進入正式分支，例外需核准。 SAST報告、修補紀錄。

Critical / 極高 立即處理，原則上不得超過7日。 未修補不得上線，除非CISO核准。 需風險接受、補償控制與重評日期。
