1. 文件定位

本報告用於ISMS第一階段文件審查，重點在確認文件化資訊、流程架構、稽核準則與必要客觀證據是否足以支持後續現場或遠端稽核。

第一階段文件審查不是條款符合性的最終結論，而是對ISMS文件充分性、可追溯性、現場稽核準備程度及需補件事項的判定。若文件不足以支持稽核目的，Audit team leader應要求補件、調整稽核計畫或延後後續稽核活動。

4. ISMS文件充分性審查表

ISO/IEC 27001條款 / 流程 文件審查重點 充分性判定準則 可能需現場確認事項
4.1 組織全景 內外部議題、氣候變遷相關性、資料來源、更新頻率與ISMS影響。 議題不是一次性清單，能連結風險、目標、變更、管理審查與流程控制。 訪談管理系統代表與流程Owner，確認議題如何影響日常控制。
4.2 利益相關方 關注方、法規、供應商、投資人、氣候/碳資料等要求是否被識別、轉換與更新。 要求清冊能連結合約審查、設計輸入、供應商要求、放行與資訊安全事件、申訴或通報。 抽查合約、資訊安全事件、申訴或通報、法規更新與要求轉換紀錄。
4.3 / 4.4 ISMS範圍與流程 ISMS範圍、外包流程、不適用理由、流程輸入輸出、責任、準則、KPI與文件化資訊。 流程互動清楚，且每一核心流程有Owner、準則、輸出與監督方式。 沿一筆訂單、專案、服務或不符合案件追溯流程。
5.1 / 5.2 / 5.3 領導 政策、資訊安全目標方向、角色責任、關注方焦點、治理會議與RACI。 最高管理階層承諾可由資源、決策、政策、目標及管理審查證據支持。 訪談最高管理階層、管理系統代表與流程Owner。
6.1 / 6.2 / 6.3 規劃 風險與機會、資訊安全目標、變更規劃、Risk owner與行動追蹤。 風險、目標、變更與資源有連動，且能說明控制措施與預期結果。 抽查風險處理計畫、目標達成追蹤與變更案件。
7.1至7.5 支援 人員、基礎設施、環境、量測資源、組織知識、能力、認知、溝通與文件化資訊。 支援資源能覆蓋ISMS運作與8章生命週期需求，並保留適當紀錄。 抽查能力評估、量測資源、文件庫、保存期限與溝通紀錄。
8.1至8.7 運作 需求、設計、外部供應者、生產/服務提供、放行、不符合輸出與變更控制。 每項運作要求都有程序、表單、清冊或紀錄可支持，並能追溯至資訊、資產、系統與服務符合性。 依資訊、資產、系統與服務生命週期抽樣，確認文件和實際操作一致。
9.1 監督、量測、分析與評估 KPI/KRI、量測描述子、資料來源、分析、解釋、報告與未達標行動。 量測不是只列指標，應能說明資料來源、公式、頻率、Owner與管理用途。 抽查KPI報告、資料來源、異常分析與改善連結。
9.2 內部稽核 稽核方案、稽核計畫、稽核紀錄、發現、跟催與稽核員適任性。 稽核方案依流程重要性、風險、變更及前次結果規劃，且發現能形成跟催。 抽查稽核報告、客觀證據、發現追蹤與稽核員評估。
9.3 管理審查 輸入資料、輸出決策、資源、改善、政策、目標、風險與變更。 管理審查有完整輸入與可追蹤輸出，不只是會議紀錄。 確認決議是否進入行動追蹤、資源與改善計畫。
10.2 / 10.3 改善 不符合事項發現、修正、根因、矯正措施、有效性、改善與標準化。 CAPA能證明根因分析、措施、結果紀錄、有效性確認與防止再發。 抽查不符合案件、資訊安全事件、申訴或通報、KPI異常與重複問題。

5. 文件審查結論判定

結論 判定條件 後續要求
文件充分，可進入現場稽核 核心文件完整、受控且可支持流程抽樣；
不影響稽核目的之小缺漏可於現場確認。		 更新稽核計畫、抽樣方向與訪談安排。
部分充分，補件後進入 部分文件缺漏、不一致或證據不足，但可於期限內補足且不改變稽核目的。 列出補件要求、責任人與期限，補件後由Audit team leader確認。
不充分，需延後稽核 ISMS範圍、流程、關鍵文件、運作紀錄、內部稽核或管理審查證據不足以支持稽核。 延後後續稽核，要求文件修訂、補正證據或管理階層決策。
需調整稽核計畫 文件顯示範圍、流程、風險、場所、供應商、資訊、資產、系統與服務或稽核準則與原計畫不同。 修訂稽核範圍、人天、稽核員能力需求、抽樣策略與受訪者安排。
