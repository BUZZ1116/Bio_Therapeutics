1. 作業目的

本作業指導書規範組織容量管理之需求識別、容量基準建立、監控、告警、趨勢分析、預測、擴充、調校、雲端配額、成本治理、效能管理、供應商容量、AI/GPU資源管理、能源效率、營運持續、事件處理、例外管理、稽核與持續改善要求，確保資訊系統與相關ICT服務具備足夠、適切且可持續之資源，以支援服務可用性、資訊安全、業務成長、客戶承諾、RTO/RPO、SLA/SLO及法規/合約要求。

容量不足或資源耗盡可能導致服務中斷、交易失敗、日誌遺失、監控失效、備份失敗、安全工具停擺、資料損毀、AI模型服務延遲、成本暴增或事件回應能力下降。因此，本文件要求容量管理必須與資產管理、變更管理、備援管理、備份還原、效能監控、弱點修補、供應商管理、雲端FinOps、AI/MLOps治理及營運持續流程整合。

2. 作業原則

  • 容量管理應以業務需求、服務重要性、使用趨勢、SLA/SLO、RTO/RPO、資料成長率、風險評估與成本效益為基礎。
  • 容量監控應涵蓋運算、記憶體、儲存、資料庫、網路、連線、Queue、API、日誌、備份、授權、雲端配額、GPU、AI推論與供應商服務限制。
  • 容量告警與擴充計畫應具備提前量，避免在資源耗盡或服務中斷後才採取行動。
  • 容量擴充、縮減、配額調整、架構改變或成本優化不得降低安全控制、備援能力、日誌保存、資料保護或合規要求。
  • 雲端容量應同時考量可用性、配額、保留容量、成本、碳排、區域限制、供應商SLA與資料主權。
  • AI/MLOps容量應同時考量GPU/加速器可用性、推論延遲、Token/Rate Limit、資料管線、向量庫、模型版本、能源效率與濫用風險。

3. 名詞與定義

名詞 定義
容量管理 規劃、監控、分析、預測與調整資訊系統資源，以確保服務容量符合業務、可用性、安全與成本要求之管理活動。
容量基準 系統在正常、尖峰與異常情境下之資源使用基準，例如CPU、記憶體、儲存、吞吐量、連線數、延遲、IOPS、GPU使用率等。
容量門檻 用於觸發告警、調查、擴充、調校或風險接受之資源使用率、延遲、錯誤率或配額門檻。
容量預測 依歷史趨勢、業務計畫、專案需求、季節性、事件、行銷活動或模型負載預估未來容量需求。
容量瓶頸 限制服務效能、可用性或擴展能力之資源、架構、程式、資料庫、網路、配額、授權或供應商限制。
SLA/SLO 服務水準協議與服務水準目標，常含可用性、延遲、吞吐量、支援時效與容量承諾。
Autoscaling 依負載自動擴充或縮減資源之機制。
Quota / 配額 雲端、SaaS、API、GPU、儲存、帳號、授權或服務可使用資源之限制。
FinOps 雲端財務營運治理，透過可視化、最佳化與責任分攤管理雲端成本與資源效率。
Overprovisioning 配置超過實際需求之資源，可能造成成本、能源與管理負擔。
Underprovisioning 資源低於實際需求，可能造成服務中斷、效能下降或安全控制失效。
AI容量 支援AI訓練、微調、推論、RAG、向量檢索、Token處理、GPU/加速器、模型Serving與MLOps流程所需資源。

Backup / Storage Owner 管理備份容量、備份窗口、不可變備份、快照、保留期限與還原容量。 備份容量報告。

AI Governance / MLOps Owner 管理AI訓練、推論、GPU、Token、向量庫、RAG、模型Serving與AI容量風險。 AI/MLOps容量報告。

5. 容量管理範圍與資源類型

資源類型 監控項目 安全與營運風險
運算資源 CPU、vCPU、核心數、負載、Thread、Process、Container Limit。 資源耗盡造成服務中斷、告警延遲或安全工具失效。
記憶體 Memory使用率、Swap、OOM、Heap、Cache、Container Memory Limit。 記憶體不足造成程序崩潰、資料損毀或服務降級。
儲存 Disk、Volume、Object Storage、Snapshot、檔案數、Inode、成長率。 磁碟滿載導致日誌遺失、資料庫停機、備份失敗。
資料庫 連線數、QPS、TPS、Lock、Index、Replication Lag、Temp Space、Tablespace。 交易延遲、鎖死、資料不一致或RPO失效。
網路 頻寬、連線數、NAT Port、VPN Session、LB連線、Packet Drop、Latency。 服務不可用、DDoS影響、遠端工作中斷。
日誌與監控 Log Ingestion、EPS、Storage、Retention、SIEM License、Alert Queue。 日誌遺失、事件偵測失效、稽核證據不足。
備份與還原 備份容量、窗口、傳輸量、成功率、還原容量、不可變保護。 備份失敗、RPO/RTO不達標、勒索復原能力不足。
雲端配額 Instance、IP、GPU、Storage、Snapshot、API Rate、VPC、LB、KMS、IAM。 配額不足造成擴充失敗或DR切換失敗。
授權與SaaS限制 使用者數、API配額、儲存量、交易量、日誌保留、Rate Limit。 合法使用、可用性與成本風險。
AI/GPU資源 GPU利用率、VRAM、Token Throughput、模型延遲、Queue、向量索引、Notebook資源。 推論延遲、訓練失敗、成本暴增、能源效率下降。
能源與碳資料 電力、PUE、GPU耗能、雲端碳足跡估算、資源閒置率。 成本、永續目標與ESG資料完整性風險。

6. 容量管理作業流程

階段 作業要求 責任角色 輸出證據
1. 容量需求識別 依業務計畫、服務等級、專案、上線、季節性、法規、備援、AI需求與歷史趨勢識別容量需求。 Service Owner / Capacity Owner 容量需求紀錄。
2. 資產與服務盤點 識別服務依賴之運算、儲存、資料庫、網路、雲端、SaaS、AI與供應商資源。 System Owner / Asset Owner 容量清冊。
3. 容量基準建立 建立正常、尖峰、異常與災難復原情境下之容量基準。 Capacity Owner / SRE 容量基準報告。
4. 門檻與告警設定 設定警示、警戒、重大與緊急門檻，並與SOC/ITSM整合。 Monitoring Owner / SOC 監控與告警設定。
5. 趨勢分析與預測 依使用率、成長率、業務事件、成本、配額與容量風險進行預測。 Capacity Owner / FinOps 容量預測報告。
6. 擴充或調校計畫 提出擴容、縮容、架構調整、查詢調校、快取、配額提升或供應商升級方案。 Technical Owner / Service Owner 容量改善計畫。
7. 變更與核准 容量調整需依變更流程、風險評估、測試、回復與安全審查執行。 Change Owner / CISO視風險 變更紀錄。
8. 實施與驗證 執行容量調整後，驗證效能、可用性、安全控制、成本與監控。 IT / SRE / Security 驗證紀錄。
9. 事件處理 容量告警、耗盡、配額不足或效能瓶頸造成風險時，依事件或問題管理處理。 SOC / Incident Owner 事件與問題紀錄。
10. 管理審查 定期提交KPI/KRI、重大風險、例外、預算、改善與資源需求。 ISMS代表 / Capacity Owner 管理審查紀錄。

7. 容量分級與監控要求

等級 適用情境 監控要求 處置要求
Critical 關鍵業務系統、身份服務、SIEM/SOC、備份、資料庫、支付、客戶服務、AI正式推論。 即時監控、24x7告警、容量預測、DR容量驗證。 門檻超標即升級，需有擴充或降載Runbook。
High 重要內部服務、正式API、核心資料平台、重要SaaS、雲端網路與安全平台。 持續監控、日/週趨勢分析、告警整合ITSM。 超標需於SLA內處理並追蹤改善。
Medium 一般內部服務、UAT、一般開發平台、部門系統。 定期監控與月度趨勢。 依風險與需求調整。
Low 短期測試、低影響實驗或可重建環境。 基本監控或成本/配額監控。 可接受較長處理時間。
AI High Capacity GPU叢集、模型服務、RAG/向量庫、Notebook平台、批次訓練平台。 GPU/VRAM、Queue、延遲、Token、Rate Limit、能耗與成本監控。 需管理調度、配額、優先序與濫用偵測。
Supplier Critical 供應商或SaaS支援Critical/High服務。 取得SLA、用量、配額、限制、事件與容量證據。 容量限制需納入風險與退場/替代方案。

8. 容量門檻與告警設定建議

資源項目 警示門檻 重大門檻 緊急門檻 處置要求

Cloud Quota 使用率超過70% 超過85% 擴充/DR失敗 提前申請配額、保留容量或架構調整。
GPU / VRAM 持續超過70% 超過85% Queue爆量、推論超時或訓練失敗 調度、擴容、模型最佳化或降級策略。
API Rate Limit 使用率超過70% 超過85% 限流、請求失敗或SLA受影響 申請提高、節流、快取或替代路徑。

DR與備援容量 確認備援站點、跨區域、不可變備份與災難復原所需容量。 DR容量驗證。
雲端配額規劃 提前申請或保留雲端配額、GPU、IP、LB、KMS、Storage與API限制。 配額計畫。
成本與預算 容量規劃需與FinOps、預算、成本中心與成本異常偵測整合。 容量成本預算。
能源與碳影響 高耗能系統與AI/GPU資源需評估能源效率、利用率與碳資料。 能源效率評估。
風險與例外 無法如期擴容、成本限制、供應商限制或技術瓶頸需登錄風險。 風險登錄與改善計畫。

10. 容量擴充、縮減與調校要求

作業類型 作業要求 安全注意事項
垂直擴充 增加CPU、Memory、Storage或GPU等單機資源。 需確認停機窗口、回復方案與授權影響。
水平擴充 增加節點、Pod、Instance、Replica或工作程序。 需確認Load Balancer、Session、日誌、權限與網路規則。
自動擴展 設定Autoscaling、HPA/VPA、Auto Scaling Group或Serverless concurrency。 需設定上限、成本保護、安全基準與事件告警。
資料庫調校 Index、查詢、連線池、Partition、Vacuum、Archive、Cache與Read Replica。 不得以關閉日誌、弱化權限或刪除稽核資料換取效能。
儲存擴充 Volume、Object Storage、Snapshot、Backup Repository與Archive擴充。 需維持加密、版本控制、不可變保護與存取控制。
網路擴充 頻寬、Load Balancer、VPN、NAT Gateway、Proxy、WAF與DNS容量調整。 需維持安全檢查、監控與網路區隔。
雲端配額提升 申請Instance、GPU、Storage、IP、KMS、API與服務限制提升。 需避免過度授權與成本失控。
容量縮減 關閉閒置資源、降規、壓縮保存、降低副本數。 不得影響RTO/RPO、安全日誌、備援與合規保存。
AI模型最佳化 模型量化、批次、快取、蒸餾、動態路由、Rate Limit與推論佇列管理。 需驗證模型品質、資料安全與濫用防護。

保留容量 對穩定Critical/High負載評估保留Instance、Savings Plan或承諾使用。 保留容量評估。
閒置資源治理 定期識別未使用Volume、Snapshot、IP、Load Balancer、Instance與測試資源。 閒置資源清理紀錄。
標籤與成本中心 雲端資源應具Owner、服務、環境、資料分類、成本中心與生命週期標籤。 雲端標籤合規報告。
跨區域容量 DR或多區域服務需確認目標區域容量、配額、網路與KMS可用性。 DR容量檢查。
自動擴展成本上限 Autoscaling需設定上限、Budget、告警與濫用偵測。 Auto Scaling與Budget設定。
日誌成本平衡 調整日誌攝取與保存不得犧牲必要安全監控與稽核證據。 日誌保留審查。
碳與能源資料 高耗能雲端工作負載與AI/GPU需追蹤利用率與碳足跡資料來源。 碳足跡報告或供應商資料。

12. 資料庫、儲存、日誌與備份容量要求

領域 容量要求 風險控制
資料庫 監控資料成長、Tablespace、Temp、Index、連線、慢查詢、Replication Lag。 避免因磁碟滿或Lock造成資料損毀與服務中斷。
資料倉儲/資料湖 監控儲存量、查詢成本、Partition、資料保留、資料品質與資料生命週期。 防止成本失控、資料保留過久與未分類資料膨脹。
檔案與物件儲存 監控物件數、版本、Bucket大小、Lifecycle、共享區與暫存區。 避免版本失控、公開分享與保存期限違反。
日誌平台 監控EPS、GB/day、Queue、Indexer、Search Head、授權、保留與冷熱儲存。 確保資安事件期間不遺失關鍵日誌。
SIEM/SOAR 容量需支援尖峰事件量、攻擊期間告警量、保留期限與查詢效能。 避免告警丟失、延遲與事件關聯失效。
備份平台 監控備份容量、窗口、失敗率、去重率、不可變空間、還原容量。 維持RPO/RTO與勒索復原能力。
快照與Replica 控制Snapshot數量、版本、跨區副本、保留策略與成本。 避免快照過度成長與舊資料殘留。
Archive Archive資料需明確保存期限、檢索需求、成本、加密與刪除策略。 避免不可控長期保存與法規風險。

13. AI、MLOps、GPU與模型服務容量要求

場景 容量管理要求 安全與治理要求
模型訓練 監控GPU/TPU、VRAM、Storage、Dataset I/O、Network、Checkpoint與Job Queue。 限制未核准資料、避免資源濫用與成本失控。
模型推論 監控延遲、吞吐、Token/s、並發數、Queue、錯誤率、Rate Limit與GPU利用率。 建立限流、降級、熔斷與安全輸出監控。
RAG / 向量資料庫 監控索引大小、查詢延遲、Embedding Queue、Namespace、Replica與儲存成長。 確保權限繼承、資料刪除與敏感資料保護。
Notebook平台 監控CPU/GPU、Memory、閒置Session、資料下載、套件安裝與外連。 設定配額、閒置回收、DLP與Secrets防護。
AI API供應商 監控Token用量、Rate Limit、成本、區域、SLA與故障替代方案。 確認資料不訓練、Prompt保存與供應商事件通報。
模型版本與Artifact 監控模型檔大小、版本數、Registry容量、保留策略與簽章狀態。 避免舊模型殘留、未授權模型與供應鏈風險。
GPU資源調度 建立優先序、配額、預約、閒置回收與成本分攤。 高敏感訓練工作負載應隔離與監控。
AI能源效率 追蹤GPU使用率、訓練時間、能耗、碳資料與模型效益。 與AI模型能源效率與碳資料安全文件一致。

15. 容量事件與問題管理

事件情境 判定條件 處置要求
容量耗盡 Disk滿載、DB連線耗盡、Queue爆量、Memory OOM、CPU飽和或配額達上限。 依事件等級隔離影響、擴容、降載、清理並保存證據。
日誌丟失風險 SIEM/Log平台攝取失敗、授權達上限、Queue堆積或Storage滿載。 優先保護安全關鍵日誌，升級SOC與CISO。
備份容量不足 備份失敗、不可變備份空間不足或備份窗口超時。 啟動備份風險處理與RPO/RTO影響評估。
雲端配額不足 自動擴展、DR切換或新服務部署因配額不足失敗。 申請配額、調整區域、降載或啟用替代方案。
API/Token限流 SaaS或AI服務因Rate Limit造成交易失敗或推論延遲。 節流、快取、批次、申請提升或切換替代供應商。
AI/GPU資源耗盡 GPU Queue爆量、推論逾時、訓練失敗或成本暴增。 啟動配額、優先序、降級、模型最佳化與成本告警。
容量異常暴增 可能由攻擊、資料外洩、爬蟲、惡意程式、錯誤程式或濫用造成。 SOC調查，必要時啟動資安事件。
擴容造成安全缺口 新資源未部署EDR、未加密、未納入日誌或錯誤開放網路。 立即修正或隔離，依變更/事件處理。
