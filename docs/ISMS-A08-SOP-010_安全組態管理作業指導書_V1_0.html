1. 作業目的

本作業指導書規範安全組態基準之建立、核准、部署、維護、監控、變更、偏差處理、例外核准、持續改善與稽核要求，確保系統、雲端、網路、應用、端點、資料庫、容器、AI服務及資安控制元件均以安全、可追溯、可驗證且符合風險要求之組態運作。

本文件旨在降低因預設設定、過寬權限、未加密、未啟用日誌、公開暴露、弱協定、錯誤防火牆規則、未關閉不必要服務、錯誤雲端設定、容器特權、CI/CD誤設定、AI服務資料保存不當或供應商組態變更造成之資安風險。

2. 作業原則

  • 所有重要技術資產應建立並套用核准安全組態基準，且基準應依風險、資料分類、服務重要性、法規、合約與威脅情勢定期審查。
  • 安全組態應採最小功能、最小權限、預設拒絕、安全預設、加密優先、日誌可追溯、可監控、可回復及變更受控原則。
  • 新系統、新雲端資源、新端點、新應用、新AI服務或重大變更上線前，應完成安全組態檢查，不得以未經核准之預設組態進入正式環境。
  • 安全組態偏差應被識別、分級、修正或經正式例外核准；高風險偏差不得長期存在而無風險處理。
  • 安全組態應盡可能以自動化、政策即程式碼、基礎設施即程式碼、合規掃描、CSPM/CNAPP、EDR/MDM、CI/CD檢查與組態漂移偵測實施。
  • 任何安全組態調整不得削弱資訊安全控制，例如不得為效能、成本或便利性任意關閉加密、日誌、EDR、DLP、MFA、備份、弱點掃描、監控或存取控制。

3. 名詞與定義

名詞 定義
安全組態 為降低資訊安全風險而設定於系統、設備、服務、應用、雲端或平台之安全相關設定，例如權限、加密、日誌、網路、服務、通訊協定、密碼政策、備份與告警。
安全基準 經組織核准之標準安全組態要求，通常參考CIS Benchmark、DISA STIG、供應商最佳實務、法規、合約與組織風險準則。
組態項目 CI Configuration Item，可被管理、審查、變更與追蹤之組態單元，例如伺服器、雲端資源、防火牆規則、Kubernetes設定、應用設定或AI服務設定。
組態漂移 實際組態與核准安全基準、IaC、標準映像或期望狀態不一致之情形。
基準偏差 因業務、技術或相容性原因，未能符合安全基準之設定差異。
IaC Infrastructure as Code，以程式化方式管理與部署基礎設施與雲端資源組態。
Policy as Code 以可自動化驗證之規則定義安全、合規與組態要求。
CSPM / CNAPP Cloud Security Posture Management / Cloud Native Application Protection Platform，用於偵測雲端與雲原生資源錯誤組態、風險與合規狀態之工具。
Hardening 依安全基準關閉不必要功能、限制權限、啟用保護、修補弱點與降低攻擊面之強化作業。

6. 安全組態生命週期流程

階段 作業要求 責任角色 輸出證據
1. 基準建立 依標準、供應商指南、風險評估、法規與控制目標建立安全基準。 Security Architecture / Configuration Owner 安全基準文件。
2. 基準審查與核准 由CISO、平台Owner、營運與相關角色審查可行性、風險與例外條件。 CISO / Platform Owner 核准紀錄。
3. 部署與套用 透過標準映像、IaC、MDM、GPO、CSPM、CI/CD或自動化工具套用基準。 IT / Cloud / DevSecOps 部署紀錄。
4. 上線前驗證 新系統或重大變更上線前完成組態檢查，未符合項目需修正或例外核准。 System Owner / Security Reviewer 上線前檢查紀錄。
5. 持續監控 定期掃描組態、偵測漂移、錯誤設定、控制停用與風險暴露。 SOC / Configuration Owner 合規掃描與告警。
6. 偏差處理 依風險分級建立修正計畫、期限、Owner與補償控制。 Platform Owner / Risk Owner 偏差追蹤紀錄。
7. 例外與風險接受 無法符合基準者需提出例外，說明原因、補償控制、期限與核准。 CISO / Risk Owner 例外核准、風險接受。
8. 基準更新 依威脅、弱點、事件、稽核、技術更新、法規或管理審查結果更新基準。 Configuration Owner / CISO 基準版本紀錄。

7. 安全組態基準文件最低內容

基準欄位 內容要求 備註
基準名稱與版本 明確標示平台、版本、適用範圍與基準版本。 例如 Windows Server 2022 Baseline v1.0。
適用資產範圍 說明適用環境、系統類型、風險等級與例外條件。 正式、測試、雲端、容器等。
控制目標 說明該組態要達成之安全目的。 例如降低暴力破解、資料外洩或未授權存取。
設定項目 列出必要設定、建議值、禁止值與允許範圍。 應可被驗證。
風險說明 說明若未符合該設定可能造成之風險。 便於偏差判定。
驗證方式 定義檢查工具、命令、CSPM規則、MDM報表、CI/CD檢查或人工驗證方式。 需可追溯。
修正方式 提供修正步驟、自動化腳本、IaC修正或變更要求。 避免人工任意修正。
例外條件 定義可接受例外情境、核准層級與補償控制。 不得默許長期例外。
Owner與審查頻率 指定基準Owner與定期審查週期。 高風險基準至少每年審查。

8. 核心安全組態要求

控制領域 最低組態要求 高風險加強要求
身分與存取 啟用SSO/MFA、最小權限、禁用預設帳號、強制帳號生命週期管理。 PAM/JIT、條件式存取、特權Session Recording。
管理介面 限制管理介面來源、使用安全協定、MFA、日誌與跳板或VPN/ZTNA。 管理介面不得公開網際網路，需PAM或PAW。
加密 啟用傳輸加密、儲存加密、金鑰管理與弱協定禁用。 使用KMS/HSM、BYOK/HYOK、金鑰分權與輪替。
日誌與監控 啟用登入、管理操作、權限變更、資料存取、安全事件與錯誤日誌。 接入SIEM、建立告警規則、保護日誌完整性。
網路暴露 預設拒絕，限制連接埠、來源、目的、Protocol，關閉不必要服務。 微分段、WAF、Private Endpoint、零信任存取。
惡意軟體防護 端點與伺服器啟用EDR、防惡意程式與防竄改。 高風險伺服器採行為偵測與威脅獵捕。
弱點與修補 啟用自動更新或集中修補，移除EOL元件。 Critical弱點緊急修補或隔離。
資料保護 依資料分類設定DLP、遮罩、備份、刪除與存取限制。 高機密資料需加密、不可變備份、嚴格審計。
備份與復原 啟用必要備份、版本保留、不可變備份與復原測試。 關鍵系統需跨區、離線或不可變備份。
Secrets管理 不得明文保存Secrets，使用Secrets Manager、PAM、KMS與輪替。 高權限Secrets需短期化與自動輪替。

9. 雲端安全組態要求

雲端組態項目 最低要求 驗證方式
Root / 管理帳號 Root或最高權限帳號不得日常使用，必須啟用MFA、告警與Break-glass控管。 雲端IAM檢查、CSPM規則。
IAM權限 採最小權限、Role Based Access、禁止長效高權限Access Key。 IAM Access Analyzer、權限審查。
儲存公開設定 物件儲存、檔案共享、資料湖預設不得公開。 CSPM、Storage Policy檢查。
KMS與加密 儲存、資料庫、備份與高敏感資料應啟用加密與Key管理。 KMS報表、資源設定。
網路安全 Security Group、NSG、防火牆規則應最小開放，避免0.0.0.0/0暴露管理服務。 CSPM、網路掃描。
日誌啟用 Cloud Audit Log、管理操作、網路流量、儲存存取與安全事件日誌需啟用。 Log設定、SIEM接入。
資料庫暴露 雲端資料庫不得公開網際網路，需私有網路、加密與存取限制。 CSPM、連線測試。
備份與刪除保護 關鍵資料庫、儲存與工作負載需備份、快照、刪除保護或不可變保護。 備份報表。
CSPM/CNAPP 雲端帳號應納入組態監控、風險分級、修正追蹤與例外管理。 CSPM報告。
標籤與資產Owner 雲端資源應具Owner、環境、資料分類、成本中心、服務與風險標籤。 標籤合規報告。

10. 容器、Kubernetes與雲原生組態要求

組態項目 最低要求 驗證方式
映像來源 僅使用核准Registry與可信映像，禁止未知來源與未掃描映像。 Registry政策、映像掃描。
映像弱點 映像需經弱點掃描，Critical/High弱點依SLA修正。 掃描報告。
特權容器 禁止特權容器、Host PID/Network、危險Capabilities，除非例外核准。 Admission Control、Policy as Code。
Pod安全 套用Pod Security Standards、限制Root使用者與唯讀檔案系統。 Kubernetes Policy檢查。
Kubernetes RBAC 最小權限，禁止過寬Cluster Admin，定期審查ServiceAccount。 RBAC審查報告。
Secrets管理 Kubernetes Secrets需加密，避免明文環境變數，優先外部Vault整合。 Cluster設定、Secrets掃描。
Network Policy 生產命名空間應限制Pod間通訊與外部連線。 Network Policy檢查。
API Server安全 限制API Server暴露，啟用審計日誌、強認證與版本更新。 Cluster審計報告。
IaC與Helm 部署檔需版本控管、審查、掃描與簽核。 Repo、PR、Pipeline紀錄。

11. 應用系統、API與SaaS組態要求

組態項目 最低要求 驗證方式
認證與Session 應使用核准認證機制、MFA或SSO，Session Timeout、Secure Cookie與CSRF防護需正確。 安全測試、組態檢查。
TLS與安全Header 應啟用TLS、HSTS、CSP、X-Frame-Options或等效安全Header。 DAST、Header掃描。
API安全 API需認證授權、Rate Limit、Input Validation、CORS限制、錯誤訊息控管。 API Gateway設定、安全測試。
錯誤與除錯 正式環境不得顯示詳細錯誤、Stack Trace、Debug Mode或敏感資訊。 滲透測試、組態檢查。
上傳與檔案處理 限制檔案類型、大小、掃描惡意檔案、隔離儲存與授權下載。 應用測試、WAF規則。
SaaS外部分享 預設限制外部分享、Guest Access、公開連結與下載。 SaaS管理後台報表。
SaaS Audit Log 重要SaaS需啟用審計日誌並接入SIEM或保存。 Audit Log設定。
AI功能設定 SaaS內建AI功能需確認資料使用、訓練、保存、外部分享與權限繼承。 AI服務審查、SaaS設定。

12. AI、RAG與MLOps安全組態要求

組態項目 最低要求 驗證方式
AI服務資料使用 外部AI服務應關閉或限制資料用於訓練，明確Prompt/輸入保存期限。 供應商設定、DPA、服務條款。
AI API Key AI API Key不得硬編碼，需保存於Secrets Manager並設定Scope、到期與用量監控。 Vault紀錄、API報表。
Prompt與輸出日誌 Prompt與輸出若保存，應依資料分類管控並遮罩Secrets與PII。 日誌抽查、DLP規則。
RAG資料源 RAG資料源需權限繼承、索引範圍控管、刪除同步與越權檢索測試。 RAG安全測試、權限測試。
向量資料庫 限制網路存取、加密、身分驗證、備份與刪除機制。 組態檢查、滲透測試。
AI Agent工具 工具調用需白名單、最小權限、人工確認、高風險操作禁止或審批。 Agent設定、操作日誌。
MLOps平台 模型Registry、Feature Store、Notebook、Pipeline需RBAC、Secrets管理、日誌與環境隔離。 MLOps組態報告。
模型部署 模型服務需版本控管、回滾、監控、存取控制與濫用偵測。 部署紀錄、監控報表。

13. 組態變更與漂移管理

管理項目 作業要求 證據
變更申請 安全組態變更應透過變更流程提出，記錄原因、風險、影響、測試與回復方式。 變更單。
風險審查 涉及關閉安全控制、暴露網路、擴大權限、降低加密或停用日誌者需CISO審查。 安全審查紀錄。
測試驗證 變更應於測試或預備環境驗證，確認不破壞安全控制或服務可用性。 測試紀錄。
自動化部署 基礎設施與雲端組態應優先使用IaC與Pipeline部署，避免人工直接修改。 IaC Repo、Pipeline紀錄。

變更後確認 變更完成後需確認安全掃描、日誌、告警與服務狀態正常。 變更後檢查紀錄。

14. 組態偏差分級與處理時限

偏差等級 判定條件 處理時限 處理要求
Critical 造成網際網路公開暴露、特權過寬、加密關閉、日誌關閉、資料庫公開、Secrets暴露、可被立即利用之重大錯誤組態。 立即處理，原則24小時內修正或隔離。 通報CISO，必要時啟動事件管理或風險接受。
High 可能導致未授權存取、資料外洩、橫向移動、重要服務中斷或重大合規缺口。 7日內修正或提出補償控制。 建立修正工單，逾期升級。
Medium 降低安全防護但尚無立即重大暴露，可能被結合其他弱點利用。 30日內修正。 追蹤改善與週期性報告。
Low 最佳實務偏差、文件不一致、低風險設定未符合建議值。 90日內修正或納入改善計畫。 定期追蹤。
Accepted Exception 經核准之偏差，具補償控制、期限、Owner與重評。 依核准期限。 不得無期限例外，需定期重評。

15. 安全組態例外管理

例外情境 最低要求 核准層級 期限與重評
無法套用安全基準 需說明技術限制、業務必要性、風險、補償控制與改善計畫。 CISO / Platform Owner 最長90日，高風險每30日重評。
需公開服務或管理介面 需來源限制、MFA、WAF/VPN/ZTNA、日誌、弱點掃描與攻擊面監控。 CISO / Network Owner 短期核准，定期檢查。
需停用日誌或監控 原則不允許；需替代日誌、暫時性原因與恢復期限。 CISO / SOC Owner 最長30日。
需降低加密或使用弱協定 原則不允許；若因相容性限制，需隔離、期限與替代計畫。 CISO / Legal（如涉合規） 最長90日。
需過寬權限 需最小化期間、範圍、審計與使用後撤銷。 CISO / IAM Owner 單次或短期。
供應商無法符合組態要求 需供應商風險評估、合約補償、監控與退場計畫。 CISO / Supplier Management / Legal 續約前重評。
