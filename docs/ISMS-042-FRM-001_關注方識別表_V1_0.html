1. 文件目的

本表單用於系統性識別與ISMS相關之關注方、需求與期望、合規義務、溝通要求、管理回應、風險與機會連結、控制措施對應及管理審查輸入，以確保組織能掌握並滿足與資訊安全、隱私、AI治理、GHG/CO2資料治理、雲端與ICT供應鏈相關之重要要求。

本表單是ISO/IEC 27001:2022 Clause 4.2「理解關注方需求與期望」之核心證據，並支援Clause 4.1、4.3、6.1、8.1、9.1、9.3與Annex A.5.31等條款之管理要求。

4. 識別基本資料 確認識別目的、範圍、資料來源、是否影響ISMS範圍及是否需管理審查。 識別紀錄、範圍、結論與範圍影響判定。
5. 識別小組與參與人員 確認參與角色、治理責任、能力需求與各專項Owner是否參與識別。 識別小組名單、角色分工與簽核確認。
6. 評估準則 定義關注方重要性、要求強制性、影響範圍、未滿足後果及管理優先級。 一致化評估準則與優先級判定。
7. 關注方類別與識別指引 由內外部議題、氣候變遷、AI監管趨勢及外部來源文件識別可能影響ISMS的關注方。 關注方候選清單與識別指引。
8. 關注方識別登錄表 登錄關注方名稱、關係、需求摘要、來源證據、合規義務、重要性、Owner與管理回應。 關注方識別主表與初步需求摘要。
9. 需求與期望分析表 將關注方需求轉換為要求性質、適用範圍、對應文件、控制措施、符合性狀態及證據位置。 需求與期望分析、符合性狀態及證據連結。
10. 合規義務判定表 判定需求是否形成法律、監管、合約、標準、客戶承諾或供應商義務。 合規義務判定、責任Owner、落實措施與缺口。
11. 要求影響分析表 判定要求是否影響ISMS範圍、風險評估、SoA、政策/SOP、KPI/KRI、資源能力及管理審查。 影響分析、變更評估及文件修訂需求。
12. 溝通需求與頻率表 設定與關注方溝通的內容、方式、頻率、責任人與輸出紀錄。 溝通矩陣、通報要求及溝通證據。
13. 風險與機會連結表 將關注方要求衍生之風險、機會與剩餘風險接受轉入風險管理流程。 風險/機會編號、處理方式、Owner與期限。
14. 控制措施與文件對應表 將需求對應至ISO條款、Annex A控制、內部文件、Control Owner與驗證證據。 控制措施、文件與證據對應。
15. PIMS / AI / GHG延伸關注方要求 識別資料主體、AI使用者/受影響群體、GHG查證機構、ESG利害關係者之特殊要求與證據。 PIMS、AI、GHG/CO2延伸要求與專項風險輸入。
16. 管理回應與行動追蹤表 將需求差距、文件修訂、控制補強、供應商追蹤、訓練、CAPA及管理審查事項轉為可追蹤行動。 行動追蹤、CAPA與改善證據。
17. 管理審查輸入彙整 將重大客戶、法規、供應鏈、PIMS、AI、GHG及缺口事項納入管理審查。 管理審查輸入資料與決議追蹤。
20. 附件與證據索引 確認附件、外部來源、合約、法規、碳證據、稽核與CAPA證據保存位置與保存期限。 附件索引與證據追溯。

2. 適用範圍

  • 適用於ISMS範圍內所有部門、流程、資訊資產、系統、資料、雲端服務、供應商、外包流程與客戶服務。
  • 適用於PIMS相關PII處理活動、AI治理相關AI系統與模型治理、GHG/CO2資料治理、供應鏈碳資料、資料中心與營運持續相關活動。
  • 適用於年度定期識別、重大變更、法規合約變更、新客戶/新供應商、新系統/新AI服務、內外部稽核、管理審查及外部驗證準備。

3. 名詞與定義

名詞 定義
關注方 可能影響、受影響或自認受ISMS影響之個人或組織，包括客戶、主管機關、員工、供應商、合作夥伴、股東、驗證機構、資料主體、AI使用者、GHG查證機構及社會大眾。
需求與期望 關注方對資訊安全、隱私、AI治理、GHG資料治理、營運持續、服務可用性、法規合規、合約履約、事件通報與證據提供之要求或期望。
合規義務 組織必須遵循或選擇承諾遵循之法律、法規、監管、合約、標準、政策、客戶要求、供應商條款與驗證要求。
關注方重要性 關注方對ISMS預期成果、風險、合規、營運、聲譽、客戶承諾或持續改善可能產生之影響程度。
要求Owner 對特定關注方需求與期望之識別、評估、落實、追蹤與證據保存負有責任之角色。
管理回應 針對關注方需求所採取之政策、程序、控制措施、合約條款、風險評估、溝通、訓練、CAPA或管理審查措施。
溝通要求 與關注方溝通之內容、時機、頻率、方法、責任人及紀錄要求。
