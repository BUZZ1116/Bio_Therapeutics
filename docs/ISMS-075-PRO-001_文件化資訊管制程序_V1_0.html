1. 管理意圖

本程序建立管理系統文件化資訊的共同控制方法，確保所有手冊、政策、程序、作業指導書、表單、清冊、矩陣、紀錄、報告、外部來源文件、GHG/CO2資料與互動式表單輸出，都能在需要的地點與時機取得正確版本，並受到適當保護、保存、更新、作廢與追溯。

文件化資訊控制不是行政性歸檔活動，而是支援第三方驗證、客戶與供應商審查、跨管理系統整合、營運控制、風險管理、查證 (Verification)、確證 (Validation)、稽核與管理審查的核心控制。

媒介與位置 包含紙本、HTML、PDF、Word、Excel、系統畫面、資料庫、雲端文件庫、客戶/供應商平台與備份封存。 不因媒介不同而免除版本、存取、保存與保護要求。

7. 文件化資訊分類與架構

文件類型 用途 核准與保存重點
MAN / 手冊 描述管理系統架構、範圍、治理、流程互動與整體要求。 通常由最高管理階層或授權治理角色核准。
POL / 政策 描述方向、承諾、高階要求與管理原則。 需與組織全景、策略及目標一致。
PRO / 程序書 描述某項管理活動從輸入到輸出的流程、責任、控制與證據。 應包含作業流程圖與程序步驟。
SOP / 作業指導書 描述特定工具、系統、文件庫或作業方法。 需可供實作者直接操作。
FRM / 表單 提供填寫欄位，使活動形成可稽核紀錄。 正式紀錄需完成審查、核准與保存。
REG / 清冊或登錄表 集中登錄可追蹤項目，例如文件、外部來源、風險、設備、供應商、碳證據。 需有欄位要求、Owner、狀態與審查頻率。
REC / 紀錄 證明活動已按計畫執行或結果符合要求。 需依保存期限與證據品質要求保存。
MTX / 矩陣 呈現要求、流程、角色、控制、文件或風險之對應關係。 需定期確認矩陣仍與實際流程一致。
RPT / 報告 彙整分析、績效、稽核、管理審查或改善結果。 需保留資料來源、分析邏輯與結論。

13. 風險、例外與升級規則

情境 最低處置 升級條件
未核准文件被使用 立即停止使用、確認影響範圍、替換正式版本並保留處置紀錄。 影響產品/服務符合性、顧客承諾、法規或放行時啟動CAPA。

紀錄遺失或不可讀 啟動資料復原、重新取得證據或建立替代證據說明。 涉及重大稽核證據、法律保全或碳查證時升級最高管理階層。
