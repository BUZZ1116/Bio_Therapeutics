1. 程序目的

本程序用於建立組織技術控制措施之治理、設計、導入、操作、監控、測試、有效性評估、例外管理、改善追蹤與證據保存方法，確保ISO/IEC 27001:2022 Annex A 技術控制措施（A.8.1至A.8.34）能依資訊安全風險、適用性聲明書、法規合約、業務需求、雲端與AI治理要求有效落實。

本程序同時作為技術控制措施與ISMS管理系統條款之橋接程序，使技術控制措施能支援風險處理、營運規劃、事件管理、弱點修補、存取控制、安全開發、日誌監控、AI系統安全、內部稽核、管理審查、驗證稽核與持續改善。

2. 管理原則

  • 技術控制措施應採風險導向，依資產重要性、資料分類、威脅情資、法規合約、雲端與AI依賴程度決定控制深度。
  • 所有技術控制措施應明確指定Owner、控制目標、適用範圍、操作頻率、證據、KPI/KRI與有效性驗證方式。
  • 技術控制措施不得僅停留於政策宣示，應落實為系統設定、工具部署、作業程序、監控規則、測試證據與可稽核紀錄。
  • 控制措施導入、變更、例外、停用或退場均應與風險評估、變更管理、SoA、控制措施與風險對應矩陣保持一致。
  • 涉及PII、客戶資料、高機密資料、AI模型、Prompt、RAG、雲端控制平面、特權存取或關鍵服務之技術控制應提高審查、監控與測試要求。
  • 控制措施有效性應定期檢查，發現缺失時應進入矯正措施、風險處理、剩餘風險接受或管理階層升級流程。

3. 名詞與定義

名詞 定義
技術控制措施 透過資訊技術、系統設定、軟硬體工具、自動化機制、監控平台、開發流程或技術架構所實施之資訊安全控制措施。
控制Owner 對特定控制措施之設計、導入、操作、監控、證據保存與改善負責之角色。
設計有效性 控制措施之設計是否足以降低對應風險，並具備清楚的控制目標、適用範圍、責任、頻率與證據要求。
執行有效性 控制措施是否依設計要求被實際執行、維持、監控與留下可查證紀錄。
控制有效性檢查 對控制設計、執行、證據、例外、缺失與改善成效進行定期或事件觸發式檢查。
技術基準 用於定義系統、雲端、網路、端點、資料庫、容器、應用、AI平台或工具之最低安全設定要求。
技術例外 因業務、技術、相容性、供應商、法規或營運限制，暫時無法完全符合控制要求之情形。
補償控制 當原定控制無法完全實施或暫時失效時，用於降低風險至可接受水準之替代或額外控制。
控制證據 可證明控制設計、執行、監控、測試、審查、核准或改善之文件、系統紀錄、截圖、報表、日誌、工單或第三方證明。

CISO / 資訊安全負責人 建立技術控制策略、核准控制準則、監督高風險控制缺口、例外與有效性結果。 控制策略、例外核准、KPI/KRI報告。
ISMS管理代表 確保技術控制措施與ISMS條款、SoA、風險處理、稽核、管理審查與文件化資訊一致。 SoA更新、控制矩陣、管理審查輸入。
Technical Control Owner 統籌技術控制措施導入、操作、證據保存、有效性檢查與改善追蹤。 控制清單、有效性檢查表、改善追蹤。
IT Operations Owner 負責端點、伺服器、網路、資料庫、備份、容量、修補、組態與營運技術控制。 系統設定、監控報表、作業紀錄。
SOC / Monitoring Owner 負責日誌、監控、事件偵測、告警處理、威脅情資與事件證據支援。 SIEM規則、告警工單、監控報告。
Cloud Security Owner 負責雲端IAM、組態、網路、金鑰、日誌、CSPM/CNAPP、雲端弱點與雲端供應商控制。 CSPM報告、雲端設定證據。
Application Security / DevSecOps Owner 負責安全開發、SAST/DAST/SCA、API安全、CI/CD安全閘門、SBOM與外包開發控制。 安全測試報告、Pipeline紀錄、SBOM。
AI Governance / MLOps Owner 負責AI模型、Prompt、RAG、MLOps、AI監控、AI安全測試與AI技術控制。 AI清冊、模型版本紀錄、AI測試報告。
Data Owner / DPO 確認資料保護、PII、資料遮蔽、資料刪除、DLP、跨境與隱私相關技術控制要求。 資料核准、DPIA、隱私控制證據。
Internal Auditor 依稽核方案抽查技術控制措施之設計與執行有效性。 稽核工作底稿、缺失報告。
Supplier Management 確保外包、SaaS、雲端、AI服務與技術供應商控制要求、證據與SLA受控。 供應商審查、合約條款、服務報告。

5. 技術控制措施管理流程總覽

流程階段 作業內容 責任角色 輸出紀錄
1. 控制需求識別 依風險評鑑、SoA、Annex A、法規合約、資產清冊、雲端/AI清冊及事件經驗識別技術控制需求。 ISMS管理代表 / CISO / Control Owner 控制需求清單、風險對應矩陣。
2. 控制設計 定義控制目標、適用範圍、技術方案、Owner、操作頻率、證據、監控與測試方式。 Technical Control Owner / 技術Owner 控制設計紀錄、技術基準。
3. 控制導入 依變更管理、專案管理或營運作業導入控制，完成設定、測試、核准、上線與文件更新。 IT / Cloud / AppSec / MLOps Owner 部署紀錄、設定證據、變更單。
4. 控制操作 依SOP執行存取控制、弱點修補、日誌監控、備份、安全開發、AI安全等控制。 各控制Owner 作業紀錄、監控報表、工單。
5. 控制監測 追蹤KPI/KRI、告警、例外、逾期、控制失效、供應商證據與趨勢。 SOC / ISMS管理代表 KPI/KRI、告警、控制儀表板。
6. 有效性檢查 定期或事件觸發檢查設計有效性、執行有效性、證據完整性與改善需求。 Control Tester / Internal Auditor 技術控制措施有效性檢查表。
7. 缺失改善 對控制缺口啟動CAPA、風險處理、補償控制、例外接受或管理升級。 Control Owner / Risk Owner 改善計畫、CAPA、剩餘風險接受。
8. 管理審查與持續改善 彙整技術控制績效、風險、事件、稽核發現、資源需求與改善結果。 CISO / ISMS管理代表 管理審查輸入、改善決議。

A.8.27 安全系統架構與工程原則 安全架構原則、信任邊界、韌性與例外應審查。 架構審查、資料流圖。
A.8.28 安全編碼 安全編碼標準、Code Review、SAST/SCA與缺陷修復應受控。 PR紀錄、掃描報告。
A.8.29 開發與驗收之安全測試 安全測試計畫、測試覆蓋、獨立性與驗收放行應受控。 測試報告、缺陷追蹤。
A.8.30 外包開發 外包合約、交付物、安全測試、存取與智慧財產權應受控。 合約、交付驗收。
A.8.31 開發、測試與生產環境分隔 環境、資料、權限與部署管線應分隔。 環境架構、權限審查。
A.8.32 變更管理 變更分類、影響評估、測試、核准、PIR與緊急變更應受控。 變更單、PIR。
A.8.33 測試資訊 測試資料核准、遮蔽、存取與刪除應受控。 測試資料紀錄。

8. 技術控制措施設計要求

設計要素 最低要求 輸出證據
控制目標 每項技術控制應明確描述欲降低之風險、保護之資產、控制目的與對應Annex A控制。 控制設計紀錄、SoA對應。
適用範圍 定義適用資產、系統、資料、使用者、地點、雲端、AI或供應商範圍。 控制範圍清單。
控制Owner 指定負責設計、操作、監控、證據與改善之Owner及代理人。 RACI、責任任命。
控制方法 定義工具、系統設定、流程、基準、監控、審查或自動化機制。 技術設計、工具設定。
執行頻率 定義即時、每日、每週、每月、每季、每年、事件後或變更後之執行頻率。 作業排程、例行紀錄。
證據要求 定義可接受證據、保存位置、保存期限、完整性與存取權限。 證據索引、保存紀錄。
有效性測試 定義如何驗證控制設計及執行有效，例如抽樣、掃描、測試、查詢、重新執行或模擬攻擊。 測試計畫、有效性檢查表。
例外與補償控制 定義不符合時之例外核准、補償控制、期限、風險接受與重評要求。 例外申請、風險接受。

11. 技術控制有效性評估

新技術導入檢查 新雲端服務、新AI工具、新資料平台、新安全工具或新開發平台導入前。 安全設計、供應商風險、資料保護、監控與退場能力。 導入安全評估、風險處理計畫。

16. 技術控制缺失分級與處理要求

缺失等級 判定條件 處理時限 升級要求
重大 / Critical 控制失效導致或可能導致重大資料外洩、關鍵服務中斷、特權濫用、重大法規違反、AI高風險輸出或外部驗證重大不符合。 立即補救；24至72小時內提出處理方案。 立即通報CISO及管理階層，必要時啟動事件管理。
