1. 作業目的

本作業指導書規範開發、測試、預備、正式、災備、沙箱、教育訓練、AI/MLOps與供應商環境之區隔、存取、資料、網路、Secrets、CI/CD、監控、變更、例外與稽核要求，確保不同環境之資料、帳號、權限、設定、服務、金鑰及網路流量不被混用或相互污染，降低未授權存取、正式資料外洩、測試資料濫用、錯誤部署、供應鏈風險、AI資料洩漏、服務中斷與合規缺口。

本文件旨在建立一致且可驗證之環境隔離模型，支援安全開發生命週期、弱點管理、安全測試、變更管理、營運持續、隱私保護與AI治理，並確保任何需跨環境傳輸資料、同步設定、部署程式或使用正式資料之行為均經核准、記錄與風險控制。

2. 作業原則

  • 正式環境應與開發、測試、預備、沙箱、教育訓練及供應商環境進行邏輯或實體區隔，且不得共享高風險帳號、Secrets、資料庫、儲存、管理介面或未經授權之網路連線。
  • 不同環境應具備明確Owner、用途、資料分類、網路邊界、存取權限、部署管道、資料來源、備份與退場要求。
  • 正式資料不得任意複製至非正式環境；如因測試、除錯、模型訓練或驗證需求必須使用，應經Data Owner、DPO及CISO依資料分類核准並完成遮罩、去識別、最小化與保存期限設定。
  • 開發、測試與預備環境不得使用正式環境Secrets、API Key、雲端金鑰、資料庫密碼、憑證、模型供應商Token或客戶正式憑證。
  • 部署至正式環境應透過受控CI/CD、變更管理、職務分離、安全閘門與可回復機制，不得由開發人員以未受控方式直接修改正式環境。
  • 環境區隔不應僅依命名或文件聲明，而應透過雲端帳號/訂閱隔離、網路分段、IAM權限、Secrets隔離、資料遮罩、資源標籤、監控與稽核證據加以實施。

3. 名詞與定義

名詞 定義
環境區隔 透過管理、技術、網路、權限、資料、Secrets、流程及監控控制，使不同用途環境間風險不相互擴散之措施。
開發環境 供開發人員撰寫、整合與初步測試程式碼之環境，原則不得保存正式資料或正式Secrets。
測試環境 供QA、功能測試、整合測試、安全測試與使用者驗收準備之環境。
預備 / 準正式環境 接近正式設定並用於上線前驗證、效能測試或UAT之環境，仍不得直接使用未遮罩正式資料，除非核准。
正式環境 提供真實業務服務、客戶服務、正式資料處理或正式AI推論之環境。
災備環境 用於災難復原、故障切換、備援或營運持續之環境，應依正式環境同等級保護。
沙箱環境 用於技術驗證、概念驗證、供應商測試、AI實驗或臨時性探索之受限環境。
環境提升 將程式碼、設定、資料庫變更、模型版本、IaC或資源設定由低階環境推進至較高階環境之流程。
正式資料 正式環境中真實業務、客戶、PII、交易、機密、AI或營運資料。
資料遮罩 將敏感資料以不可逆或受控方式轉換，使其不再直接識別個人、客戶或敏感內容。
環境漂移 不同環境之設定、版本、權限、資料結構或控制措施與基準不一致，造成測試結果失真或安全風險。

4. 角色與責任

Environment Segregation Owner 維護環境區隔模型、環境清冊、區隔基準、跨環境例外與合規報告。 環境清冊、區隔檢查報告。
DevSecOps Owner 管理CI/CD環境提升、部署權限、安全閘門、Artifact與環境變數隔離。 Pipeline設定、Release紀錄。
Cloud Security Owner 管理雲端帳號、訂閱、IAM、網路、安全群組、KMS與CSPM之環境隔離。 雲端環境設計、CSPM報告。
IT Operations Owner 管理伺服器、資料庫、網路、備份、監控與正式維運環境之隔離。 組態紀錄、維運紀錄。
Network Security Owner 設計與維護跨環境網路分段、防火牆、VPN、ZTNA、API Gateway與管理通道限制。 網路規則、分段圖。
System / Application Owner 定義系統各環境用途、資料需求、部署流程、測試需求與權限要求。 系統環境矩陣。
Data Owner 核准資料跨環境使用、遮罩、去識別、保存期限、刪除與測試資料集。 資料使用核准與遮罩紀錄。
DPO / 隱私負責人 審查PII於非正式環境之使用、去識別、DPIA、跨境與資料主體權利影響。 隱私審查、DPIA。
AI Governance / MLOps Owner 管理AI模型、Prompt、RAG、訓練資料、模型版本、模型端點與AI測試環境隔離。 AI環境矩陣、模型版本紀錄。
QA / Test Owner 確保測試環境、測試資料、測試帳號及測試結果符合區隔與資料保護要求。 測試資料與帳號紀錄。
Supplier Management 確保供應商開發、測試或維運環境符合環境隔離、資料保護與退場要求。 合約條款、供應商評估。
Internal Auditor 抽查環境清冊、區隔證據、跨環境存取、正式資料使用與例外管理。 稽核底稿、稽核發現。

5. 環境類型與最低隔離要求

環境類型 用途 最低隔離要求 正式資料使用
開發環境 程式開發、單元測試、初步功能驗證。 獨立帳號/權限、獨立Secrets、不得連正式資料庫，不得開放正式管理權限。 禁止，除非不可逆去識別且經核准。
測試環境 功能測試、整合測試、安全測試、QA驗證。 與開發/正式分離，測試帳號與測試資料獨立，網路受限。 原則禁止，必要時遮罩並核准。
預備 / 準正式環境 上線前驗證、UAT、效能與部署演練。 接近正式設定但與正式網路、資料、Secrets隔離；部署需受控。 需核准、遮罩、最小化、期限與刪除。
正式環境 正式業務、客戶服務、正式資料處理。 最高等級控管，最小權限、PAM、MFA、變更管理、監控、備份。 可使用正式資料，需依資料分類保護。
災備環境 故障切換、復原與營運持續。 依正式環境同等級控制，與測試環境隔離，定期演練。 依正式資料保護要求。
沙箱 / POC環境 概念驗證、供應商測試、技術探索。 限制網路、帳號、資料、成本、期限與外部連線；到期清除。 禁止使用正式資料。
教育訓練環境 訓練、示範、演練與課程。 與正式資源完全隔離，資料合成或假名化，帳號短期。 禁止使用正式資料。
AI/MLOps實驗環境 模型實驗、Prompt測試、RAG測試、Notebook與資料分析。 資料集、模型、API Key、GPU、Notebook與RAG資料源隔離。 需AI治理與Data Owner核准。
供應商環境 外包開發、測試、維運或代管服務。 合約要求、資料限制、存取隔離、日誌、退場刪除與稽核權。 原則禁止，必要時須DPA與核准。

6. 環境區隔生命週期流程

階段 作業要求 責任角色 輸出證據
1. 環境需求提出 提出環境用途、系統、資料分類、使用者、期限、雲端/網路/資料需求與風險等級。 System Owner / Project Owner 環境申請紀錄。
2. 區隔設計 定義環境邊界、帳號/訂閱、網路、IAM、Secrets、資料、CI/CD、監控與備份。 Security Architecture / Cloud / DevSecOps 環境區隔設計。
3. 安全審查與核准 依資料、AI、供應商、對外暴露及正式資料使用情境審查。 CISO / Data Owner / DPO 核准紀錄。
4. 建置與基準套用 依安全組態基準、IaC、標籤、Policy as Code、Secrets Manager與監控建置。 IT / Cloud / DevSecOps 建置紀錄與基準檢查。
5. 資料與Secrets配置 建立獨立測試資料、環境專用Secrets、短期憑證與遮罩資料。 Data Owner / Secrets Owner 資料核准與Secrets紀錄。
6. 使用與監控 持續監控跨環境連線、權限、資料移動、成本、AI用量、部署與異常。 SOC / Environment Owner 監控報告。
7. 定期審查 審查環境必要性、Owner、資料、帳號、Secrets、網路規則、成本與合規狀態。 Environment Owner 環境審查紀錄。
8. 退場與清理 環境不再需要時刪除資料、撤銷權限、停用Secrets、銷毀資源並更新清冊。 System Owner / Cloud / IT 退場紀錄。

7. 網路與連線隔離要求

控制項目 最低要求 高風險加強要求
網路分段 不同環境應以VLAN、子網、VPC/VNet、Security Group、ACL、防火牆或微分段隔離。 正式與非正式環境不得同網段或無限制互通。
跨環境連線 所有跨環境連線需有申請、Owner、用途、來源、目的、埠、期限與日誌。 正式至非正式或非正式至正式連線需CISO審查。
管理介面 正式管理介面不得由開發/測試網段直接存取。 需PAM、跳板、ZTNA、MFA與Session Recording。
資料庫連線 非正式環境不得直接連接正式資料庫。 例外需Data Owner、DPO與CISO核准並採唯讀、遮罩或隔離機制。
API與服務呼叫 測試環境應呼叫測試API、Mock、Stub或沙箱服務，不得誤呼正式外部API。 需Egress控制、API Gateway與環境標籤。
供應商連線 供應商測試/維運通道應與正式網路分段並限制時間與用途。 高風險需Session Recording與單次授權。
AI外部服務 非正式AI測試應使用測試Key與測試資料，不得直連正式AI API Key或正式RAG資料源。 需Proxy/CASB/DLP與用量監控。
日誌監控 跨環境連線、拒絕流量、異常Egress與資料移動需記錄並可供調查。 高風險連線接入SIEM並建立告警。

8. 身份、權限與職務分離要求

控制項目 作業要求 證據
環境專用角色 開發、測試、預備、正式及災備應使用不同角色與權限集合。 IAM角色矩陣。
正式環境存取 正式環境存取需最小權限、MFA、PAM/JIT、核准與日誌。 PAM/IAM紀錄。
開發人員限制 開發人員原則不得直接修改正式環境資料、設定或程式；需透過Release流程。 CI/CD紀錄、權限審查。
測試帳號 測試帳號需具名或可追溯、限定環境、期限、角色與資料範圍。 測試帳號清冊。
服務帳號 不同環境服務帳號不得共用，且權限、Secrets、Token與憑證應分離。 服務帳號清冊。
Break-glass 緊急正式環境存取需Break-glass流程，使用後立即審查與輪替。 緊急存取紀錄。
供應商權限 供應商權限限定環境、期限、用途，禁止使用組織共享帳號。 供應商存取紀錄。
權限審查 正式與高風險非正式環境權限至少每季審查，其他環境至少每年。 權限審查紀錄。

9. 資料隔離、遮罩與測試資料要求

資料處理情境 控制要求 核准要求
使用合成資料 優先使用合成資料、範例資料或人工建立測試資料。 通常由System Owner核准。
使用遮罩正式資料 需資料最小化、不可逆遮罩或去識別、保留期限、刪除與存取限制。 Data Owner、DPO與CISO依風險核准。
使用未遮罩正式資料 原則禁止；僅於重大故障、法規測試或無替代方案時短期核准。 管理階層授權、DPO、CISO與Data Owner核准。
資料複製至雲端測試 需確認資料所在地、加密、權限、跨境、供應商條款與刪除。 Data Owner / DPO / Cloud Security核准。
AI模型訓練或微調 正式資料用於AI訓練需AI治理、授權、PII評估、資料不訓練條款與刪除計畫。 AI Governance、Data Owner、DPO核准。
RAG索引建立 非正式RAG不得索引正式機密資料，除非完成權限繼承與遮罩。 Data Owner與AI Governance核准。
測試資料保存 測試資料需設定保存期限、刪除責任與刪除證據。 System Owner / Data Owner確認。
資料回流正式 測試或非正式環境資料不得回流正式環境，除非經驗證與核准。 Change Owner與Data Owner核准。

10. Secrets、金鑰與憑證區隔要求

Secrets類型 區隔要求 禁止事項
資料庫密碼 不同環境使用不同帳號、密碼與權限。 禁止測試環境使用正式資料庫帳密。
API Key / Token 開發、測試、預備、正式需分環境Key，設定Scope、到期與用量限制。 禁止非正式環境使用正式API Key。
雲端Access Key 不同雲端帳號/訂閱/專案與環境需分離Key或Role。 禁止跨環境共用高權限Access Key。
TLS憑證 測試與正式憑證分離，正式私鑰不得出現在非正式環境。 禁止複製正式私鑰至開發或測試。
KMS金鑰 不同環境應使用不同KMS Key或Key Policy限制，正式Key權限嚴格控管。 禁止非正式環境解密正式資料。
CI/CD Secrets Pipeline變數需分環境保護，正式Secrets僅允許正式部署Job存取。 禁止在PR、Fork、測試Job曝光正式Secrets。
AI API Key AI測試、開發、正式推論需分Key，正式Key不得用於Notebook或沙箱。 禁止將AI Key輸入Prompt或提交Repo。
Webhook Secret 測試Webhook與正式Webhook Secret分離，並具簽章與Replay Protection。 禁止測試服務接收正式Webhook資料。

11. CI/CD、部署與環境提升要求

控制項目 作業要求 證據
環境流水線 程式碼、IaC、模型或設定應依開發、測試、預備、正式順序提升，避免人工跳環境部署。 Pipeline設定。
部署權限 正式部署權限應與開發權限分離，需核准、雙人審查或Release Gate。 部署權限矩陣。
Artifact一致性 正式環境部署之Artifact需來自受控Build，具版本、雜湊、SBOM或簽章。 Artifact紀錄。
環境變數 環境變數與設定需分環境管理，避免開發設定進入正式。 設定管理紀錄。
資料庫變更 資料庫Schema與Migration需經測試、備份、回復計畫與變更核准。 DB變更紀錄。
AI模型提升 模型、Prompt、RAG索引、特徵與模型端點提升需版本控管、測試、核准與回滾。 模型版本與部署紀錄。
安全閘門 正式部署前需通過SAST、SCA、Secrets、IaC、容器、DAST/API或AI安全測試。 Release Gate證據。
回滾機制 正式部署需具回滾、藍綠部署、金絲雀或備援策略。 回滾測試與Runbook。

VPC / VNet 不同環境使用不同VPC/VNet、子網、路由與安全群組，跨環境連線需核准。 網路圖、Security Group。

控制項目 作業要求 證據

訓練資料 開發/實驗使用資料需去識別、最小化、授權與保存期限。 資料核准紀錄。

項目 最低要求 範例 / 證據

16. 環境漂移、監控與定期審查

監控項目 監控內容 處置要求
環境漂移 設定、版本、IAM、網路、KMS、部署、Policy與安全基準差異。 建立修正工單或例外。
跨環境連線 非預期連線、過期規則、未授權API呼叫或資料庫連線。 立即調查與阻斷。
正式資料外流 正式資料複製至非正式環境、未遮罩資料、DLP命中。 啟動事件或違規處理。
Secrets混用 正式Secrets出現在非正式環境、Repo、Notebook或CI/CD測試Job。 立即撤銷輪替並通報事件。
權限異常 開發者或供應商持有不必要正式權限。 撤權與權限審查。
環境閒置 長期未使用沙箱、測試資源或臨時環境。 停用、刪除或重新核准。
AI用量異常 非正式AI環境使用正式Key、用量暴增、未知模型端點。 停用Key、調查來源。
成本/資源異常 沙箱或測試環境資源暴增、超出預算或不合規區域。 限制資源與通知Owner。

17. 正式資料使用於非正式環境之核准流程

步驟 作業要求 責任角色 輸出證據
1. 需求提出 說明使用正式資料之目的、範圍、必要性、替代方案與使用期限。 Project Owner / QA / Data Scientist 正式資料使用申請。
2. 資料分類與影響評估 確認是否含PII、客戶資料、高機密、合約限制、跨境或AI訓練用途。 Data Owner / DPO 資料影響評估。
3. 遮罩與最小化設計 定義欄位遮罩、去識別、抽樣、Tokenization、合成資料或資料削減方式。 Data Owner / Engineering 遮罩設計。
4. 安全控制審查 確認環境隔離、加密、權限、日誌、保存期限、刪除、DLP與監控。 CISO / Security Owner 安全審查。
5. 核准與執行 取得必要核准後執行資料移轉，記錄資料版本、位置、使用者與期限。 Data Owner / IT 核准與移轉紀錄。
6. 使用監控 監控資料存取、複製、匯出、AI輸入、供應商接觸與異常活動。 SOC / Data Owner 監控紀錄。
7. 刪除與驗證 期限屆滿或任務完成後刪除資料、備份與暫存，保存刪除證據。 System Owner / Data Owner 刪除證明。
