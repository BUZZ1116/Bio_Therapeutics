1. 作業目的與適用範圍

目的 適用範圍
提供受控文件庫的建立、命名、版本、權限、發布、封存、備份與日常維護作業方法。 適用於 管理系統、ISMS、PIMS、AIMS、BCMS、GHG 與 CO2 管理系統相關手冊、政策、程序、SOP、表單、清冊、矩陣、紀錄與外部來源文件。

2. 建議文件庫結構

資料夾 內容 控制重點
00_Manual_and_Policy 手冊 (MAN)、政策 (POL)、治理架構文件。 僅最高管理階層或授權人員核准發布。
04_Context_and_Process 組織全景、利益相關方、流程、風險與機會文件。 連結管理審查與流程Owner。
07_Support/075_Documented_Information ISMS-075程序、表單、清冊、矩陣與本SOP。 本組文件的主工作區。
08_Operation 管理系統、供應鏈、設計、產品服務提供、外包與生命週期文件。 依產品服務與流程分資料夾。
09_Performance 監督、量測、稽核、管理審查與報告。 高敏感資料應限制權限。
10_Improvement 不符合、CAPA、改善、經驗學習。 保留閉環證據。
External_Documents 外部標準、客戶文件、供應商文件、法規與資料庫索引。 注意授權與不得散布限制。
Archive_Obsolete 失效、作廢、封存版本。 唯讀、限制存取、明確標示不可使用。
GHG_Evidence 活動數據、係數、計算工作簿、查證報告與碳聲明證據。 依 Confidential / 機密 或 Highly Confidential / 高度機密 管制。

中繼資料 填寫規則 用途
文件編號 依文件編碼規則設定，例如 ISMS-075-SOP-001。 唯一識別與清冊索引。
文件名稱 應能清楚描述目的與範圍。 便於搜尋與稽核抽樣。
版本 / 狀態 Draft、Review、Approved、Effective、Obsolete、Archived。 避免草案、正式版與失效版混用。
Owner / Reviewer / Approver 填寫角色或姓名。 確認內容責任與核准責任。
生效日 / 下次審查日 依核准與審查週期設定。 支援定期審查與到期提醒。
文件分級 Public / 公開、Internal / 內部、Confidential / 機密、Highly Confidential / 高度機密。 連結存取控制與外部分享。
適用管理系統與條款 例如 管理系統 適用管理系統標準 7.5、GHG ISO 14064。 支援符合性矩陣與稽核追溯。
關聯文件與紀錄 連結表單、清冊、外部文件、紀錄保存期限。 避免孤立文件與證據斷鏈。
失效版本位置 標示舊版封存路徑。 支援版本追溯與錯版調查。

4. 受控文件庫作業流程

步驟 作業內容 責任 輸出 / 控制點
1. 建立草稿 依文件類型建立草稿並填寫首頁、版本、Owner、適用系統與條款。 文件Owner 草稿不得放入正式發布區。
2. 提出申請 使用 ISMS-075-FRM-001 提出新增、修訂、作廢、合併或緊急變更。 申請人 / 文件Owner 申請表與附件完整。
3. 審查 由Owner、管理系統代表與相關專業Owner審查內容、風險、分級、外部要求與保存期限。 Reviewer 審查意見與補正紀錄。
4. 核准 依文件類型與分級完成核准。 Approver 核准紀錄與生效日。
5. 發布 將正式版移至受控發布區，設定唯讀或受控權限，更新文件總清冊。 文件管制負責人 正式版、清冊更新、發布通知。
6. 舊版處置 舊版移至Archive_Obsolete並標示不可使用，必要時回收外部副本。 文件管制負責人 舊版封存與回收紀錄。
7. 通知與訓練 通知受影響人員，必要時完成訓練或簽收。 文件Owner 公告、簽收、訓練紀錄。
8. 定期審查 依審查週期或事件觸發確認文件仍適用。 文件Owner 審查紀錄或修訂申請。

5. 命名與版本規則

項目 規則 範例
檔名 文件編號_文件名稱_版本.html 或核准格式。 ISMS-075-SOP-001_受控文件庫作業指導書__V1_0.html
草稿版本 Draft Vx.x，可在審查過程中修訂。 Draft V1.0、Draft V1.1
正式版本 核准後改為 Effective 或正式版號。 V1.0 Effective
失效版本 移至封存區並加上 Obsolete 或 Archived 標示。 ISMS-075-SOP-001_V0_9_Obsolete
禁止事項 不得以 final、new、latest、copy 等字樣作為正式版本判斷依據。 Final_Final_New 不是受控版本。

6. 權限設定原則

資料夾 / 文件類型 建議權限 注意事項
正式發布區 一般使用者唯讀；
Owner與文件管制負責人可維護。		 避免使用者自行覆蓋正式版。
草稿區 文件Owner與Reviewer可編輯；
其他人依需要讀取。		 草稿不得作為正式作業依據。
封存區 文件管制負責人可維護；
一般使用者不得讀取或僅限查閱。		 應標示不可使用。
GHG證據區 GHG資料Owner、Reviewer、查證支援人員依任務授權。 避免公式、係數或原始資料被非授權修改。
高度機密區 最小必要授權並定期審查。 可包含個資、資安事件、AI風險、查證報告。

7. 備份、日誌與緊急存取

控制項 作業要求 最低紀錄
備份 受控文件庫應納入組織備份機制，並定期確認可還原。 備份設定、還原測試紀錄。
存取日誌 Confidential / 機密 與 Highly Confidential / 高度機密文件應保留必要存取或下載紀錄。 系統日誌或審查紀錄。
離線副本 BCMS或營運中斷需要時，可建立受控離線副本。 副本清冊、持有人、版本、回收紀錄。
緊急變更 重大事件需立即發布時，可先臨時發布，但須補正式申請與核准。 緊急發布紀錄、補審紀錄。
災難復原 文件庫不可用時，應有替代存取方式與恢復優先順序。 BCP或復原紀錄。

8. 日常作業檢查表

頻率 檢查事項 責任 異常處置
每月 檢查草稿、審查中、待發布與待封存文件是否逾期。 文件管制負責人 提醒Owner；
必要時升級至管理系統代表。
每季 抽樣確認文件總清冊、文件庫版本、權限與分級一致。 文件管制負責人 / 管理系統代表 更正清冊或權限；
重大差異列CAPA。
每半年 檢查 Confidential / 機密 與 Highly Confidential / 高度機密 文件權限。 資訊安全Owner / 文件管制負責人 移除不必要權限並保留紀錄。
每年 完成ISMS-075文件整體審查與有效性評估。 管理系統代表 納入管理審查輸入。
事件觸發 標準、法規、客戶要求、系統工具、組織或重大風險變更。 文件Owner 啟動文件制修訂申請。

9. 監督與有效性評估

指標 目標 / 觸發 說明
正式版錯用件數 發生即啟動不符合與矯正措施。 包含草稿被使用、舊版未回收或錯版發布。
文件發布準時率 低於 95% 應分析瓶頸。 確認審查、核准與發布流程可執行。
權限異常件數 重大異常即啟動事件管理。 支援ISMS/PIMS與敏感證據保護。
文件庫備份還原成功率 應依組織BCMS目標執行。 確保營運中斷時仍能取得關鍵文件。
