1. 作業目的

本作業指導書規範組織於AI模型訓練、微調、推論、RAG、MLOps、雲端與資料中心運算過程中，如何管理能源效率、資源使用效率、碳資料安全、碳排放計算資料完整性、供應商碳資料可信度、AI模型能源與碳績效監控、揭露資料保護及事件處理，確保AI系統之資訊安全與永續治理能被一致、可追溯、可稽核地執行。

本文件將AI能源效率與碳資料安全納入ISMS技術控制措施，要求AI模型與相關工作負載在設計、訓練、部署、使用、監控與退場階段，同時考量資訊安全、隱私、AI治理、資料治理、雲端安全、供應商管理、GHG盤查、ESG揭露及營運持續要求。

2. 作業原則

  • AI模型能源效率與碳資料安全應採風險導向與生命週期管理，不得僅以成本或效能作為唯一優化目標。
  • AI訓練、微調、推論與RAG工作負載應優先選擇符合安全、效能、可用性、資料所在地、合約與碳效率要求之運算環境。
  • 能源用量、碳排放係數、PUE/CUE/WUE、工作負載用量、模型版本、訓練資料與推論量等資料，應被視為受控資料並具備完整性、可追溯性及存取控制。
  • 碳資料不得未經核准任意修改、重算、刪除、外傳或對外揭露；任何估算、換算、假設、係數版本或供應商資料來源均應留存證據。
  • AI能源與碳績效資訊若涉及客戶、供應商、機房、雲端架構、模型效能、成本、營運量或安全架構，應依資訊分類與合約要求保護。
  • 涉及外部AI服務、雲端GPU、第三方模型、代管MLOps或外包資料處理者，應確認供應商對能源、碳、資料安全、日誌、刪除、跨境與事件通報之責任。
  • AI能源效率改善不得降低必要安全控制，例如不得為降低成本而關閉日誌、監控、加密、備份、弱點掃描、存取控制或事件偵測。

3. 名詞與定義

名詞 定義
AI模型能源效率 AI模型於訓練、微調或推論過程中，達成既定品質、準確性、安全性與業務目的時，對運算、儲存、網路與冷卻等能源資源之使用效率。
碳資料 用於計算、驗證、追蹤、分析或揭露溫室氣體排放、能源使用、排放係數、工作負載碳強度、雲端碳足跡、AI模型碳成本及ESG/GHG績效之資料。
工作負載碳強度 特定AI工作負載、模型訓練任務、推論服務或資料處理任務在指定期間內所對應之碳排放量或估算指標。
PUE Power Usage Effectiveness，資料中心總能源使用量與IT設備能源使用量之比值，可作為資料中心能源效率指標。
CUE Carbon Usage Effectiveness，資料中心碳排放量與IT設備能源使用量之比值，用於描述碳效率。
WUE Water Usage Effectiveness，資料中心用水量與IT設備能源使用量之比值，用於描述水資源效率。
GreenOps 將雲端、資料中心、應用架構與工作負載管理納入能源效率與碳效率最佳化之營運方法。
碳排放係數 用於將活動數據轉換為溫室氣體排放量之係數，包括電力係數、雲端供應商係數、地區係數、能源種類係數或其他適用係數。
模型版本碳紀錄 特定模型版本於訓練、微調、部署、推論或批次處理中產生之能源用量、資源用量、碳估算、係數版本與假設紀錄。
碳資料完整性 碳資料在蒐集、轉換、計算、儲存、傳輸、審查、揭露與封存過程中未被未授權修改、刪除、替換或扭曲之特性。

CISO / 資訊安全負責人 確保AI能源與碳資料相關資訊安全控制、存取控制、日誌監控、事件通報與供應商安全要求有效。 控制要求、例外核准、事件處理紀錄。
AI Governance Owner 確保AI模型能源效率與碳資料管理納入AI治理、AI風險評估、模型版本與使用情境審查。 AI治理紀錄、AI風險評估、模型清冊。
MLOps Owner 記錄模型訓練、微調、部署、推論、資源用量、版本、回滾與能源/碳相關監控資料。 模型版本紀錄、MLOps日誌、資源用量報表。
Cloud / Infrastructure Owner 提供雲端、資料中心、GPU/TPU/CPU、儲存、網路、PUE/CUE/WUE、區域與資源用量資料。 雲端用量報表、基礎設施效率資料。
FinOps / GreenOps Owner 分析AI工作負載成本、能源效率、碳效率、資源浪費、排程、區域選擇與最佳化建議。 FinOps/GreenOps報告、改善紀錄。
GHG Data Governance Owner 維護碳資料欄位、計算方法、係數版本、資料品質、保存、審查與揭露證據。 碳資料清冊、計算底稿、係數紀錄。
Data Owner 核准AI能源與碳計算所需資料來源、分類、使用目的、保存期限與共享範圍。 資料核准、資料分類、存取審查。
SOC / Monitoring Owner 監控碳資料異常存取、能源/碳資料竄改、AI用量異常、API濫用與資料外洩告警。 SIEM告警、事件工單、監控報告。
DPO / 法務 / 法遵 審查碳資料中可能涉及PII、客戶敏感資訊、合約限制、跨境、對外揭露與聲明責任。 法遵審查、DPIA、對外揭露核准。
供應商管理 向雲端、AI、資料中心與外包供應商取得能源、碳、資料安全、SLA、事件與稽核證據。 供應商審查、合約條款、證據收集。

5. 作業流程總覽

流程階段 作業內容 責任角色 輸出紀錄
1. AI能源與碳範圍識別 識別AI模型、Prompt應用、訓練任務、推論服務、資料管線、雲端區域、供應商與碳資料來源。 AI Governance Owner / MLOps Owner AI能源與碳範圍清單。
2. 資料分類與安全需求確認 確認能源用量、碳資料、模型效能、雲端成本、供應商碳資料及揭露資料之分類與保護要求。 GHG Data Owner / CISO / Data Owner 資料分類與安全需求表。
3. 能源效率與碳風險評估 評估模型架構、訓練頻率、推論量、資料中心或雲端區域、供應商、碳係數與資訊安全風險。 AI Governance / GreenOps / Risk Owner AI能源與碳風險評估。
4. 控制設計與導入 導入資源配額、排程、用量監控、模型版本碳紀錄、存取控制、日誌、DLP、完整性保護與供應商要求。 MLOps / Cloud / SOC / GHG Owner 控制設定、監控規則、程序紀錄。
5. 監控與資料收集 收集模型工作負載、能源、資源用量、碳估算、係數版本、供應商資料與異常告警。 MLOps / GreenOps / SOC 能源與碳監控報告。
6. 審查與最佳化 定期檢討模型能源效率、碳強度、資源浪費、效能、安全性、資料品質與改善機會。 AI Governance / GreenOps / CISO 改善計畫、管理審查輸入。
7. 揭露與證據保存 對內/對外揭露前完成法務、ESG、CISO與資料Owner核准，保存底稿與證據。 GHG Owner / 法務 / CISO 揭露核准、底稿封存。
8. 事件與異常處理 碳資料竄改、異常用量、未授權外傳、供應商資料不一致或AI能源異常應通報並處理。 SOC / Incident Manager 事件通報、調查與檢討報告。

7. AI模型能源效率設計要求

設計領域 作業要求 證據
模型選型 在滿足安全、準確性、可用性與合規要求前提下，評估模型大小、推論成本、能耗、延遲、可壓縮性與部署模式。 模型選型評估、AI風險評估。
任務適配 不得以超大型模型處理可由小型模型、規則、檢索、批次或傳統分析完成之低複雜度任務，除非具業務與風險理由。 架構審查、效能比較。
訓練策略 訓練與微調應評估資料規模、訓練輪次、早停、參數高效微調、重用既有模型與避免重複訓練。 訓練計畫、實驗紀錄。
推論最佳化 正式推論應評估快取、批次、量化、蒸餾、模型壓縮、請求合併、Token限制與資源自動伸縮。 推論最佳化報告。
RAG效率 RAG應控制索引大小、檢索筆數、重排序、上下文長度、快取與資料更新頻率，避免不必要運算。 RAG設計、查詢效能報表。
排程與區域 可批次或非即時任務應評估低碳時段、低碳區域、成本效率、資料所在地與合規限制。 排程策略、區域選擇評估。
安全不可降級 能源效率改善不得犧牲日誌、監控、加密、存取控制、DLP、備份、弱點掃描或事件偵測。 變更評估、控制確認。

監控項目 最低監控內容 監控頻率 證據

計算方法管制 排放係數、計算公式、活動數據、邊界、假設與估算方法應受控，變更需核准。 GHG Owner / ESG Owner 計算方法文件、變更紀錄。
傳輸安全 碳底稿、供應商資料、查證資料與揭露草稿傳輸應使用核准安全通道。 使用者 / IT 傳輸紀錄、加密證據。
DLP與外洩防護 碳資料若屬機密或高機密，應納入DLP/CASB/郵件外寄或雲端分享監控。 SOC / DLP Owner DLP政策、告警紀錄。
備份與復原 重要碳資料、計算底稿與揭露核准證據應備份並可復原。 IT / GHG Owner 備份紀錄、復原測試。
刪除與保留 碳資料保存期限應依法規、查證、合約、ESG揭露與紀錄保存要求設定。 GHG Owner / 法務 保存期限清冊、刪除紀錄。
