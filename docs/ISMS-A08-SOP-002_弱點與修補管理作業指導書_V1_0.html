1. 作業目的

本作業指導書規範組織對資訊資產、雲端服務、應用系統、網路設備、端點設備、資料庫、第三方元件、容器映像、開源套件、AI模型服務與MLOps平台進行弱點識別、風險分析、修補排程、變更控管、驗證關閉、例外接受、持續監測及管理審查之方法。

本文件目的在於確保弱點管理活動可被計畫、執行、追蹤、量測與稽核，並能支援資訊安全風險處理、事件預防、合規要求、供應鏈管理、營運持續、隱私保護與AI治理要求。

2. 作業原則

  • 所有弱點均應以資產重要性、暴露程度、威脅情資、CVSS、EPSS、是否已遭利用、資料敏感度、業務衝擊及補救可行性進行優先排序。
  • 高風險、已遭利用、網際網路暴露、涉及PII/客戶資料/高機密資料或關鍵服務之弱點，應以加速流程處理。
  • 修補活動不得僅以安裝更新為完成條件，必須包含影響評估、備份或回復準備、變更核准、部署紀錄、驗證測試及證據保存。
  • 無法於期限內完成修補者，必須提出補償控制、例外申請、剩餘風險接受及重新審查期限。
  • 弱點管理應與資產清冊、變更管理、事件管理、供應商管理、雲端安全、DevSecOps、AI治理、風險登錄與管理審查連動。

3. 名詞與定義

名詞 定義
弱點（Vulnerability） 資訊資產、系統、流程、組態、軟體、硬體、模型、資料處理或控制措施中可被威脅利用而造成資訊安全事件、資料外洩、服務中斷、未授權存取或合規失效之缺陷。
修補（Patch） 針對作業系統、應用程式、韌體、套件、容器映像、雲端元件、AI平台或安全工具套用安全更新、設定調整、版本升級或補救措施。
補償控制 當弱點暫時無法修補時，採取額外安全控制降低被利用可能性或衝擊，例如網路隔離、WAF規則、EDR規則、關閉服務、存取限制、監控告警或虛擬修補。
CVSS Common Vulnerability Scoring System，用於衡量弱點技術嚴重度之通用評分方法。
EPSS Exploit Prediction Scoring System，用於估計弱點於一定期間內被利用可能性之參考指標。
KEV Known Exploited Vulnerabilities，已知遭利用弱點清單，可作為加速修補與緊急處理之依據。
SBOM Software Bill of Materials，軟體組成清單，用於識別應用程式、套件、函式庫與第三方元件之版本與弱點曝險。
弱點Owner 對弱點分析、修補規劃、修補執行、例外申請、驗證關閉及證據保存負責之角色。

5. 弱點管理流程總覽

流程階段 作業內容 責任角色 輸出紀錄
1. 資產範圍確認 從資產清冊、雲端服務清冊、AI模型與Prompt資產清冊、供應商清冊、CMDB與系統架構圖確認掃描與修補範圍。 資產Owner / Vulnerability Management Owner 弱點管理範圍清單。
2. 弱點識別 透過掃描工具、威脅情資、供應商公告、滲透測試、程式碼掃描、雲端組態掃描、事件調查與稽核發現識別弱點。 SOC / AppSec / IT / Cloud Security 弱點掃描報告、發現清單。
3. 分析與分級 依CVSS、EPSS、KEV、暴露面、資產重要性、資料敏感度、可被利用性、補償控制與業務衝擊進行分級。 Vulnerability Management Owner / System Owner 弱點分級與處理優先順序。
4. 處理規劃 決定修補、升級、設定調整、停用、隔離、補償控制、接受、轉移或風險處理計畫。 弱點Owner / CISO 修補計畫、風險處理計畫。
5. 變更與部署 依變更管理流程完成影響評估、測試、備份、核准、部署與回復準備。 IT / DevSecOps / Change Owner 變更單、部署紀錄、回復計畫。
6. 驗證與關閉 以重新掃描、版本確認、設定檢查、滲透測試複測、日誌確認或控制證據確認弱點已處理。 Vulnerability Management Owner / SOC 複測報告、關閉紀錄。
7. 監測與改善 追蹤逾期弱點、重複弱點、例外、趨勢、KPI/KRI、事件關聯與改善行動。 ISMS管理代表 / CISO KPI/KRI報告、CAPA、管理審查輸入。

7. 弱點嚴重度與優先排序準則

等級 判定條件 處理時限 升級要求
緊急（Critical Emergency） 已遭利用或列入KEV；網際網路暴露；可遠端未授權執行；影響關鍵服務、PII、客戶資料、高機密資料、特權帳號、雲端控制平面或AI生產模型服務。 24至72小時內完成修補或補償控制；必要時立即隔離。 即時通報CISO、IT主管、System Owner；必要時啟動事件管理或緊急變更。
高（High） CVSS高分、EPSS高、可被利用性高、公開PoC、影響重要資產或可造成橫向移動、權限提升、資料外洩或服務中斷。 7至14日內完成處理；有外部暴露者優先。 每週追蹤至關閉，逾期需提出例外與補償控制。
中（Medium） 需特定條件利用、影響範圍有限、已有部分控制，但仍可能造成未授權存取、資訊揭露或可用性下降。 30至60日內處理或納入版本修補計畫。 納入月度追蹤與風險登錄。
低（Low） 利用難度高、衝擊有限、無敏感資料或已具足夠補償控制。 90至180日內依例行維護處理。 納入基準改善與版本更新計畫。
資訊性（Informational） 不構成立即弱點，但顯示設定改善、版本老舊、最佳實務差距或後續檢查需求。 依改善計畫或下次審查處理。 必要時轉為設定基準改善項目。

12. 例外管理與剩餘風險接受

例外情境 最低要求 核准層級 重新審查
無可用修補程式 記錄原廠公告、影響評估、替代版本、補償控制與監控措施。 CISO / System Owner 至少每30日或原廠更新時。
修補導致業務中斷 提出測試結果、業務衝擊、維護窗口計畫、暫行控制與預計完成日。 IT主管 / Business Owner / CISO 依風險等級每7至30日。
舊版或無法升級系統 隔離網段、限制存取、強化監控、禁止外部暴露、建立淘汰計畫。 最高管理階層授權代表 / CISO 至少每季。
供應商代管限制 取得供應商風險說明、修補計畫、SLA承諾、補償控制與客戶影響評估。 供應商管理 / CISO / 法務 依合約與風險等級追蹤。
AI模型或平台相依性限制 評估模型性能、資料管線、套件相容、推論服務可用性與替代控制。 AI Governance Owner / CISO 模型版本變更或至少每30日。

領域 控制要求 證據

模型供應商公告 追蹤外部AI服務、API、模型版本、資料保留、訓練使用、區域處理與安全事件公告。 供應商公告、影響評估。
模型版本弱點追蹤 模型版本、訓練資料、微調資料、Prompt模板與安全控制變更應與弱點修補狀態連動。 AI模型版本與訓練資料追蹤清冊。
AI輸出與決策風險 若弱點可能造成不正確輸出、偏差、未授權資料揭露或業務決策錯誤，應納入AI治理與事件管理。 AI風險評估、事件通報。

16. 弱點管理KPI/KRI

指標 定義 目標 / 門檻 用途
Critical弱點逾期率 逾期未關閉Critical弱點數 / Critical弱點總數。 目標0%；任何逾期需升級。 管理審查、風險升級。
High弱點逾期率 逾期未關閉High弱點數 / High弱點總數。 依組織目標設定，例如低於5%。 修補效率監測。
平均修補時間（MTTR） 自弱點確認至驗證關閉之平均天數。 依資產類別與風險等級設定。 流程成熟度分析。
重複弱點率 已修復後再次出現之弱點比例。 持續下降。 根因分析與基準改善。
掃描覆蓋率 已納入弱點掃描之資產數 / 應掃描資產數。 關鍵資產100%。 範圍完整性確認。
例外弱點數 已核准但尚未修補之例外弱點數與風險等級。 高風險例外需逐案審查。 剩餘風險管理。
外部暴露高風險弱點數 可由網際網路存取資產上未關閉Critical/High弱點數。 目標0或立即處理。 攻擊面風險監控。
