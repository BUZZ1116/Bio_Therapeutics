1. 聲明目的

本範圍聲明書用於正式定義組織資訊安全管理系統（Information Security Management System, ISMS）之邊界與適用範圍，作為內部治理、風險評鑑、控制措施適用性聲明書（SoA）、稽核方案、管理審查、驗證申請與外部驗證之依據。

本聲明亦用於說明ISMS與PIMS、AI治理、供應鏈安全、雲端服務、資料中心、GHG/CO2資料治理及氣候變遷相關資訊安全議題之整合關係，確保範圍界定能反映組織實際營運、資訊資產、資料處理、外部依賴、風險與合規要求。

12. 外部供應商、外包與第四方範圍 確認雲端、AI平台、資料中心、資安服務、PII委外、ESG/GHG平台與查證機構之責任邊界與控制要求。 外部供應商與第四方範圍。

15. 範圍與風險評鑑 / SoA連動 確認範圍已轉入資訊安全風險評鑑、風險處理、風險登錄、SoA與控制措施對應矩陣。 連動檢查表。
16. 驗證範圍聲明與對外揭露版本 管理內部完整版、驗證機構版、客戶合約版與公開聲明版之揭露內容、限制與核准。 對外揭露版本控制。
17. 範圍聲明審查與核准 取得ISMS、PIMS、AI、GHG、法務、供應商管理、最高管理階層對範圍聲明之審查與核准。 審查與核准紀錄。
19. 紀錄保存 定義範圍聲明書、範圍界定表、補充表、驗證版本、變更紀錄與管理審查決議之保存與保護要求。 紀錄保存要求。

2. 範圍聲明原則

  • ISMS範圍應以組織全景、關注方需求、法規合約要求、資訊資產、資訊安全風險與營運流程為基礎。
  • 範圍應明確說明納入與排除之組織單位、場所、流程、系統、服務、資訊資產、雲端、AI服務、PII處理活動與供應鏈關係。
  • 若組織擔任AI系統與服務之提供商、供應商、整合商或使用者，應明確說明AI活動是否納入ISMS範圍。
  • 若組織處理PII，或作為PII controller / processor，應說明PIMS與ISMS範圍之關係。
  • 若氣候變遷、GHG/CO2資料、碳盤查、碳足跡、碳中和聲明或查證證據涉及資訊安全或隱私風險，應納入範圍判定與風險評鑑。
  • 範圍排除不得影響組織達成資訊安全目標、履行法規合約義務或管理資訊安全風險之能力。
  • 本聲明應至少每年審查一次，並於重大變更、重大事件、驗證要求或管理審查決議後更新。
